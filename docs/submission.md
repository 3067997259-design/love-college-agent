## 1. 核心需求清单（草稿）

评分原文是“核心预设需求全部落地，无半成品；次要需求未完成不扣分，附加功能加分”。所以核心清单只列一定能做完的那条闭环。写多了，没做完就扣分。

32 h 时按实际进度定稿。定稿后清单里的每一项都必须能现场演示，做不完的项移到“次要”或“愿景”，绝不留在核心里。

**核心需求**（来自技术方案 §9 的第零、一圈）：

1. **计划与番茄钟**：用户说出计划，她排成番茄，确认后开始。专注时安静，休息时交付。
2. **校园邮件到日程**：只读指定文件夹；候选事项附邮件原文；确认后生成 .ics 和 Markdown。
3. **资料处理**：读取邮件附件（带文字层的 PDF），产出整理文件。
4. **有界执行与证据**：步数上限、可取消、重复调用拦截；完成以工具结果为准；全过程写入日志，调试面板能当场回放。
5. **记忆**：跨会话记得共同经历。
6. **备份与恢复**：导出私人存档，校验后恢复；恢复后她能说出之前发生的事。
7. **MCP 客户端**：接入外部工具。
8. **书本主界面与迷你陪伴窗**。
9. **设置与部署**：用户在设置页用自己的密钥完成部署。新手流程的动画在第二圈（技术方案 §9，体验设计 §7）。

**次要需求**（做完加分，没做完不扣分）：礼物（经 MCP 调用 Rodin，绑定记忆）、日记、她自己的当日安排与外出、角色包导入与缺素材回退、心流与编码、隐私模型、新手流程的动画、语音、展位上经 MCP 和她一起玩 Minecraft。

**愿景，不在本次范围**：从一张图生成角色与差分、由她自己编写插件、双人网球、好感度等关系数值、3D 角色、多所学校的实际接入。

界面不留死按钮：砍掉的功能连同入口一起拿掉，比如语音砍了，设置页的语音槽位也一起删，不放“敬请期待”。

## 4. 部署说明

助手起草，队友在一台干净的机器上照着装一遍，装通才算完成（38–44 h）。

1. 系统要求：Windows 版本、磁盘空间、网络。
2. 安装：安装包下载与安装步骤。
3. 首次启动，和新手流程的必填步骤一一对应（体验设计 §7.1）：
   1. 你的名字。
   2. 填模型：地址、密钥、模型名；体检通过才能下一步。列出实测过的供应商。
   3. 她的名字和基础身份：默认桃子，或导入角色包。
   4. 已有存档的，在第一步选“我已经有一本书了”，导入私人存档。
4. 可选配置（新手引导里点对应的家具，或在设置页里改）：
   1. 邮箱（信箱）：163 开启 IMAP、取得授权码、设“桃子”文件夹的收信规则。
   2. 编码环境（电脑）：范围、Shell、沙箱、审批模式。
   3. MCP server 的粘贴格式与示例（书架）、番茄钟时长（钟）、每日预算。
5. 常见问题：按应用里的提示逐条写，每条写清它对应的报错类别和处理方法（技术方案 §3.9），比如配置错误、上游繁忙、网络、余额不足、邮箱登录失效。
