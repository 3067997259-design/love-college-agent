# 体验设计：界面、形象与语音

整理日期：2026-10-11，来自当日的技术讨论。状态：用户确定了书本式主界面和迷你陪伴窗；其余内容是用户同意按建议记录的方向，文中数值都是默认值，赛中按实际效果调。工程部分见 [技术方案](tech-design.md)，画风、角色外观与借鉴分界见 [美术规格](art-spec.md)。

## 1. 两条原则

- **画面是她的状态的投影。** 她在做什么、处于哪个阶段、此刻几点，都直接决定画面，而不是一组随机播放的动画。这样桃子看起来就不只是“一堆画”。
- **应用就是片子里那本书。** 左页是她的房间，右页是用户的页面。她交给用户的东西，从左页越过中缝来到右页，对应视频第 07 镜的日程纸。

界面分两种做法：

- 主界面（书）定制、手绘风，界面风格见 [美术规格](art-spec.md) §6。
- 设置页朴素实用，用 Tailwind CSS + shadcn/ui，不追求风格。设置页的信息架构参考 AIRI 的设置页分组（供应商、模型、角色卡、模块、数据）。AIRI 是 Vue，本项目用 React 重新实现，不搬组件和样式，提交时注明。

## 2. 主界面：一本打开的书

### 左页：她的房间

- 桃子本人，姿势、表情和光线随状态变化（§3）。
- 她最新说的一句话，以对话框显示，和语音同步。
- 桌上的钟就是番茄钟，显示剩余时间。不做全屏大倒计时。
- 桌上挂一块门牌，切换情境：工作中、安静、休息。“暂停所有后台活动”另设一个开关，叫“熄灯”。README 要求“安静”和“全部暂停”是两种不同状态，门牌和熄灯正好分开表达。番茄钟的阶段会自动翻转门牌（[技术方案](tech-design.md) §3.5）。

### 右页：用户的页面（对话）

- **顶部**：今天的计划和番茄格。
- **对话流**：
  - 她的话正常显示。
  - 工具活动显示成手写体小字，比如“我去邮箱里看看～（3 封新邮件）”。这些文字由代码按模板生成，不额外调用模型。
  - 她执行任务时，`update_plan` 的步骤显示在任务卡里，逐项打勾。
- **候选卡片**：截止时间、计划完成时间、引用的邮件原文，以及“确认”“忽略”两个按钮。“证据 → 候选 → 确认”要让评委亲眼看到，所以来源原文必须在卡片上。
- **交付卡片**：日程文件、整理好的资料，从左页越过中缝滑过来，点开就是真实文件。
- **输入框**在最底下。她干活时按“发送”，消息会排队，在下一步并入；另有一个“停止”按钮。

### 书签

书页边缘做成书签：对话、日程、礼物、日记、设置。

- **礼物架**：每件礼物用 `<model-viewer>` 显示，点开能看到它来自哪段经历。
- **日记**：她写的日记，带主观标记。
- **数据**：备份和恢复。私人存档在界面上就是那支羽毛笔：导出时出现，恢复时颜色从笔尖晕开，和视频第 18 镜一致。

## 3. 状态与画面

| 状态 | 画面 |
| --- | --- |
| 在做用户交给她的活 | 侧面，坐在电脑前 |
| 在做自己的事（安静陪伴） | 低头写字 |
| 休息、交流、向用户提问 | 转过来面向你 |
| 应用窗口获得焦点 | 她抬头看你一眼 |
| 姿势切换、存档恢复 | 线稿 → 上色的过渡，复用提取出的线稿 |
| 每条回复 | 带一个情绪标签，切换到对应表情（4 种，具体随角色设定图定） |
| 说话 | 嘴型按语音音量开合 |
| 一直在 | 每 2–6 秒随机眨一次眼，每次约 0.15 秒；呼吸周期约 3.5 秒，缩放不超过 1% |
| 时段 | 早晨、白天、傍晚、夜晚四档光线叠加层；窗外天色跟着变；夜里台灯亮 |
| 环境 | 窗外、茶杯热气等小动态，按时段和活动出现 |

姿势对应视频镜头，素材与片子共用：

- 写字和用电脑：第 03 镜。
- 面向你：第 04 镜。因此第 04 镜提到第一档制作（[赛前统筹](team-plan.md) §3）。
- 推出交付物：第 07 镜。

## 4. 素材与差分

- **底图**：每个姿势一张完整立绘，从开赛后最先冻结的角色设定图出发，和视频共用。
- **面部差分**：用 NovelAI 只重绘脸部区域，贴在底图上。
  - 面向你的姿势：4 种表情，每种都有睁眼、闭眼和张嘴三张，约 12 张贴片。
  - 侧面的两个姿势：只做闭眼贴片，用于眨眼。
- **命名约定**：姿势、表情和变体写进文件名，角色包导入时按名字自动识别（§7）。

## 5. 语音

- 云端流式合成。候选是 MiniMax、火山引擎豆包和 Azure，均未验证，赛前挑一家试。
- 用现成或设计出的音色，不克隆真人声优。
- 文字先出，语音随后跟上。语音失败时显示“语音失败，已改为纯文字”，不影响对话。
- 有静音开关。
- 赛中约 2–3 小时。进度落后时，语音是第一个砍的。

## 6. 迷你陪伴窗

用户 2026-10-11 确定要做。

- 专注段开始时，书合上，缩成桌面角落的一个置顶小窗。透明背景，只有她坐在桌前继续做事。用户用别的软件时她也在场，这才是桌面陪伴。
- 透明区域要能点穿：默认用 `setIgnoreMouseEvents(true, { forward: true })`，鼠标移到她身上时再接收点击。
- 有些显卡驱动会把透明背景渲染成黑色。遇到时退回到不透明的圆角窗口。
- 休息开始时铃响，她转过来；点一下，书重新打开，右页就是她带来的东西。
- Electron 实现约 1–2 小时，人物的透明图层本来就有。

## 7. 设置与配置

- **首次启动向导**，三步：填模型 → 填邮箱授权码（可跳过）→ 选角色，然后开始。评委要核验部署能否复现，部署说明与向导一一对应。
- **供应商**：分槽位，包括主对话、后台整理、语音和 Rodin。每个槽位填地址、密钥和模型，带一个“测试连接”按钮，实际验证流式输出和工具调用。密钥只存在主进程的加密存储里。
- **邮箱**：授权码，读取的文件夹，只读接入之后的邮件（默认开启）。
- **番茄钟**：专注、短休息和长休息的时长。
- **插件**：
  - MCP server 列表。可以直接粘贴 Claude Desktop、Cursor 那种标准的 `mcpServers` 配置，已有的配置拿来就能用。
  - 每个 server 有启用开关、连接状态和工具列表。首次启用时显示完整命令并请用户确认。
  - 每种情境能用哪些工具，单独设置；对外写入一律需要批准。
  - Skills 先做只读列表。
- **角色**：当前角色，以及导入角色包。
- **数据**：备份与恢复（羽毛笔）。
- **用量与预算**：设置页显示当天用量；平时界面上不显示，只在达到上限时明确提示。
- **关于**：第三方来源与参考声明。

## 8. 让用户做自己的桃子

- **首版做角色包导入**（`.lca-character`）：名字、人设，以及按命名约定组织的图片。我们自己的桃子本来就按角色包加载，所以导入功能几乎是顺带做出来的。
- **人设和产品规则分开**（建议）：
  - 角色包里的人设只写她是谁、怎么说话。
  - 工具规则、完成证据、番茄钟里什么时候开口，这些由 harness 的系统提示负责。
  - 这样导入别人的私设时，这些规则不会跟着丢。
  - 我们自己的桃子，用用户赛前已有的原创人设改编（[美术规格](art-spec.md) §5）。
- **缺什么回退什么**：只有一张图，就当静态立绘；没有闭眼贴片，就不眨眼；没有表情贴片，就一直用底图的表情；没有房间背景，就用空白纸页。
- **不做**：上传一张图，自动拆分、补全、生成差分。运行时要调用生图 API，质量和一致性都没验证过。路演里作为路线图口头讲。
- 对评分的意义：角色包导入加缺素材回退，证明“每个人都能有自己的她”不只是口号。

## 9. 失败要分开显示

- 邮箱登录失效 ≠ 没有新邮件。
- 模型限流，与服务不可用分开提示。
- 语音失败，已改为纯文字。
- 礼物生成失败或超时：她如实说，不说“做好了”。
- 预算用完：后台活动暂停，界面明确提示。

评委核验系统稳定性时，容错处理是重点之一。

## 10. 不做

- Live2D、Spine 等骨骼动画。
- 用 AI 视频生成她的待机动作。
- 可选：只给背景做循环视频，比如窗外。
- 线条抖动滤镜只用在转场里，不常驻。
- 翻页动画可选，有余力再做。
