# 体验设计：界面、形象与语音

整理日期：2026-10-11，来自当日的技术讨论；2026-10-12 修订 §7（首次启动改为用户设计的新手流程）和 §9；2026-10-13 在 §2、§3 加入心流、分身和外出（她会出门，左页显示她在的地方）。状态：用户确定了书本式主界面和迷你陪伴窗；其余内容是用户同意按建议记录的方向，文中数值都是默认值，赛中按实际效果调。工程部分见 [技术方案](tech-design.md)，画风、角色外观与借鉴分界见 [美术规格](art-spec.md)。

## 1. 两条原则

- **画面是她的状态的投影。** 她在做什么、处于哪个阶段、此刻几点，都直接决定画面，而不是一组随机播放的动画。这样桃子看起来就不只是“一堆画”。
- **应用就是片子里那本书。** 左页是她在的地方，平时是她的房间；右页是用户的页面。她交给用户的东西，从左页越过中缝来到右页，对应视频第 07 镜的日程纸。

界面分两种做法：

- 主界面（书）定制、手绘风，界面风格见 [美术规格](art-spec.md) §6。
- 设置页朴素实用，用 Tailwind CSS + shadcn/ui，不追求风格。设置页的信息架构参考 AIRI 的设置页分组（供应商、模型、角色卡、模块、数据）。AIRI 是 Vue，本项目用 React 重新实现，不搬组件和样式，提交时注明。

## 2. 主界面：一本打开的书

### 左页：她在的地方

- 平时是她的房间。她出门时，左页翻到她在的那一页（首版是海岸和秋千，背景复用片子）。翻回房间页，能看到伞架空着、桌上压着一张纸条，看得出是出门了，不是不见了。家具都在房间页（[技术方案](tech-design.md) §3.14）。
- 桃子本人，姿势、表情和光线随状态变化（§3）。
- 她最新说的一句话，以对话框显示，和语音同步。
- 桌上的钟就是番茄钟，显示剩余时间。不做全屏大倒计时。她在外面时，剩余时间显示在右页顶部的番茄格里。
- 书桌上有几个固定位置，摆她外出带回来的东西。点开能看到哪天、在哪里带回来的。
- 桌上挂一块门牌，切换情境：工作中、安静、休息。“暂停所有后台活动”另设一个开关，叫“熄灯”。README 要求“安静”和“全部暂停”是两种不同状态，门牌和熄灯正好分开表达。番茄钟的阶段会自动翻转门牌（[技术方案](tech-design.md) §3.5）。

### 右页：用户的页面（对话）

- **顶部**：今天的计划和番茄格。
- **对话流**：
  - 她的话正常显示。
  - 工具活动显示成手写体小字，比如“我去邮箱里看看～（3 封新邮件）”。这些文字由代码按模板生成，不额外调用模型。
  - 她执行任务时，`update_plan` 的步骤显示在任务卡里，逐项打勾。
- **候选卡片**：截止时间、计划完成时间、引用的邮件原文，以及“确认”“忽略”两个按钮。“证据 → 候选 → 确认”要让评委亲眼看到，所以来源原文必须在卡片上。
- **交付卡片**：日程文件、整理好的资料，从左页越过中缝滑过来，点开就是真实文件。
- **变更卡片**（2026-10-13）：老师改了截止时间时出现。写旧时间、新时间，附两封邮件里的证据原文；确认后，手机日历里那一项随之更新（[技术方案](tech-design.md) §6.1）。
- **输入框**在最底下。她干活时按“发送”，消息会排队，在下一步并入；另有一个“停止”按钮。
- **指令**：输入 `/` 弹出当前能用的指令。普通对话里能用 `/privacy`，心流模式另有一组（[技术方案](tech-design.md) §3.11、§3.15）。开着 `/privacy` 时，输入框旁有一个滤芯标记。
- **一天一页**（2026-10-13）：新的一天翻到新的一页，往回翻能看到前几天的对话。她的墨色褪成铅笔灰，字始终能读。往回翻时，左页换成那天拍下的照片，越早越淡（[技术方案](tech-design.md) §4.1）。
- **引用**：在旧的一页上选中一句话点“引用”，她会去回忆。这时显示“桃子正在回忆……”，左页短暂换成那天的照片（[技术方案](tech-design.md) §4.2）。
- **心流模式**（2026-10-13）：她进入心流时，右页从对话换成工作视图：计划、命令与输出、diff、审批。退出后换回对话，心流的工作摘要作为一条记录出现在对话里（[技术方案](tech-design.md) §3.11）。

### 书签

书页边缘做成书签：对话、日程、礼物、日记、设置。

- **礼物架**：每件礼物用 `<model-viewer>` 显示，点开能看到它来自哪段经历。
- **日记**：她写的日记，带主观标记。2026-10-13 起，日记加密存在她的文件夹里，钥匙藏在共同经历里，随进度解锁（[技术方案](tech-design.md) §3.16）。书签里建议显示日期和锁，也能在这里输钥匙解开（待定）。
- **数据**：备份和恢复。私人存档在界面上就是那支羽毛笔：第一件真事之后她把它送给你，以后从这支笔导出；恢复时颜色从笔尖晕开，和视频第 18 镜一致（[技术方案](tech-design.md) §3.7）。设置页里的导出一直都在。

## 3. 状态与画面

| 状态 | 画面 |
| --- | --- |
| 在做用户交给她的活 | 侧面，坐在电脑前 |
| 在做自己的事（安静陪伴） | 低头写字 |
| 休息、交流、向用户提问 | 转过来面向你 |
| 应用窗口获得焦点 | 她抬头看你一眼。每天第一次打开时，有事才开口（[技术方案](tech-design.md) §3.5） |
| 姿势切换、存档恢复 | 线稿 → 上色的过渡，复用提取出的线稿 |
| 每条回复 | 带一个情绪标签，切换到对应表情（4 种，具体随角色设定图定） |
| 说话 | 嘴型按语音音量开合 |
| 一直在 | 每 2–6 秒随机眨一次眼，每次约 0.15 秒；呼吸周期约 3.5 秒，缩放不超过 1% |
| 心流中 | 坐在电脑前，和“在做用户交给她的活”同一个姿势 |
| 派出分身（有余力） | Q 版的小桃子跑到对应的家具旁干活，做完冒烟消失，纸飞回她桌上（[技术方案](tech-design.md) §3.12） |
| 外出 | 左页是她在的那一页，穿出门那套衣服；首版尽量复用片子里的外景和她在外景里的画面（[技术方案](tech-design.md) §3.14） |
| 刚回来 | 带回来的东西出现在书桌上，先是线稿，再上色 |
| 时段 | 早晨、白天、傍晚、夜晚四档光线叠加层；窗外天色跟着变；夜里台灯亮 |
| 环境 | 窗外、茶杯热气等小动态，按时段和活动出现 |
| 新邮件 | 不急的：信箱口露出一封信，迷你窗里她手边多一张卡片。急件另弹一条系统通知（[技术方案](tech-design.md) §6.1） |
| 睡着 | 凌晨 4 点以后、你不在时，她在床上睡着，房间暗下来；夜里的整理在这时做（[技术方案](tech-design.md) §4.1） |
| 回忆中 | 左页短暂换成那天的照片 |

姿势对应视频镜头，素材与片子共用：

- 写字和用电脑：第 03 镜。
- 面向你：第 04 镜。因此第 04 镜提到第一档制作（[赛前统筹](team-plan.md) §3）。
- 推出交付物：第 07 镜。

## 4. 素材与差分

- **底图**：每个姿势一张完整立绘，从开赛后最先冻结的角色设定图出发，和视频共用。
- **面部差分**：用 NovelAI 只重绘脸部区域，贴在底图上。
  - 面向你的姿势：4 种表情，每种都有睁眼、闭眼和张嘴三张，约 12 张贴片。
  - 侧面的两个姿势：只做闭眼贴片，用于眨眼。
- **命名约定**：姿势、表情和变体写进文件名，角色包导入时按名字自动识别（§7）。

## 5. 语音

- 云端流式合成。候选是 MiniMax、火山引擎豆包和 Azure，均未验证，赛前挑一家试。
- 用现成或设计出的音色，不克隆真人声优。
- 文字先出，语音随后跟上。语音失败时显示“语音失败，已改为纯文字”，不影响对话。
- 有静音开关。
- 赛中约 2–3 小时。2026-10-13 起排在第三圈，有余力才做（[技术方案](tech-design.md) §9）。

## 6. 迷你陪伴窗

用户 2026-10-11 确定要做。

- 专注段开始时，书合上，缩成桌面角落的一个置顶小窗。透明背景，只有她坐在桌前继续做事。用户用别的软件时她也在场，这才是桌面陪伴。
- 透明区域要能点穿：默认用 `setIgnoreMouseEvents(true, { forward: true })`，鼠标移到她身上时再接收点击。
- 有些显卡驱动会把透明背景渲染成黑色。遇到时退回到不透明的圆角窗口。
- 休息开始时铃响，她转过来；点一下，书重新打开，右页就是她带来的东西。
- Electron 实现约 1–2 小时，人物的透明图层本来就有。

## 7. 首次启动与设置

### 7.1 首次启动：把她画出来

2026-10-12 用户设计，取代原来“模型 → 邮箱 → 角色”的三步向导。助手补充的部分（存档入口、家具表、账户、角色来历、编码环境的配置项），用户同日逐条确认。动画做法是助手的实现方案，赛中按效果调。

意象：**铅笔是你，羽毛笔是她。** 前半段你把她画出来，后半段她给自己的世界上色。和片子同一套语言，新手引导本身就是一段小 PV。

| 步 | 右页 | 左页画面 |
| --- | --- | --- |
| 0 | — | 小窗口里一本合着的书。初始化完成后打开，进入全屏（设置里可改） |
| 1 | 写你的名字（键盘输入） | 铅笔画出空房间，只有线条，还没有人；接着勾出她的线稿 |
| 2 | 配置第一个模型供应商。体检通过、模型选对 | 彩铅给她上简单的颜色 |
| 3 | 你想怎么称呼她（默认桃子） | 排线晕染成更真实的颜色 |
| 4 | 基础身份：性格、情绪、爱好等最基本的提示词，预先填好我们的桃子；也可以在这一步导入角色包 | |
| 5 | 其他分块的提示词，包括工具调用指引（[技术方案](tech-design.md) §3.9）；以及“关于你”：你的称呼和偏好，存在你的档案里，不进角色卡（[技术方案](tech-design.md) §4.2） | |
| 6 | 完成 | 她活过来，拿起羽毛笔探索这个环境。新手引导：点房间里的家具，她好奇地给它画上颜色 |
| 7 | — | 整个房间上色，她注意到书页之外的你，无缝转入对话 |

- **光标**：鼠标停在主界面上时变成一支铅笔，热点在笔尖。设置里可以关掉。
- **第 0 步的另一个入口**（用户批准）：“我已经有一本书了”，导入私人存档，直接走恢复动画：颜色从羽毛笔尖晕开，整个房间一次上色（[技术方案](tech-design.md) §5）。路演的最后一击是“清空本地数据 → 导入存档”，清空后重新打开会进入新手流程，所以这个入口必须有；评委复现时也可能用到。
- **家具就是设置**：向导里只留必填项（第 1–5 步）。可选的配置放到房间里，点哪件家具就配哪一项，配好了她就给它上色。

  | 家具 | 配置 |
  | --- | --- |
  | 电脑 | 编码环境（见下）。允许她工作，电脑就开机；不允许就不开 |
  | 信箱 | 邮箱（演示主线靠它） |
  | 衣柜 | 换衣服：形象和角色包 |
  | 书架 | 插件和 skills |
  | 工作台 | Rodin（礼物） |
  | 钟 | 番茄钟时长 |
  | 台灯 | 熄灯 |
  | 床 | 作息：她几点睡（默认凌晨 4 点）、你的作息和休息日（[技术方案](tech-design.md) §3.14）；夜里整理哪些事、用多少预算（建议，2026-10-13） |

  编码环境在点电脑时配置，不放进向导（用户同意）。朴素的设置页（§7.2）照样保留，所有配置都能在那里改，给熟练用户和部署说明用。
- **账户**：不设服务器，不做第三方登录，就是本机档案，按 UUID 区分（数据表本来就带 user_id）。默认不设密码：Windows 账户已经隔离了用户，密钥也绑在系统账户上加密；密码如果用来加密数据，忘了数据就没了。需要时在设置里做成可选项，只用来加密导出的存档。多用户切换首版不做。
- **名字不做手写**（用户定）：第 1 步时模型还没配，Windows 自带的中文手写识别要装语言包，不可靠，识别错了很恼人。名字用键盘输入。
- **角色来历**：开放填写，但有两种矛盾要处理：
  - 和世界设定（房间、书、羽毛笔）矛盾：产品规则和世界设定写在 harness 的系统提示里，优先于角色卡（§8）。
  - 用户写“我们从小就认识”这类共同经历：和“有来源的共同经历”冲突（README）。存成“用户写的设定”，不进经历记忆；共同经历只来自真实发生过的互动。提示文案赛中定。
- **编码环境**（点电脑时配置；沙箱方案由用户在赛中定，见技术方案 §3.6）。编码能力本身由预设插件加一份官方 skill 提供（技术方案 §1）。配置项：
  - 范围：不允许 / 只在她的书桌（她房间文件夹里的 `书桌/`，[技术方案](tech-design.md) §3.16）/ 加上用户指定的文件夹 / 整台电脑。
  - Shell：自动检测 PowerShell、Git Bash、WSL，可以手动指定路径。
  - 沙箱方式；联网：禁止、白名单或允许。
  - 审批模式：每次都问 / 只读自动、写入要问 / 书桌内自动 / 全部自动（bypass，红字警告）。
  - 删除、格式化、改注册表、git push 等危险操作，不论哪种审批模式都要问。
  - 单条命令的时长和输出上限。
  - 密钥隔离：她跑的命令不继承应用的环境变量；应用的数据目录（密钥、存档）永远不在她能访问的范围里。
  - 官方预设插件启用哪些，能不能导入外部 MCP。Computer use（看屏幕、动鼠标）不单独设开关，仿照 OpenAI 的做法，做成预设插件之一。
  - 展位模式下强制关闭运行代码（技术方案 §3.10）。
- **跳过与重来**：动画可以跳过，第二次以后默认跳过；设置里有“重新初始化”。全屏要适配投影仪的 16:9，书的比例固定，多出的边用桌面纹理填。
- **部署复现**：部署说明对应必填的几步，加上设置页里的可选项。评委用自己的密钥照着走一遍就能复现。

**动画怎么做**（建议；助手负责实现和调试，用户看明暗和形体，队友看色相）：

- 素材：房间和她各三层，线稿、简单上色、完整上色，严格对齐。线稿用 NovelAI 的 Line Art 从彩图提取（实测和原图对齐，见[美术规格](art-spec.md) §2.3）；简单上色版用色块化处理，或试 Colorize 工具。都是赛中的美术工作。
- “铅笔画出来”：不做逐笔的矢量动画（从位图提取单线不可靠）。用笔刷形状的遮罩沿预设的涂抹路径逐步揭开线稿层，一支铅笔跟着笔尖走。
- “晕染上色”：一个带噪点边缘、向外扩散的遮罩着色器。存档恢复（技术方案 §5）和姿势切换（§3）本来就要这个效果，一套代码三处用。
- 家具遮罩：每件家具一个多边形，既是可点击的区域，又是上色的遮罩。
- 工期粗估：揭开和晕染的系统约 3–4 小时（和存档恢复共用），新手流程和遮罩约 3–4 小时，排在 32–38 h 的界面时段。
- 降级：逐件家具上色 → 整个房间一次淡入上色 → 右页上的朴素向导（技术方案 §9）。

### 7.2 设置页

- **供应商**：一张供应商列表，每个填地址和密钥，带一个“测试连接”按钮，实际验证流式输出和工具调用。密钥只存在主进程的加密存储里。语音和 Rodin 仍是各自的槽位。
- **模型**（2026-10-13 用户提出）：按用途选模型的一组下拉框，从配好的供应商里选。建议的几项：主模型（对话）、心流模型（编码）、后台模型（整理记忆、日记、当日安排、上下文压缩）、分身模型、隐私模型（滤芯，[技术方案](tech-design.md) §3.15）。默认都是“跟随主模型”；隐私模型选“跟随主模型”，就是信任主模型，不隔离也不过滤。附件和拖进来的文件要不要过滤，由 `/privacy` 控制。
- **邮箱**：授权码，读取的文件夹；每次扫描读最近的未读邮件，最多 30 封；急件提醒规则，能看、能删。
- **番茄钟**：专注、短休息和长休息的时长。
- **插件**：
  - MCP server 列表。可以直接粘贴 Claude Desktop、Cursor 那种标准的 `mcpServers` 配置，已有的配置拿来就能用。
  - 每个 server 有启用开关、连接状态和工具列表。首次启用时显示完整命令并请用户确认。
  - 每种情境能用哪些工具，单独设置；对外写入一律需要批准。
  - Skills 先做只读列表。
  - 每个插件和 MCP server 可以打上或去掉“可能处理隐私数据”的标记（[技术方案](tech-design.md) §3.13、§3.15）。
- **角色**：当前角色，以及导入角色包。
- **数据**：备份与恢复（羽毛笔）。
- **用量与预算**：设置页显示当天用量；平时界面上不显示，只在达到上限时明确提示。
- **开发者模式**（2026-10-13 用户定，正式版保留）：默认关闭。打开后，调试工具可以连上应用，调试面板多出上下文查看器等视图（[技术方案](tech-design.md) §3.17）。展位模式下不能开。
- **关于**：第三方来源与参考声明。

## 8. 让用户做自己的桃子

- **首版做角色包导入**（`.lca-character`）：名字、人设，以及按命名约定组织的图片。我们自己的桃子本来就按角色包加载，所以导入功能几乎是顺带做出来的。
- **人设和产品规则分开**（建议）：
  - 角色包里的人设只写她是谁、怎么说话。
  - 工具规则、完成证据、番茄钟里什么时候开口，这些由 harness 的系统提示负责。
  - 这样导入别人的私设时，这些规则不会跟着丢。
  - 我们自己的桃子，用用户赛前已有的原创人设改编（[美术规格](art-spec.md) §5）。
- **缺什么回退什么**：只有一张图，就当静态立绘；没有闭眼贴片，就不眨眼；没有表情贴片，就一直用底图的表情；没有房间背景，就用空白纸页。
- **给插件留的具名槽位**（2026-10-13）：插件声明要用的表情、动画槽位（比如 `expression: proud`），角色包按命名约定提供，缺的同样回退。写插件的人和画角色的人由此对接（[技术方案](tech-design.md) §3.13）。
- **不做**：上传一张图，自动拆分、补全、生成差分。运行时要调用生图 API，质量和一致性都没验证过。路演里作为路线图口头讲。
- 对评分的意义：角色包导入加缺素材回退，证明“每个人都能有自己的她”不只是口号。

## 9. 失败要分开显示

完整规则见[技术方案](tech-design.md) §3.9“出戏防线”（2026-10-12）：她能开口时，工具失败由她按角色卡的工具调用指引说；她开不了口时，由书本旁白按类别提示。两种情况下，消息后面都有“！”，点开就是原始报错。

- 邮箱登录失效 ≠ 没有新邮件。干活的工具失败，她必须如实说。
- 模型调用失败分类别提示：上游繁忙、配置错误、内容被拦截、网络、余额或额度用完、说到一半断了。
- 语音失败，已改为纯文字。
- 礼物生成失败或超时：她不能说“做好了”。可以按指引改编进情节，比如“胶水用完了”，失败的礼物排进她之后的安排。
- 预算用完：后台活动暂停，界面明确提示。

评委核验系统稳定性时，容错处理是重点之一。

## 10. 不做

- Live2D、Spine 等骨骼动画。
- 用 AI 视频生成她的待机动作。
- 可选：只给背景做循环视频，比如窗外。
- 线条抖动滤镜只用在转场里，不常驻。
- 翻页动画可选，有余力再做。
