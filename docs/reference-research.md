## 3. 对 GPT 线最有用的结论

1. **插件化包含执行器本身。** 用小型装配层提供服务注册、依赖检查、生命周期和事件分发；日志、模型、工具、循环、调度都可经它装入。首版只需启动时装配，不需要复刻 dsh 的热更新、配置叠层和包管理。
2. **安全不能由可重排的普通钩子决定。** 不可绕过的约束在实际工具执行入口检查；界面隐藏工具、插件清单和模型提示都不能替代执行检查。同进程代码插件是可信代码，不等于沙箱。
3. **日志有不同阅读权限。** 原始工具结果留在受保护的数据域；她的模型上下文、记忆抽取和回忆必须共用允许她看到的投影，隐私过滤不能只发生在第一次读邮件时。
4. **调度和发言分开。** AIRI 的 focused gate 不适合直接继承。我们的专注段继续工作与自主活动，把正常发言和问题留到休息；熄灯才停全部活动。
5. **取消必须到达副作用所有者。** 模型请求停止、MCP 请求超时和游戏玩家释放按键是三个不同事实。工具结束要等它停止或明确报告状态未知；不能把停止等待当成停止动作。
6. **MC 可通过标准 MCP 接入，但需要小量应用编排。** 工具子集、事件轮询、长动作查询、取消、结果核对由本项目负责；持续跟随不是当前 MCP 工具清单里的一条现成工具。

## 4. 开赛时按这个顺序使用调研

| 工作 | 先查哪里 | 需要落地的结果 |
| --- | --- | --- |
| 第一小时共享接口 | dsh §3、AIRI §2 | 有身份与序号的事件；状态快照；受限命令；工具结果和任务终态 |
| 底座与插件加载器 | dsh §2–5 | 注册可撤回、依赖可检查、工具权限在执行处生效、所有官方功能经加载器装入 |
| harness 与调试模式 | dsh §4–6、AIRI §2 | 单推进器、插话与停止、有界执行、假依赖与真实依赖走相同接口 |
| 记忆、翻页、恢复 | AIRI §3–5 | 来源可追溯、只压投影、跨会话检索、恢复无自动副作用 |
| 展位 MC | mcpfabric §2–6 | 两个玩家在同一世界，工具打到她的客户端；停止、断线和复位可验证 |

这些是研究后的建议与查阅入口，不增加冻结设计的范围，也不把第三圈改成必做。各功能优先级继续以 [技术方案 §9](tech-design.md#9-赛中时间安排48-小时按圈排) 为准。

## 5. 本轮发现的资料滞后

- dsh 原目录落后于远端，旧设计里记录的装配方法要以本轮固定源码复核。
- AIRI 的早期 MEMORY-DESIGN 有“零调用方”等历史勘探结论，当前 chat store 已接入检索、抽取和压缩，不能按早期描述判断现状。
- mcpfabric README 写“50+”，本轮 `mcp-server/src/tools.ts` 有 **96 个具名工具条目**；实际运行进程的 listTools 仍须开赛后核对。
- AIRI 最新鞘翅证据首页仍写 **M7 尚未通过**。既有局部通过与当前严格整程验收分开；展位选型不依赖这条未完成验收的飞行能力。
