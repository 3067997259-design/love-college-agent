## 当前优先级

2026-10-26 已按用户建议接通现有门牌的工作入口和主模型文本状态交接，见[实现与验证](research/v1.2-state-routing-20261026.md)。本地合成流程通过；下一步仍需获授权地验证真实聊天模型的格式遵循、工作模型执行及协作交付，不能将此变更视为供应商兼容问题已解决。

同日后续[真实复测](research/v1.2-real-state-collaboration-20261026.md)已验证主模型文本交接、DeepSeek 官方工作模型的独立委派与两人团队执行，合计 167,449 / 480,000 预留单位。团队自拟规则有一处判定文字矛盾，保留内容质量缺口；未追加指定规则员身份续用、长期使用或安装包验收。

再后续获授权的[同一规则员续用](research/v1.2-real-member-reuse-20261026.md)也已验证：原测试档重启恢复，原成员 ID 不变、无新建成员，规则员完成新输入核对后主角色汇总；累计 204,319 / 480,000。模型汇总文案的否定词误用仍单独记录，长期使用和安装包范围不变。

2026-10-19 用户提出重新研究正常项目工作能力：旧心流仅限角色书桌和受限文本副本，不能代表完整工程工作环境。工作区、授权和执行后端的对照见 [harness 调研](research/harness-workspaces-20261019.md)，同日选定 DSH。

同日决定 fork DSH 替换心流，[接入记录](research/dsh-fork-spike-20261019.md) 跑通了新手请求、工作中插话与按项目授予的信任。DSH 的工作细节记在它自己的会话日志里，journal 只记对话、引用、审批与信任；第三方内容按 D2 逐次询问，并在下一轮撤回。书本已能排 Markdown、按轮收起活动、一键回答审批；DSH 随安装包分发，书里选项目，默认启用。2026-10-20 以此发布 v1.0.0。

1.0.0 之后的顺序（2026-10-20）：

1. **1.0.x：书本与新手。** 按维护者试用提出的小项打磨：聊天模型与工作模型、思考强度、新手上色与第一次干活的开头、设置成为书里的一页。
2. **1.1：一个她，一天一条时间线。** 2026-10-21 完成，见 [v1.1.0](releases/1.1.0.md)。
   - 当时的问题：她主动说的话（番茄、邮件、生活）仍走旧循环，DSH 会话看不到；换项目会新开会话；日切后没有前几天的摘要。
   - 已完成的目标：自主事件注入同一个会话；换项目不打断当天的对话；带上记忆摘要。
   - 已完成的收尾：移除旧心流和 `LCA_DSH=0` 回退，冒烟测试改用脚本模型跑在 DSH 上。
   - 进度（2026-10-21）：自主事件、换项目、记忆与摘要已进 DSH 会话；引用与第三方内容的退役改为从会话日志折叠，重启后照样生效；旧心流与 `LCA_DSH=0` 已移除。开发者场景（脚本回复）已经由本地模型接口跑在 DSH 上，旧循环已删除，只剩 Minecraft 游戏回合自己的小循环。她的提问改用 DSH 自带的 `ask_user_question`，书里的问题卡一次可答一到四件事。
3. **1.2：给熟练用户的扩展。**
   - 书里用 DSH 自己的管理器装插件、MCP 和 skills。
   - 子代理与智能体团队的界面，按需展开，不删工具。
   - 公开之前先补两个缺口：子代理里的沙箱信任，长期队员读过的第三方内容的撤回。
   - 2026-10-23 开始实施，见 [1.2 现状审计与开发计划](research/v1.2-development-plan-20261023.md)。P0–P5 已完成对应隔离验收；[P5 回执](research/v1.2-p5-20261024.md)记录普通委派 / 团队共存、选择引导与成员 / 任务功能面板。P6 的本机组合、候选包及实际升级已通过；1.2 尚未发布，第二机、获授权的真实模型、实际日用与全房间美术仍分别待验收。
   - 子智能体 UI：团队远景与小卡片已接线，V2 按真实工作类型安排位置，工位和状态图已齐备。剩余为大小桃子画风统一与实际日用观感，详见上表。
4. **每个版本：** 第二台机器的安装与升级验收；DSH 升级前先过 bridge 检查和打包探针；缓存命中率实测。
5. **按需：** Office 与语音的按需下载。

### 已记录的后续改进

- **模型能力手动声明（2026-10-26 已实现，尚未打包发布）。** 用户展示的 DSH 流程已接到聊天 / 工作模型卡，字段、绑定、来源区分、恢复自动和实际 DSH 参数均有[本地服务证据](research/v1.2-model-capabilities-20261026.md)。截图的数值未写入用户配置；真实服务是否接受对应参数仍按授权另验。

上游 DSH 目前不收 PR 和 issue：需要的能力先用插件层（Cordis 服务替换、模型选择、钩子）解决。非改源码不可时，补丁放在 fork 的 `lca` 分支上，每个补丁写清原因，并改为从 fork 构建运行时。

2026-10-19 曾形成 [一天一条时间线的 demo 计划](research/day-timeline-demo-20261019.md)，记录接入前的连续性、成本、安全和节拍问题。其“结论出来前不替换心流”属于当时实验约束；后续 DSH 接入和旧心流移除以 v1.1.0 发布记录为准。

1. **让新用户能开始使用。** 减少安装与模型配置阻碍，说明外部依赖和输入限制，核对干净机器的安装与升级。
2. **让日常使用可靠。** 观察真实模型和网络下的失败、停止与恢复，避免半截工作、重复动作和不明确等待。
3. **守住经历和数据。** 继续验证记忆纠正、来源退出、日切、备份与升级；保存记录与准确回忆分别评价。
4. **改善共处体验。** 检查主动发言时机、安静模式、生活连续性、资源消耗与实际作品质量。
5. **逐步开放扩展。** 清楚记录插件和角色契约，改善导入、依赖检查、缺素材回退及来源说明。

每次选择一个完整场景推进，先明确用户要完成什么，再决定是否需要新模块。维护者自己的连续使用与少量自愿试用反馈，用来发现问题和验证价值，不引入增长或留存考核。

## 保持开放的方向

更多学校来源、真实 TTS / OCR 质量、长期自主生活、更多角色与场景、素材生成辅助都值得研究，但需要独立的配置、成本与体验验证。

一图生成完整差分、光学遗忘体验、非尾步选择性撤销、显式关系阶段与解锁没有全部成为生产能力。它们的实验、建议和已实现部分要明确区分；研究入口见 [研究索引](research/README.md)。

## 每次维护的交付

- 问题、预期行为、实际变化与已知限制。
- 与改动相称的检查；真实服务、安装和长期运行只报告已实际完成的部分。
- 同步使用说明、来源与版本记录。
- 有数据迁移时先保全旧资料，兼容与回滚有依据；不为了演示或测试清空用户存档。
