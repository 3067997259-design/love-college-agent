# 插件与校园助手

插件书签集中管理本地插件、skills 和外部 MCP。候选在对话里的卡片上确认或忽略，确认过的事在日程页查看和导出；设置中的快捷入口只负责打开插件页。

评估新的 DSH 或其他生态插件时，使用 [插件迁入评估规格](plugin-migration-spec.md) 与 [评审模板](templates/plugin-migration-review.md)，分别判断用户价值、迁入路线、核心流程影响、宿主缺口、运行证据和许可。LCA 本地插件、DSH bundle、MCP 与 skill 是不同接入面；可导入或可加载不代表整包可用。该规格是评审流程，不是通用转换器或新增的插件 SDK。

## 校园助手

当前推荐入口是 [campus-assistant](../plugin-packages/campus-assistant/README.md)，需要 LCA v0.1.10 及另行安装、配置和登录的 Student Hub 后端。插件不附带后端工程、Python、个人数据库、学校账号或登录状态。

1. 从 [Release](https://github.com/3067997259-design/love-college-agent/releases/tag/v0.1.10) 获取校园助手包，或使用仓库中的 `plugin-packages/campus-assistant`。
2. 在普通模式的插件页添加该目录，核对实际路径与指纹后启用。其他电脑参考包内 `connection.example.json` 填写后端、Python 和配置路径；连接文件不放账号密码。
3. 请她“检查校园助手是否准备好了”。检查只证明依赖与配置存在，不证明账号认证。
4. 需要真实采集时，明确要求扫描；等待同一个 jobId，查询进度或取消。扫描结束后读取并整理证据，再在书页核对候选原文、确认或忽略。
5. 确认后在日程页点「导出成日历文件」，从交付卡打开实际 `.ics` / Markdown。

也可只“导入已有校园事项”，读取已有结果而不发起新扫描。重复导入保留当前决定，有实质日期变化才形成新版本。来源失败不能解释为没有更新，本地文件不等于外部日历 / Todoist 写入，插件不支持课程提交。

启用一体插件后，旧 `student-hub` MCP 与 `student-hub-candidates` 工具不再重复提供，已有候选和忽略记录保留。旧包保留用于兼容与调试，不再作为新用户的组合安装步骤。

## MCP 与本地代码插件

MCP 支持 stdio 和 Streamable HTTP。使用标准 `mcpServers` JSON 导入，连接时核对 fingerprint 及原生窗口里的实际命令 / 参数或地址；精确工具白名单由用户配置，重启不自动重连，OAuth 尚未接入。

本地代码插件按 manifest 声明工具、权限、入口和家具槽位，由用户核对指纹并启用。代码插件会在主进程的插件边界执行，不应把安装未知插件等同于只读文档导入。

私有工具结果走主进程窄出口，原文不直接作为普通工具回执。隐私模式见 [隐私与数据](privacy-and-data.md)；模型输出仍需校验，不把插件声明当作可信内容证明。

开发入口为 `src/main/plugins/`、`src/main/mcp/`、`src/shared/` 与 `plugin-packages/`。现有完整包可作为接口示例，外部依赖、工具权限和数据归属需要逐项说明。

## 1.2 开发中的 DSH 扩展管理

P4 已在插件书签接入 DSH 扩展管理。它与 LCA `manifest.json` 插件格式不同，不能互换：已有 LCA 包继续用右上角“添加插件”；DSH bundle 用“添加 DSH 扩展”，经系统目录窗口选择含 `package.json` 与 bundle 声明的本地目录。

安装先核对候选指纹，再在本页下方批准。新增 bundle 默认停用；构建脚本另外批准。列表分别显示已保存的启停设置、当前实际加载状态和待重启状态。停用运行中的代码后，要批准重启，才能移除。随应用维护的组件折叠显示，不能在页面中停用或移除。

1.2 的 Windows 适配层为获批准的包管理进程提供随包运行时，普通 `node build.js` 生命周期脚本不要求另装 Node / pnpm。不会修改系统 PATH；原生编译器、Python 等扩展自身额外需要的工具仍须另行配置。rc.1 补充验收发现过此入口缺失，修复及替代候选进度见 [P6 回执](research/v1.2-p6-20261024.md)。

“最近的扩展操作”可取消进行中的操作；取消或断连不保证撤销已发生的效果。结果未知时点击“核对这次操作”，查询原操作的持久回执；没有完成证据时仍保持未知，不自动重新安装。底座边界见 [P3 回执](research/v1.2-p3-20261023.md)，页面验收见 [P4 回执](research/v1.2-p4-20261023.md)。

## Markdown 技能

技能页现在显示 DSH 实际可用的技能目录，不再把插件 / MCP 工具名当作 skills。只读取选定项目自身的 `.dsh/skills`、`.agents/skills`，以及此存档的 `dsh-home/skills`；不向上搜索父仓库，不自动引入其他应用的个人 skills。扩展注册的技能也会列出。

可以选择含 `SKILL.md` 的目录，导入到当前项目或此存档。正文须有包含 `name` 和 `description` 的 YAML frontmatter；名称使用小写字母、数字和连字符。导入会复制资源目录、显示来源指纹并请求批准，不运行目录里的脚本。同名目录不覆盖；原有文件仍由用户在来源目录维护。

存档级技能的正文由受限 provider 读取；附带文件仍处于 `dsh-home` 私有根内，未向通用文件工具开放。需要她进一步读取资源或操作脚本的技能请导入项目，再按项目的文件与命令权限执行。

同名的文件系统技能按项目 `.dsh`、项目 `.agents`、此存档的顺序优先；扩展提供的技能参与 DSH 自身的合并规则，页面标明实际胜出项和被覆盖项。解析失败、缺少 `SKILL.md`、不允许的链接均有反馈。技能搜索根及条目拒绝符号链接 / junction，单目录最多 512 项、单份 Markdown 最多 1 MiB；导入总量沿用扩展目录的 5000 文件 / 50 MiB 限制。

只允许通过页面移除此前由页面导入且内容未改动的目录。移除将其移至同级 `lca-skill-removed` 备份目录；已修改或原有文件需在本地维护后刷新。切换项目会清除上一项目的目录投影。每次模型目录读取与技能加载重新核对文件；`skill` 工具结果进入现有第三方来源与下一轮退役流程，不把旧正文当作当前文件。

MCP 继续由 LCA 维护原有连接，再向 DSH 提供白名单工具；页面标明所有者、来源和实时连接状态。没有静默迁移为第二条 DSH 连接，也没有重新注册校园工具。
