# Love, College & Agent

项目说明文档参赛队伍 LECA · 上海科技大学 · 2026 年 10 月 18 日

### 一个能办事，也能留住共同经历的个人 Agent

作品面向大学生活，将校园通知、资料处理、专注计划与持续陪伴放进同一本桌面电子书。左页呈现角色的房间与生活，右页承载对话、候选事项、交付和工作记录。工作能力给用户打开应用的理由，共同经历与角色生活构成长时间使用的体验。

### 三个核心场景

校园事务：读取通知后先形成附证据的候选。用户核对原文并确认，再生成真实的日历文件或 Markdown；忽略和改期有各自的状态，不把扫描当作接受建议。

资料与专注：拖入文字层 PDF、文本或 Markdown，得到整理成品；用户明确选择隐私独立处理或主模型直接读取。番茄钟由代码计时，专注时安静陪伴，休息时交流与交付。

共同经历：对话、作品、照片和来源可追溯的记忆留在本机；用户可以翻旧页、引用当时的片段，并导出或恢复自己的私人存档。

### 运行与获取

平台：Windows x64 桌面应用。需要用户自行配置模型服务；校园助手另依赖本机已配置的 Student Hub 后端。安装器、插件和版本验收回执通过仓库 Release 提供。

代码仓库：https://github.com/3067997259-design/love-college-agent

## 功能与现场演示

| 功能 | 实际行为与边界 |
| --- | --- |
| 校园助手插件 | 一个插件完成依赖检查、只读扫描、进度查询/取消、结果读取与候选卡导入；用户确认后在书页生成本地 .ics / Markdown。学校登录、课程提交和外部同步不在本次范围。 |
| 资料与隐私 | 新文件正文在获授权的回合可直接讨论，整理成品单独交付。独立隐私模式失败即停；跟随主模型表示关闭隔离，主模型可见获授权原文。 |
| 执行与工作台 | 有界工具循环、取消、失败分类、审批与回执。工作模式的读写和命令限制在书桌范围；普通聊天不能凭一个任意磁盘路径浏览整个仓库。 |
| 番茄与迷你窗 | 计划先提案再确认；进度、暂停和阶段持久化。专注时安静陪伴，迷你窗可展开；不以模型回答代替计时。 |
| 记忆、旧页与存档 | 记忆有来源及纠正关系；用户旧页与模型上下文分开。私人存档校验、恢复前备份、重启恢复；存档当前不加密，不作为公开角色包。 |
| 日常生活、日记与礼物 | 作息、外出事实由代码定；真实读写需有产物。日记是加密的角色化回顾，不当作事实来源。实时礼物受用户同意、服务配置与预算约束。 |

### 演示材料如何理解

动画短片为产品概念与叙事展示，约 207.5 秒，带中文字幕。片中的长期相处、回档与角色成长具有艺术表达成分，不作为每项能力已长期运行的证据。可操作的桌面应用、实际文件与工具回执作为功能展示。

现场可能使用预读的演示邮件、公开资料、预生成羽毛笔、预先准备的旧页或存档。短番茄、加速时钟、合成服务与真实服务分别标注。未配置的真实 TTS/OCR 质量、多学校即插即用、任意系统目录操作和长期开放式自主生活，不列为本次已完成承诺。

## 原创与来源声明

### 独立实现与开发时间

本作品以独立工程实现桌面应用、主进程、执行框架、日志投影、书本界面、校园确认链与存档恢复。仓库 pre-event 标签的根目录仅含 README、AGENTS、CLAUDE、.gitignore 和 docs；赛前为设计、研究与计划文档。应用开发及本次采用的生成画面、视频合成在赛中完成，具体范围以 Git 与素材生成记录为准。

赛前无关题材的工具练习没有作为应用代码或正式素材直接搬入。对开源项目的参考、已有原创项目的外部接入和第三方资源，以下单独披露，不把参考工程整套组装成参赛作品。

### 赛前已有项目与参考机制

Student Hub 是作者赛前已有的校园助手项目。本作品新增插件适配其读取能力，后端独立安装，不将后端、登录状态或个人数据库打进安装包。AIRI 及作者 fork、Neko 的 DevLog 提供记忆和体验机制参考；deepseek-harness 提供回合、步骤、收件箱和插件装配思路。LCA 的工程、界面和业务链独立实现。

角色设定参考作者为 AIRI fork 编写的原创角色卡；原卡含私人信息，不公开。视觉与体验借鉴仅限抽象风格和叙事思路，不复制参考产品的具体角色素材。历史 Minecraft/mcpfabric 联动已撤出本次演示。

### AI 辅助与素材制作

团队使用 Codex、Claude、OpenCode 等 AI 编码工具辅助实现、审计与文档工作；图像使用 NovelAI 与 GPT-image，视频包含通过 CompShare 调用 MiniMax H3 生成的片段，并进行人工选择、合成、字幕和修整。不将 AI 辅助内容宣称为纯手工作品。产品方向、取舍、素材采用与最终提交由团队负责。
