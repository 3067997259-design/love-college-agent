## 0. 结论摘要

1. **文案的核心问题不是“不够可爱”，而是三种腔调混进了产品**：工程腔（主进程、UID、fake、allowTools）、法务腔（“不表示”“不能据此判断”“没有审核过”）、以及新手指引里的**惊悚叙事**（“她醒了”“她注意到你了”“这间屋子，是你画的吧”）。第三种最伤体验，必须整段重写。
2. **设置页不是设置页**：正常模式是十余个折叠组，开发者模式直接把近二十个业务／调试组件平铺；邮箱扫描、排番茄、提议出门、抽取记忆、写日记等日常动作都挤在设置里。缺少独立的「开发与调试」板块。
3. **Minecraft 的问题不是“多了一个设置”，而是缺少统一的扩展入口**。插件中心只做三件事：列出已安装插件、开关、添加插件。Student Hub、mcpfabric、自定义 MCP、本地插件都走同一个“已安装插件”列表；没装的不出现，行标题只写插件名，技术参数点开行才看。
4. **Provider 只有“导入 JSON 文件”一条路**：`models.configure` 打开原生文件选择框，没有 GUI、没有测试连接、没有按用途选模型。新手指引第 2 步还有一个实际阻塞：导入配置后 `configuredSlots` 不更新，按钮仍然不可点（`src/main/config/model-settings.ts:13,28` 与 `src/renderer/src/onboarding/OnboardingPage.tsx:82`）。
5. **技术上可以实施，但不建议在 16:00 冻结前把全部改造塞进提交包**。文案与低风险交互可先做；设置页／插件中心／Provider GUI 需要新的主进程写入口、测试迁移和完整回归，属于冻结后的下一版。具体分级见 §9。

### 1.2 新手指引：八步流程本身可改文案，模型步有真实阻塞

- 流程：`cover → name → model → call → persona → alive → coloring → greet`（`OnboardingPage.tsx:15-21`）。名字／称呼通过 `onboarding.profile` 保存，完成通过 `onboarding.complete`；步骤本身是渲染层本地状态。
- **模型步阻塞：** `createModelSettings` 初始化时把启动时已有的槽位写进 `configuredSlots`（`model-settings.ts:13`）；导入配置后只改 `status/restartRequired`（`:28`），不更新 `configuredSlots`。因此新用户导入成功后，`OnboardingPage.tsx:82` 的“接好了”仍然 `disabled`（因为 `configuredSlots.length === 0`），只能点“先跳过”。这是一个可以直接修的主进程视图问题：保存成功后把新文件的槽位名（只名字，不含 URL／密钥）并入 `configuredSlots`，并保留 `restartRequired`。
- **重启问题：** 模型客户端在启动时装配（`src/main/index.ts:530-546`），当前没有热重载。保存配置后必须重启才生效；新手指引没有步骤持久化，重启会回到 `cover`。因此完整 GUI 放进新手指引前，需要二选一：
  1. 保持“填写连接（保存）→ 提示重启 → 可先跳过，进书后在设置里完成”，不承诺无缝；
  2. 增加 `onboarding.step` 持久化，重启后回到模型步（需要日志／投影／存档与测试改动）。
  建议先做 1；2 作为后续。

### 1.3 设置页：双入口、双形态，测试依赖真实存在

  - 设置容器 `data-settings="user"`／`data-settings="developer"`；

  - 现有组名或一次性更新 `openSettingsGroup` 与 3–5 个脚本。

### 1.4 插件中心：展示够用，添加与安装需要新 IPC

- `snapshot.runtime.plugins` 已有 `PluginView`（名称、版本、来源、状态、工具、隐私、权限、指纹，`state.ts:79-92`）。
- `snapshot.mcp.servers` 已有 `McpServerView`（传输、状态、来源、指纹、隐私、工具，`state.ts:316-327`）。
- `snapshot.minecraft` 已有玩家、范围、动作数、特性、停止核实（`state.ts:704-722`）。
- `snapshot.mailbox`／`documents`／`capabilities` 足以显示本机校园能力的“已连接／待配置／来源受阻”。
- **mcpfabric 是外部插件：** `D:\mcpfabric` 是 MIT 的 Fabric mod + MCP server（`mcp-server/dist/index.js`，游戏内 bridge `127.0.0.1:25599`）；本应用只通过标准 `mcpServers` 配置接入，不复制、不内置它的代码。`snapshot.minecraft` 是主进程的编排／安全层，不是插件本身。
- **结论：** 插件中心的“已安装列表 + 行内开关/配置”可以纯渲染层完成；连接／启停／开始轮次仍复用现有 `mcp.configure`／`mcp.connect` 等命令。**MC 是安装后出现的 `mcpfabric` 行，不是内置项**；没装就不显示，不用“未安装”占位，也不能用合成 fixture 冒充插件已装。真正的“粘贴 MCP 配置 / 安装本地目录”需要新增主进程 IPC；“在线包名/GitHub 安装”不在本轮范围，不假装支持。
- **模式门禁：** `MinecraftControls` 在正常模式返回 `null`（`MinecraftControls.tsx:7`）；当前正常用户看不到 MC。插件中心应如实标“展位／开发模式可用”，不要为了统一入口悄悄放开游戏控制。

### 1.5 Provider GUI：需要新的写入口，不能只改界面

现状：
- 唯一命令是 `models.configure`（`commands.ts:66`），主进程弹原生文件框，校验后写 `connections/providers.json`（`model-settings.ts:20-28`）。
- 快照只含槽位名、状态、重启标记，不含 URL／模型名／密钥（`state.ts:359-364`；`shared/README.md:79`）。
- 供应商文件还包含 `mail`、`tts`、`rodin` 等条目（`model-settings.ts:9-11`、`voice/port.ts:5`、`gifts/rodin-api.ts:9-13`）。GUI 写一个槽位时必须**合并保留**其他条目，不能整文件覆盖。
- 没有“测试连接”的服务级接口；只有 CLI 探针 `probeModel`（`validation/model.ts:6-17`），且只测 `chat`、返回内部 reason。

因此 Provider GUI 至少需要：
1. 新的白名单命令（示意）：`models.provider.save`（槽位、base URL、model、可选新密钥）、`models.provider.remove`、`models.probe`（只测已保存配置）。
2. 主进程原子写：读旧文件 → 只合并目标槽位 → 用现有 strict schema 校验全文件 → 0600 临时文件 + rename；拒绝符号链接／非普通文件／超过 256 KB；错误只返回闭集码，不带 URL、密钥或供应商原文。
3. 密钥不回流：快照永远不返回已保存密钥；编辑时显示“已保存，留空不修改”，只有用户输入新值时覆盖。
4. 探针：固定合成提示、`maxOutputTokens` 很小、超时有界、无工具、无用户数据；结果只返回 `ok`／闭集失败码；按资源账本预留一次极小请求，不绕过预算。TTS 用固定短句；Rodin 不做免费探针，保存后由首次真实生成验证。
5. 重启语义：保存后仍显示“已保存，重启后生效”，提供“重启应用”；不要宣称热生效。新手指引按 §1.2 处理。

**结论：** GUI 本身是表单，难的是主进程写入口与探针的安全边界；这部分可以做，但必须单独提交接口、单独回归，不能和视觉改版混在一个大提交里。

## 2. 新手指引文案重写（V2 终稿）

### 2.1 设计原则

- **去惊悚**：不再用“她醒了”“她注意到你了”“这间屋子，是你画的吧”这种“画中人突然回头”的第四面墙桥段。新叙事是“书房已经在那，你添上自己的痕迹，她走过来打招呼”。
- **去散文腔**：每步只做一件事，标题短，正文不超过两行；不解释主进程、不解释存档结构。
- **动作名稳定**：保留 `翻开`、`写好了`、`先跳过，稍后在设置里配`、`就叫这个`、`好`、`剩下的交给她`、`开始吧`、`我已经有一本书了`、`从这本书恢复`，避免 `smoke-onboarding` 大改。
- **状态短句**：连接成功统一用“已经连接”；不再写“还没有试过连接”“连接很稳，随时可以开口了”。

### 3.1 形态与入口

- **形态：** 书页内的设置跨页／右页视图，左侧分类导航，右侧内容区；同一张纸、同一套墨色和手写标题。不再用右下角 560px 悬浮面板，也不在设置里放“开始专注／扫描邮箱／提议出门”这类日常按钮。

## 4. 插件中心：一个列表 + 一个导入框

### 4.1 先纠正上一版的设计

上一版把插件中心写成了“卡片市场 + 来源标签 + 详情抽屉 + 未安装状态”，这是过度设计，也是 AI 味的来源。用户给出的参考很清楚：**插件市场只做三件事——列出已安装的插件、开关、添加插件。** 没装的插件不出现；不要出现 `MCPfabric · 未安装`、`外部插件 · MCP` 这类状态串；不要为了说明来源而在每行堆标签。

现状的割裂仍然存在：

- 本机校园能力（邮箱／资料）在 `UserSettings` 的“邮箱与资料”组（`UserSettings.tsx:43`）；外部 Student Hub 只是 MCP server，混在“工具连接”里。
- Minecraft 是外部插件 mcpfabric，却只在展位分组（`UserSettings.tsx:49`）或开发者平铺面板（`ToolsPanel.tsx:56`）出现，且是一整块半径／秒数／勾选框表单（`MinecraftControls.tsx:11-27`）。
- MCP 在“工具连接与提醒”组里以裸列表出现（`McpControls.tsx:12-24`），用户要读 `stdio`、`allowTools`、指纹。
- 本地插件在“本地扩展”组里另起一套卡片（`UserSettings.tsx:52-57`）。
- 正常模式没有礼物生成入口（`UserSettings` 不导入 `GiftControls`）。

但解决方式不是再加一层市场 UI，而是把入口收成一个列表。

**设计禁令：** 不写“未安装”占位；不做卡片网格；不做来源大标签；不做大详情页；不把 `stdio`／`allowTools`／指纹／端口放在首页。插件市场只回答“装了什么、开没开、怎么再加一个”。

### 4.2 页面结构（结构参考截图，画风跟书）

- **入口：** 第一版只做书页第 6 枚书签「插件」；输入框左侧小拼图图标与设置第 2 板块直达留到后续，不为了入口再加一套页面。
- **页头：** 左侧手写标题「插件」，下面一句“安装、启用和配置插件”；右侧一个刷新图标 + 一个 `+ 添加插件` 按钮。不要筛选胶囊、不要分类 tab、不要搜索框。
- **分组，只有两组：**
  - `内置插件配置`：真正内置、可配置的工具，例如「网页读取」「书桌预览」；一行一个，右侧开关或“配置”。
  - `已安装插件`：mcpfabric、Student Hub、本地插件、自定义 MCP。一行一个，右侧开关。
- **行：** 左侧手绘小图标（线稿 + 一点桃色），中间插件名 + 一句话说明，右侧开关。名字用插件自己的名字（如 `mcpfabric`、`Student Hub`、manifest 里的 `name`），说明用中文一句话；不把来源、传输方式、状态码写进标题。
- **展开：** 点行本身才展开少量配置（连接、核对玩家、工具白名单、隐私），不再跳“详情页”。技术字段收在展开区最下面，默认不显示。
- **空状态：** 手写一句“还没有安装插件。点右上角「添加插件」。”不要放四张空卡片。
- **视觉：** 纸色底、铅笔虚线分隔、手写标题、线描图标；开关是桃色/铅笔灰的小拨片。参考截图的层级，不照搬深色背景和发光图标。

```text
插件                                            ↻   [+ 添加插件]
安装、启用和配置插件

内置插件配置
  [线稿地球]  网页读取        公开网页，每次地址单独批准        [开关]
  [线稿画框]  书桌预览        隔离沙箱里的静态页面              [开关]

已安装插件
  [线稿方块]  mcpfabric       Minecraft 陪玩                   [开关]
  [线稿学士帽] Student Hub     校园邮箱、日程与资料              [开关]
  [线稿拼图]  我的本地插件     一句话说明                        [开关]
```

行不写“外部插件 · MCP”“未安装”；点行才展开连接与安全配置。

### 4.3 添加插件：一个导入框

- 对话框标题「添加插件」；一句说明：“输入本地插件目录，或 MCP 配置文件路径。”
- **只有一个输入框**，占位示例：`D:\mcpfabric`、`D:\mcpfabric\examples\mcp.json`。不粘贴原始 JSON；路径由主进程读取，凭据不经过渲染层。
- 下方一个浅桃色提示条，不写大段免责声明：“插件在本机以你的权限运行。只安装你信任的来源；MCP 服务器连接前还会核对启动目标和指纹。”
- 主按钮「安装」，次按钮「取消」。
- 输入判定：
  - 存在的本地目录 → 读取 `manifest.json`，作为本地插件安装；新增 `plugin.install` 主进程 IPC，校验、复制到数据根并立即发现；代码插件仍要指纹确认。
  - 存在的本地 `.json` 文件且含 `mcpServers` → 通过新增的 `mcp.configure.path` 导入；内容只在主进程读，渲染层只传路径。
  - 其他包名／GitHub 地址：v1 **不假装支持在线安装**；提示“暂不支持在线安装，请选择本地目录或 MCP 配置文件”。如果以后做 registry，再在这个框里扩展，不另开一套 UI。
- 安装成功后，插件直接出现在「已安装插件」列表；**不出现“未安装”占位**。如果连接失败，只在行下显示一行小字 + “！”，不把整行变成错误卡。
- mcpfabric：用户在游戏侧装好 Fabric mod + MCP server 后，在 LCA 里选择本地 `mcpServers` JSON 路径；列表出现 `mcpfabric`，说明“Minecraft 陪玩”，开关默认关；点行展开后核对玩家、范围、聊天／截图／挖掘。
- Student Hub：同样通过 MCP 配置进入列表，名字 `Student Hub`，说明“校园邮箱、日程与资料”；本机邮箱／资料整理仍在内置能力里，不混成一张卡。

### 4.4 mcpfabric 安装与验收清单（P2 必须）

用户已明确：改动结束后要实际安装 `D:\mcpfabric` 测试。这里把“装插件”拆成可核对的事实，避免把合成 fixture 当成实机通过：

1. **游戏侧：** 把对应 Minecraft 版本的 `mcpfabric-<version>+<mc>.jar` 与 Fabric API 放进游戏 `mods/`；启动游戏，确认 bridge 在 `127.0.0.1:25599`。本机 `D:\mcpfabric\mcp-server\dist\index.js` 已存在（2026-10-15 构建），`node_modules` 也在；若重装或改源码，按 `mcp-server` 的 `npm ci && npm run build` 重新生成。
2. **凭据：** token 在游戏的 `config/mcpfabric.config.json`；只在本机填入 MCP 配置的 `MCPFABRIC_TOKEN`，不打印、不提交、不发给 renderer／调试接口。
3. **LCA 侧：** 在「添加插件」里选择本地 `mcpServers` JSON 文件（`type: stdio`，`command: node`，`args: ["D:/mcpfabric/mcp-server/dist/index.js"]`；JSON 里用正斜杠可省去反斜杠转义，`env` 含 `MCPFABRIC_URL`／`MCPFABRIC_TOKEN`）；核对 fingerprint 与启动目标后再连接；`allowTools` 只放本轮需要的游戏工具。**mcpfabric 这个 server 必须设 `privacy: "none"`**：结构化游戏协议和截图只在公开结果下可用；不要把它和含隐私的校园工具混在同一个 server 里。
4. **应用内：** 「已安装插件」列表出现 `mcpfabric` + “Minecraft 陪玩” + 开关；点行展开后核对实际玩家 UUID、范围、时长与聊天／截图／挖掘选项；开始一轮，再验证停止释放（`stopVerified`）。不要写“MCPfabric · 未安装”这类状态串。
5. **隔离：** 游戏日志／上下文独立；不把个人聊天、邮件、资料、心流原文带进游戏；结束只给普通上下文代码生成的尝试／观察／释放摘要。
6. **记录：** 合成 `pnpm test:minecraft*` 通过不等于插件安装通过；实机结果单独写进验收记录，明确“真实双客户端／单客户端”“真实模型或 fake”“是否实际拾取／完成目标”。

### 4.5 文案与测试

- 行标题只放插件名；说明用一句话中文；`stdio`、`allowTools`、指纹、端口等只在点开后的配置区出现。
- 已安装列表来自 `snapshot.runtime.plugins`（本地插件）与 `snapshot.mcp.servers`（MCP）；没装的来源不显示。连接失败在行下用一行小字 + “！”，不新增整块错误卡。
- 保留 `aria-label="Minecraft 展位控制"`、`.mcp-server[data-id]`、`MCP 连接确认`、`确认此配置并连接` 等测试钩子；新增行用 `.plugin-row[data-plugin-id]` 方便迁移。
- 开发者／展位模式下，已安装的 mcpfabric 行默认展开，让 `smoke-minecraft`、`smoke-campus` 仍能在打开设置后找到控件；正常模式下默认只显示列表，不渲染扫描／游戏控件（`smoke-settings.mjs:21-22` 可继续通过）。

## 5. Provider GUI：独立配置页

### 5.1 目标与边界

- 目标：新手不碰 JSON，也能填地址、密钥、模型并当场知道“已经连接”；熟练用户仍可 `导入 JSON`。
- 边界：密钥只在主进程；界面不回显已保存密钥；不把供应商响应正文、URL、模型名写进日志或错误详情；保存后需要重启才生效（现状如此，不假装热更新）。

### 5.2 页面结构

Provider 是设置六个板块中的第 1 个，但它是**独立子页**：有自己的标题、表单、测试与保存，不是折叠组里的两个输入框。第一版先按“日常对话／记忆与日记／隐私滤芯”三个用途槽位做；服务商模板列表是后续增强（见 §13）。

```text
设置 / 模型与声音

[服务商]
  (•) DeepSeek        已经连接
  ( ) OpenAI          未配置
  ( ) 本地 Ollama     未配置
  [+ 添加服务商]

  接口地址   https://api.deepseek.com/v1        （预填，可改）
  API 密钥   ••••••••••••••                    （已保存，留空不修改）
  模型       deepseek-chat                      （下拉／手填）

  [保存]  [测试连接]     状态：已经连接

[用途分工]
  日常对话       DeepSeek · deepseek-chat
  记忆与日记     跟随主模型
  隐私滤芯       未启用
  语音           未配置
  3D 礼物        未配置

  [保存并重启应用]     已保存，重启后生效
```

- **预设模板**：DeepSeek、OpenAI、SiliconFlow、阿里百炼、火山豆包、Moonshot、本地 Ollama、自定义兼容接口。模板只预填地址和常见模型名，仍以“测试连接”结果为准；不宣称每家都完整兼容。
- **状态文案**：成功就是 `已经连接`；失败用闭集原因（密钥无效／地址连不上／服务繁忙／额度不足），不显示供应商原文。
- **用途分工**：五个下拉，默认“跟随主模型”；隐私滤芯选“未启用”时说明“含隐私的原文只暂存，不外发”。
- **保存与重启**：保存后按钮变“已保存，重启后生效”，旁边提供“重启应用”。不要写“立即生效”。

### 5.3 主进程契约（实现时必须遵守）

1. `models.provider.save`：只接受白名单槽位；`apiKey` 可省略表示保留旧值；`baseUrl` 只允许 http／https，拒绝 userinfo／query／hash；模型名长度有界。
2. `models.provider.remove`：只删目标槽位，保留 `mail`、`tts`、`rodin` 与其他槽位。
3. `models.probe`：只测已保存配置；固定合成提示；无工具；超时有界；结果闭集；按资源账本预留；不把响应正文返回渲染层。
4. 文件写：读旧文件 → 合并 → strict schema 校验 → `connections/providers.json.tmp`（0600）→ rename；拒绝符号链接／非普通文件／超过 256 KB；失败保留旧文件。
5. 快照：`ModelSettingsView` 只增加 `configuredSlots`、`status`、`restartRequired`、闭集 `error`，不增加 URL／模型名／密钥。
6. 测试：`smoke-settings` 增加 GUI 保存／非法地址拒绝／密钥不回流；`smoke-model-slots` 保留 JSON 导入；新增合成 HTTP 探针成功／失败；确认重启后槽位生效。

### 5.4 与新手引导的衔接

- 新手第 2 步先给两个入口：`填写模型连接`（GUI）与 `选择模型配置文件`（旧路径）；测试成功显示 `已经连接`。
- 如果 GUI 保存后需要重启：显示“已保存，重启后生效”，并允许“先跳过，进书后在设置里完成”。不要在新手流程里假装已经可用。
- 若要真正无缝，需做 §1.2 的步骤持久化或热重载；那是另一个工作量，不在本轮承诺。

## 17. Student Hub 作为 MCP 插件包（2026-10-18）

用户指出不应为 Student Hub 单独写适配层。这里按插件和 MCP 加载器的既有边界处理：

## 18. Student Hub 候选插件与通用候选出口（2026-10-18）

用户要的效果是：从 Student Hub 改出一个新插件，装给桃子后直接形成 LCA 候选卡。这里没有把 Student Hub 的 MCP 工具面扩成写接口，也没有在 LCA 里写 Student Hub 专用分支；新增的是一个本地代码插件和一个通用的宿主候选出口。

**宿主出口：**

- `PluginActivationContext.ingestCandidates(seeds)` 和插件工具结果的 `candidates` 字段只接受有界种子：外部 id、标题、截止／活动时间、来源标签和一段用户可见证据摘录。
- 插件启用时可以调用 `ingestCandidates`；工具调用返回的候选由 registry 转交宿主后立即剥离，不进入模型 projection、普通工具日志或调试状态。
- `campus.ingestCandidates` 复用现有候选投影、版本和证据库；同一外部事项内容不变时幂等，不重复追加 revision；改期时沿用同一候选 id。
- 候选摘录只写入主进程私有证据库；候选卡默认仍未确认，确认／忽略、导出和证据读取沿用现有流程。
- 只有 `privacy: none` 或已声明自行处理隐私的插件能保留这条出口；带隐私滤芯的插件候选不会绕过滤芯。

**Student Hub 插件：**

- 包在 `plugin-packages/student-hub-candidates`，是本地代码插件，不是 MCP server，也不是 Student Hub 的适配层。
- `read-items.py` 以 SQLite `mode=ro` 和 `PRAGMA query_only=ON` 只读 Student Hub 数据库；默认根目录 `D:\student-hub`，可用 `LCA_STUDENT_HUB_ROOT`／`LCA_STUDENT_HUB_DB`／`LCA_STUDENT_HUB_PYTHON` 覆盖。入口在每次执行前校验辅助脚本的 SHA-256，避免辅助脚本绕过插件指纹。
- 只导入 `needs_review`、`confirmed`、`synced` 且带截止时间或活动开始时间的事项；没有日期的公告、已忽略、已取代和已完成不生成卡片。
- 映射标题、课程／来源、截止／活动时间和原文预览；Student Hub 加密后的 `shenc:` 信封不会当成主题显示。候选证据是 Student Hub 已保存的摘要／预览，不重新抓取邮件正文。
- 启用时自动导入一次；工具 `import_student_hub_candidates` 可刷新。不扫描邮箱、不读取密码、不写 Student Hub、不写日历／Todoist。

**验证：**

- `pnpm typecheck`、`pnpm test`：76 个文件／543 项通过。
- `pnpm test:plugins`：本地插件安装、指纹确认、技能分栏、MCP 路径导入和连接确认仍通过。
- `pnpm test:student-hub-candidates`：真实 Electron，合成 Student Hub SQLite；安装、启用、自动导入、候选卡渲染、看原文、快照不含摘录、重启后不重复导入全部通过。
- 手工用本机 Student Hub 只读库跑插件映射，返回 3 条当前带日期事项（只计数量，没有把正文写入记录）。这不等同于在用户正式 profile 中安装验收。

**边界：** 插件目前从 Student Hub 的**事项**（item）映射，不读取未审核 artifact 的启发式日期；`needs_review` 为 0 时不会凭空造卡。Student Hub 已确认的事项在 LCA 仍作为待确认候选出现，避免把外部确认当成 LCA 确认。真实个人 profile 的安装、真实模型切换和跨重启卡片仍需用户实际操作验收；未重打包。
