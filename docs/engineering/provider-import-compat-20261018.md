# 旧 providers 配置导入兼容性修复

2026-10-18 14:18。用户在 v0.1.8 导入本机原有 `providers.json`，界面返回 `configuration-failed`。此前只核实文件存在，未验证它能通过 GUI 导入；这不足以指导用户直接使用。

## 原因

启动读取器接受附加字段并只取已知连接字段；GUI 导入器使用严格 schema，拒绝根级、模型槽位、Rodin 和邮箱中的附加字段。同一文件因读取入口不同而表现不同。本轮由独立 Electron 主进程检查，错误均为 `unrecognized_keys`，文件不是符号链接、硬链接数为 1；没有在助手上下文、终端或诊断中输出任何配置值。

## 现场可用处理

- 原文件保持不变。主进程生成私密兼容副本 `D:\lca-demo-private-20261018\providers-demo.json`，目录权限限定当前用户和 SYSTEM；不加入仓库、Release 或公开操作卡包。
- 副本只保留现有连接字段，模型、邮箱和 Rodin 的值保持不变。按用户已确认的演示选择，将记忆/日记与隐私设为 `follow-main`；后者表示关闭隔离、主模型可处理新原文。
- 使用实际安装的 v0.1.8、新的隔离数据目录，通过应用 `models.configure` 入口导入该副本，结果 `saved`；识别五个模型槽位、邮箱及 Rodin，TTS 未配置。没有发起连接测试、模型、语音、礼物或邮箱请求。
- 用户当前 v0.1.8 直接导入此副本即可。导入后测试日常对话，并按界面提示重启以启用邮箱/Rodin。

- 导入及读取现有配置先取已知字段再严格校验，兼容附加说明和 UTF-8 BOM。写出的内部配置仍为规范格式。
