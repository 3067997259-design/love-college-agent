# 第一圈：附件、拖入文件与 /privacy

2026-10-16，约 20:40（GMT+8）。按用户要求，用合成文件与显式 fake 隐私依赖贯通资料处理。真实 IMAP 继续记认证前 ECONNRESET 阻塞，本批没有重试、读取真实邮件／配置或调用真实模型。资料原文与整理成品均只供用户；模型只拿通用文件名、类型、页数和校验过的截止时间。

## 操作与范围

在自己的 worktree 用 `pnpm dev` 启动，在“工具与设置”打开开发模式并重启。

1. 将 `.pdf`、`.txt` 或 `.md` 拖入窗口，或点击右页“选择资料”。一次最多 5 份，文件会复制到当前 profile 的主进程私有源库。界面使用代码生成的通用文件名；源路径和原文件名不会进入公共状态。
2. 附件入口：扫描“初始”合成邮箱，设置页会出现一份合成 PDF 的元数据，点击“整理附件”。滤芯关闭时仅登记待处理任务，尚未下载／解析附件正文。现有场景中的附件是程序生成的英文作业要求 PDF，用于验证真实文字层解析，非队友尚待发送的中文演示附件。
3. 输入 `/privacy` 切换，`/privacy on`／`/privacy off` 显式设定，也可在设置页切换。它由本地控制器处理，不作为聊天请求发给模型。开关在当前 profile 的 `settings.json` 持久化，不进入存档日志；重启保持，切换开发场景仍使用各自设置。
4. 开启且隔离依赖可用后处理暂存任务，成功产生实际 Markdown 文件，在右页交付卡“打开”。预览只给用户，不向模型回传内容。
5. 在设置页的“资料滤芯场景”切到“滤芯失败”或“非法输出”，再交新文件，应看到失败任务且没有成功交付；切回可用后需要显式“重试”。可取消未完成任务。

**当前路线**：本批只接隔离整理。关闭 `/privacy` 时只暂存；公开资料跟随主模型整理、用户主动让主模型阅读成品的路线均未实现，不能将暂存解释成已整理。正常模式缺少可用隐私依赖时拒绝开启；若设置仍保留开启但依赖缺失，任务明确失败，开关不会悄悄复位。

支持带文字层的 PDF、UTF-8 文本／Markdown。单文件最多 10 MiB、抽取文本最多 120000 字符；PDF 最多 60 页，解析 15 秒超时，隔离模型 30 秒超时，单任务总计 90 秒；队列最多 20 份待处理，当前资料列表最多 200 份。无文字层扫描件、损坏／加密或无法提取文字的 PDF、非法编码、其他格式和超限文件明确失败；本批不做 OCR、DOCX 或图片整理。

fake 滤芯仅对抽取文本做确定性开发排版并标记合成数据，不代表真实模型的语义整理质量。设置页提示小型隐私模型可能影响整理质量；正式学校隐私客户端与连通验证仍待后续。

## 实现边界

| 数据／动作 | 实现与出口 |
| --- | --- |
| 用户拖入／选择 | 真实 preload 的 `importFiles(File[], epoch)`；`webUtils.getPathForFile` 在 preload 解析原生 File 后直接交主进程，不把路径返回页面；JS 伪造的无磁盘 File 拒绝 |
| 输入校验 | 主进程拒绝任意路径公共命令；只接信任的应用主 frame 的专用 IPC，校验 epoch、数量、扩展名、常规文件、大小和读取前后身份／修改状态；不接 URL、UNC 或符号链接文件 |
| 原始文件 | `documents.sqlite` 的私有 BLOB 表，按用户／角色＋内容哈希标识；原文不进入 JSONL、快照、工具结果或 MCP；校验哈希后读取 |
| 附件 | 只读源暴露 `readAttachment`；扫描先登记固定 UID／partId 的安全元数据，用户选择后进入同一个任务队列。合成源返回固定 PDF；真实 blocked 源无读取实现 |
| 文字解析 | UTF-8 严格解码；PDF 由独立解析子进程执行现有 pdf-parse 2.4.5，结果只回主进程；禁用 eval／字体远程工作读取，不渲染或执行附件内容 |
| 隐私整理 | 固定格式凭据等先由代码打码，再交独立、无工具的 `DocumentPrivacyModel`；缺失、超时、失败、非法 schema 一律停止；没有调用主模型的备用路径 |
| 窄出口 | 长 Markdown 与证据引文留在主进程；截止时间必须逐字有据且由代码解析绝对日期复核。页数来自解析器，文件名由代码生成，模型输出额外指令字段被拒绝 |
| 成品交付 | 复用已有不可变 artifacts、哈希校验和无 preload／Node／桥的用户预览；只有成功落盘后追加完成事件和交付卡，不把正文写进事件 |
| 调度／持久化 | `document/job`／`document/attachment`／`document/completed` 是 append-only 元数据；重放投影，处理中的崩溃任务记 interrupted，需要重试；正常退出会停止在途处理 |
| 模型可见 | 仅冻结的 `document` 事件和 `get_processed_files` 工具的元数据；没有读取原文／成品、确认日程或开放文件系统的工具 |

关闭滤芯、熄灯或停用资料插件会中止在途任务、暂停队列，不产生迟到的成功交付。明确取消保留 cancelled，重试是新 attempt；相同输入再次导入不重复建任务。处理失败不自动转主模型，不自动重试；断电未完成的任务不推断为已成功。邮件正文的隐私锁独立于文件开关，`/privacy off` 不会解除邮箱正文隔离。

PDF 解析最初在 Electron 的 Node worker 线程中尝试：同一合成 PDF 在普通 Node 可解析，但 Electron 进程以 `3221225477` 原生异常退出，无安全报告；尚未定位具体依赖。随后改为独立子进程，已通过 Electron 验证。子进程复用 Electron 自带的 Node 模式，JS 堆上限 192 MiB，只继承 SystemRoot／TEMP／TMP，关闭标准输出转发，按超时／取消或结束终止；它是故障隔离，不是 Windows 权限沙箱。没有因此添加依赖或安装额外运行时。

API 用法依据当前安装版本源码／类型及官方文档：[Electron webUtils](https://www.electronjs.org/docs/latest/api/web-utils)、[pdf-parse](https://github.com/mehmet-kozan/pdf-parse)。合成 PDF 由本工程独立生成；未读取或复制参考项目数据、模块、凭据或美术。
