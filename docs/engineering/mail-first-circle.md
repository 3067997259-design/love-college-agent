# 第一圈：合成邮箱到本地交付

2026-10-16，约 20:10（GMT+8）。按用户要求先贯通“证据 → 候选 → 确认 → 交付”。IMAP 继续记阻塞；本批没有连接真实邮箱、读取真实配置或消费真实模型额度。合成数据只用于开发与测试，不能宣称真实邮件或学校隐私模型已接通。第一圈的资料处理、记忆和私人存档等仍未完成。

## 使用入口

后续更新：附件、拖入文件与 `/privacy` 已在独立开发 profile 接通合成流程，见 [资料处理记录](documents-first-circle.md)。下文的“附件未处理”是邮箱首批验收时的边界；真实 IMAP 和学校隐私模型仍未接通。

在自己的 worktree 运行 `pnpm dev`，打开“工具与设置”，启用开发者模式并重启。开发数据在 `<数据根>/developer/<sceneId>/`，不会混入正常 profile，chat 与邮件隐私依赖都是显式 fake，不加载真实 providers。

1. “工具与设置” → 邮箱，选择“初始：作业、活动与无待办馆讯”，点击“扫描合成邮件”。3 封初始邮件产生 2 张候选；馆讯只记处理进度，不生成事项。
2. 关闭设置，右页“看原文”查看用户专用摘录及高亮。可填写上海时区的计划完成时间，再确认。原始截止时间单独保存。
3. 回到设置，点击“导出新确认事项”。每个新确认版本生成一份 .ics 与一份 Markdown，交付卡“打开”显示已校验的实际文件字节。这里只生成本地文件，尚未写入任何外部日历。
4. 选择“新增截止时间变更”并扫描。作业变为 changed：同时提供旧、新证据，旧安排在重新确认前继续有效。忽略变更也保留旧安排；旧 revision 的确认会被拒绝。重新确认并导出后，沿用同一 UID，SEQUENCE 从 0 到 1。
5. “隐私模型不可用”与“恶意输出拒绝”用于故障演练。应看到明确失败，既不产生新候选，也不把失败解释成空邮箱。“空邮箱”只表示本次来源没有未读输入，已有事项不会删除。

数据是 [演示邮件脚本](../demo-emails.md) 的合成副本，包括虚构姓名、地址与凭据标记，不读取参考项目数据。首封带附件的脚本只作为邮件内容，本批尚未下载或处理附件。

## 数据所有者与边界

| 数据 | 所有者／出口 |
| --- | --- |
| 原始邮件、发件人、逐字证据 | 主进程 `mail/evidence-vault.ts`，`campus.sqlite` 的私有证据表；按用户／角色作用域和内容哈希验证；不进 JSONL |
| 用户原文查阅 | 独立 `readEvidence(opaqueRef)`；最多 8000 字符摘录，UTF-16 半开区间高亮；固定格式的密钥等仍打码；没有模型工具或调试读取入口 |
| 隐私模型输入 | 固定格式先代码脱敏，再交无工具的独立依赖；本批仅 fake；缺失、超时、错误和非法输出均关闭，不回退主模型 |
| 候选、进度、确认、导出事实 | append-only 日志；候选、邮箱视图及 SQLite 缓存由日志重放；扫描未确认、未导出 |
| 模型上下文与工具结果 | 校验过的枚举、时间和短字段，带 untrusted／fake 标记；无证据正文、quotes、发件地址或原始主题 |
| 交付文件 | `<当前 profile>/artifacts/<hash>.ics`／`.md`；日志只存安全卡片、相对路径和文件哈希；渲染进程只用 artifactId |

滤芯输出使用严格 schema，不接受多余字段。任务、地点须来自逐字引文；日期由代码按发信日和上海时区重新计算并与模型值比对。当前支持明确本地年月日／时分、“下周三中午前”一类下个自然周表达及同日活动时段。不支持的语言、带显式时区的时间、多日期歧义和不存在的日期拒绝，不能猜成有效截止时间。正式隐私客户端与更广日期语言留待后续；用户计划时间不参与原始证据校验。

邮箱源接口只提供 `readUnseen`，没有改已读的能力。合成源按固定 UIDVALIDITY／UID 返回，最多处理 30 封；本地处理记录防止重复建卡。正式适配器当前是零网络 IO 的 blocked 实现，不代表 IMAP ID、文件夹只读或 PEEK 已在真实服务器验收。历史认证前 ECONNRESET 与 Clash 假设见 [首批记录](first-hour.md)。

邮箱插件固定隐私锁，设置与 IPC 均不能关闭。模型工具只有 `check_mail` 和 `get_campus_items`，不提供确认、忽略、导出或原文读取。候选命令要求画面上的 `expectedRevision`，重复确认无额外副作用。工具回合取消会中止该工具发起的扫描；熄灯或插件停用会中止所有扫描。导出使用统一调度队列。

文件先持久化，再追加成功事实；失败只有失败卡，不记已导出。路径限于自有 artifacts，拒绝符号链接／junction、路径穿越、文件内容冲突和哈希不符。文件按作用域、事项、版本和格式固定命名，重复导出幂等；中断后的相同文件可安全复用。预览窗口无 preload／Node／桥接口，只展示转义后的已验证内容。

日历为 VEVENT：作业以原始截止时刻为 DTSTART，不捏造时长；活动单独使用活动开始／结束，报名截止写入说明。用户计划时间只在说明中。输出 UTC 时间、CRLF、TEXT 转义与 UTF-8 75 字节折行，依据 [RFC 5545](https://www.rfc-editor.org/rfc/rfc5545)。改期保持 UID 并递增 SEQUENCE，旧交付文件不改写。**手机日历重复导入行为未实测**，本批不宣称外部更新成功。
