# 上传资料与邮件上下文修复

2026-10-18，v0.1.9。用户在 v0.1.8 忽略三封邮件，上传文件后立即询问，回复却概括邮件。属于实际使用暴露的上下文与进度问题。

## 原因和改动

- 原文补充只从已完成整理的文件取材；文件接收后正在整理时没有正文。本轮改为从用户当时授权给主模型、且未取消的文件中提取原文，不等待另一次整理模型请求完成。当前开启隔离或历史隔离文件仍不公开。
- 邮件原文补充、读取工具、待投递事件未排除已忽略候选；现在按当前候选状态和证据版本排除。历史自动生成的邮件事件和工具返回仅在模型投影中刷新，原日志、用户聊天保留。已拒绝的改期不能作为当前原文再次注入。
- 当前模型请求带最新资料状态、是否具备正文和已忽略事项 ID。提示词明确区分上传文件、邮件和历史工具结果；没有正文时只能说明状态或限制，不能拿邮件替代。补充正文不写入 model/seen、普通日志或自动记忆。
- 上传入口从快照显示整理中、完成、失败、暂存及取消；工具实际读取校园候选元数据时，活动文字改为“查看了当前校园事项”，不再声称读过邮件正文。
- 同包包含 `daee222` 的 providers 注释字段/BOM 导入兼容修复。

## 验证

- 定向 25 项单测和类型检查通过；覆盖整理前/中可读取、取消排除、历史隔离不自动公开，已忽略邮件原文/工具/投递/模型投影排除。
- `smoke-model-routing` 正常模式 Electron + 合成 HTTP + 合成 Student Hub 库：安装候选插件、忽略三项、上传文件、刻意保持整理请求未返回，再发送“立即读这份刚上传的文件”。捕获的主模型请求已包含对应文件正文；即使调用邮件工具也只得到空列表；此时资料任务仍为 processing，之后放行整理才显示已完成。
- 同一流程覆盖隐私失败关闭、历史隔离、配置热生效、重启和原文不入普通日志。全部为合成资料，不读取用户邮件/上传文件，不代表真实模型措辞质量验收。
