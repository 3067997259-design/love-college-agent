# 有界澄清问题

2026-10-17。共享接口 `d8270ad` 已先合 main（合并 `4fde7dd`）。`ask_user` 同时供普通聊天和心流使用；游戏模型没有该工具。界面只作朴素接线，文字在独立 `voice/questions.zh.json`，角色画面仍归 Claude。

## 行为与归属

- 问题至多 240 个 Unicode 字符，最多三项各 60 字的选项；每回合三问、上海 04:00 分日每天十二问。回答至多 1000 字，可多行。拒绝控制／双向格式字符、损坏 Unicode 和已知凭据值。
- 专注／安静时只给快照 `question.status=queued` 和归属元数据，不给问题正文，也不提前写用户可见问句。休息／退出安静后显示。十分钟期限只计算可见时间；再次专注时暂停剩余期限。不通知、不展开书本、不抢焦点。
- 书本独占 `question.answer`／`question.dismiss`。回答补充信息，不能替代运行审批、候选确认、外部写入授权。迷你窗和诊断窗不能回答。
- 问句第一次显示时追加 `assistant/message(displayOnly)`，历史可回看，不重复作为模型消息，也不在回合结束后追读 TTS。回答追加普通 `user/message` 与命令幂等收据。
- `ask_user` 的工具结果只有状态和回答消息 ID。整个 assistant 工具批次全部记下结果后才 `inbox/drain` 回答，因此上游顺序是 assistant(tool_calls) → 所有 tool → user，不会把用户消息插在工具结果中间。既有世界事实可插入在批次之后。
- 停止、父回合取消、熄灯、入睡、插件关闭、新用户要求或工作作用域改变会结束旧等待。尚未提交到完整批次的回答遇到取消／异常结束会 `inbox/drop`，标为未送达；重启关闭未结束的问答，不恢复执行。已经接受的回答不会因后来一条用户消息而凭空删除，按顺序进入上下文。
- 心流问题／回答沿用工作上下文隔离及 `eligibleIndexes=[]`；离开心流后不进普通聊天、经历记忆。普通回答只有成功进入模型输入后才具备既有“她当时看到”的来源证明。问句本身保守地不因为展示而新增记忆证明。
- 日志只追加；问答记录随私人存档保存为历史，恢复不复活等待或消耗模型额度。

## 实际验证

`pnpm test:questions` 已通过：真实 Electron／SQLite、朴素选项和多行回答、专注小窗排队到休息再展开、书本权限、跳过、心流回答不串普通上下文、停止拒绝旧 ID、重启无请求重放、实际 ZIP 导出恢复仍保留历史且无等待。另用正常模式与本机合成 HTTP 服务检查实际序列化的 `tool_calls`／`tool_call_id` 配对和回答角色；不读取真实供应商文件，不调用付费服务。

类型检查、lint、64 文件／425 项全量 Vitest 通过；随后新增防止 TTS 追读展示问句的回归，语音专项 14 项通过（总用例增加到 426）。问答单测覆盖可见期限暂停、每回合／每日上限、凭据拒绝、取消／作用域／重启、完整批次提交前丢弃及命令幂等。

合成服务能证明协议和持久化行为，不能证明真实模型会在合适时机提问；这一质量项保留给连续演示。
