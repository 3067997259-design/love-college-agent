# 加密日记和她的文件夹

2026-10-17，接口 `4721803`。普通模式在“文档/桃子的房间/作用域摘要-数据根摘要”下投影书桌、日记、带回来的东西、礼物、运行记录；开发／展位在各自数据目录。目录名必须带上数据根身份，否则共用同一角色的两个普通 profile 会读写同一份房间（#8）；已解析的路径记在 profile 设置里，之后改命名公式也不会静默搬家。程序从日志重建，工具仅能接触书桌。重建是**对账式**的：程序拥有的投影（日记／礼物／运行记录／带回来的东西）里，不属于当前日志的文件会被清掉，否则恢复较早存档后房间会混入恢复之后的「未来」内容（#9）；`书桌` 与名字不在托管命名内的文件一律不删。运行记录采用事件类型、统一时间和成败的白名单，绝不序列化原始记录对象。礼物为本地 GLB，小物为带来源的目录 JSON，美术缺失可回退。

日记从 seenFragments 的实际可见片段取材，最近三天、每天一篇，不读原始工具结果、邮件、附件或交付成品。按方案走主模型 chat 槽位的独立 JSON 任务，计自主预算，不接回普通对话；无配置就关闭，失败不存正文、不推进完成，不自动重复同一天调用。手动重试和每日总尝试仍有界。fake 正文仅用于开发验收。主观文字不作事实、不进入 model/seen 或记忆，也不保存内部推理。

写入时生成不可变钥匙和下一日页 04:00的解锁时刻，正文只在主进程内短暂存在，落盘是单篇 ZipCrypto ZIP。实现参照 [PKWARE APPNOTE](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT) 的格式独立编写，未复制项目代码；沿用方案选定的弱密码 ZIP，不作为强安全密码库。钥匙固定存私人日志，随私人存档走，不进快照、调试或模型。解锁后仅书本窗口的 readDiary 用户入口返回正文／钥匙，当前用“下一页书签”朴素入口；藏在物品／礼物的艺术提示后续交 Claude。私人存档含密文资源；恢复重新投影，不改钥匙。

实际通过：typecheck、lint、2 项单测，其中 Python 标准 zipfile 独立解开合成 ZIP，错密码拒绝；`pnpm test:room` 真实 Electron 验证锁／解锁、用户界面、快照／调试无正文和钥匙、密文文件、原生私人存档导入恢复和密文／钥匙完全相同。没有宣称已在资源管理器手工打开验收；真实主模型写日记尚未实测。
组合审计补充：日记按实际日页归属取材，跟随 04:00 翻页完成后写，不在午夜提前结束仍在继续的那一天；钥匙到下一日页 04:00 解锁。新增凌晨 01:00 仍不写前一天的单测，并验证主模型 chat 路由、计入自主预算、正文不入日志。显式 LCA_DATA_DIR 的测试／多实例房间也放进各自数据目录，避免共享真实“文档”投影。
