## 本轮验收发现与修复

- `7d8600b`：`62f077e` 的 lint 清理改变了校园插件辅助文件，入口保留旧指纹，导致插件拒绝加载，首轮包内矩阵停在 `THREE_CANDIDATES_MISSING`。同步指纹并增加实际分发包加载、两类辅助文件篡改拒绝的单元检查。校园插件仍需另行安装。
- `4ad3931`：读过外部来源后切换状态，系统提示可能带上来源限制。旧代码下一轮在步骤开始前按旧坐标写替换记录，DSH 冷恢复报日志格式损坏。系统 / 开发者提示现在于 `agent/request` 钩子、步骤已打开且请求尚未发出时用当前坐标退役；不存在的会话才新建，损坏记录保留原错误和原文件。新增状态切换 → 来源退役 / 新命令 → 冷恢复回归；不自动修复旧损坏日志。

首轮 `f5cbb89` 安装器（SHA-256 `e68564a472dd73519c998d3e30a7d27c1390ff8c2737e7e669aa93da50746def`）留在不带 `-r2` 的输出目录，标记为验收失败，不用于交付。中间的诊断失败和中断记录也保留；最终候选另在 `-r2` 目录构建，不把后续通过写回旧包。定向回归曾揭示 DSH 禁止在 `session/event` 内递归追加日志，最终修复改用请求钩子；曾调整测试中的冷启动模型交接预期，未放宽生产审批或来源边界。

最终包矩阵的原完整命令通过前 18 项后，在第 19 项 `showcase` 停于 `WRITE_CHECKPOINT_MISSING`：记录显示休息结束的前台事件使写作暂停为 `busy`，前台结束时合成时钟已冻结，不会自动发生下一次 5 秒调度。`0a1c546` 仅修正测试，等待前台 / 记忆与收件队列完成，再有界推进调度，仍检查完整产物哈希、失败状态和恢复。包文件未改变；原命令退出码为 1，后续按安装器、asar、bridge 与逐项脚本哈希续跑，不称为原完整命令退出码 0。
