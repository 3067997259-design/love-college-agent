# 聊天、工作与生活的上下文连续性审计

2026-10-19。用户要求在尝试接入 DSH 前，检查现有上下文注入是否实现同一角色、同一本日会话在聊天、编码、日程与世界泡之间的连续性。本文先记录当前事实，再列出待实现的目标，不把换后端当作问题已经解决。

## 结论与证据范围

当前实现是**同一日会话和 harness 下的两种独立上下文投影**。人格和一部分摘要的冻结已经存在，但完整的本日会话承接、工作中实时事实同步和退出后的语义回接没有贯通。独立投影也作用于 UI、记忆和恢复，因此用户感到工作像另一个板块有具体的代码原因。

## 1. 已经实现的部分

### 一个日会话、同一个主循环与主模型

同一用户 / 角色只有一个当前日会话，按上海时间 04:00 划分；日切等待执行、空闲和计时条件，不在工作中强切。心流继续通过同一个 `createHarness` 和 chat 模型客户端采样，没有另起一个 code provider 或第二个普通聊天会话。

来源：[会话存储](../../src/main/store/session.ts#L26)、[日切调度](../../src/main/memory/service.ts#L110)、[主循环装配](../../src/main/index.ts#L543)。

### 每次模型步骤确实重新准备上下文

harness 在每次采样前调用 `prepareContext(turnId, signal)`，收到工具结果后再进入下一步。普通聊天从 memory 服务组装系统约束、档案、角色卡、跨日摘要、当日上下文和召回；工作模式走 flow 服务。

来源：[每步准备与请求](../../src/main/harness/loop.ts#L109)、[普通聊天组装](../../src/main/memory/service.ts#L193)、[模式分流](../../src/main/index.ts#L559)。

### 人格和已有的系统摘要会冻结

进入工作时调用普通准备端口，取其中全部 `system` 消息保存为 `flow/open.prefix`，再加工作规则、coding skill 和聊天引用。角色卡与人格因此会反复发送，并没有完全撤去人设。

普通 `/compact` 把旧完整回合的压缩结果投影为 `system` 消息，所以**已经生成的当日 conversationSummary 也会进入冻结前缀**。它不是完全没有承接压缩结果。

但进入工作并不保证产生一次覆盖本日全部已有内容的压缩：普通自动压缩按 24,000 字符阈值触发，并保留最近完整回合；工作入口随后自行筛选消息。

来源：[工作入口](../../src/main/heart-flow/service.ts#L171)、[普通压缩](../../src/main/memory/service.ts#L81)、[摘要投影](../../src/main/journal/projection.ts#L111)。

## 2. 连续性断在哪里

| 断点 | 实际行为 | 后果 |
| --- | --- | --- |
| 进入工作 | 除 `system` 外，只另取 UI 中最近 12 条非旁白消息，每条前 500 字；不是完整的压缩后当日上下文。 | 早先尚未进入摘要的要求、单条消息尾部的约束会丢失。 |
| 引用与世界事实 | 跨日摘要、记忆召回和 worldFacts 都作为 `user` 数据消息提供，入口筛系统层时把它们去掉。 | 即使普通聊天刚知道的经历和世界状态，工作入口也可能不知道。 |
| 工作中的状态更新 | 活跃 flow 不再调用普通准备端口；世界快照不会重新注入。`backgroundQuiet` 使非用户 inbox 事件不被 drain。 | 番茄与世界事件继续记录和排队，但进入模型要等退出工作；安静发言门控同时成了事实接收门控。 |
| 可用工具 | 活跃工作只保留 `clock.read`、`plan.update`、`user.ask` 和 `desk*`。 | 时间可查，当前执行计划可写；番茄、记忆检索、校园候选 / 日程及普通 MCP 能力均被切掉。 |
| 回到聊天 | 普通上下文和聊天 UI 排除整个 flow 区间；退出只投递约 2,000 字符以内的文件 / 执行证据 JSON。 | 工作中用户说过什么、为何选择某方案、约定接下来做什么，不会作为对话自然接回。 |
| 工作记忆 | 工作 `prepareContext` 返回 `eligibleIndexes: []`。 | 工作输入整体不进入 seenFragments；用户的工作中决定也被一起排除，日摘要和日记无法直接取到这些片段。 |
| 工作压缩 | 手动压缩保留最近最多 25 个文件变更 ID / 路径与可选 focus；自动压缩额外保留当前回合消息。 | 更早的目标、理由、用户决定、未解决问题没有语义检查点。 |
| 恢复旧工作 | 复用原 flow 的冻结前缀，追加旧结束证据，不重新走当前普通准备。 | 工作结束后新增的聊天与规则不会自动进入恢复任务。 |

来源：[12 条引用](../../src/main/heart-flow/service.ts#L178)、[世界事实是 user 数据](../../src/main/index.ts#L443)、[工作上下文](../../src/main/heart-flow/service.ts#L113)、[工具范围](../../src/main/index.ts#L543)、[安静与 drain](../../src/main/harness/loop.ts#L56)、[排除工作区间](../../src/main/heart-flow/context.ts#L11)、[UI 分流](../../src/main/heart-flow/service.ts#L103)、[退出证据](../../src/main/heart-flow/summary.ts#L8)、[工作压缩](../../src/main/heart-flow/service.ts#L59)、[恢复](../../src/main/heart-flow/service.ts#L160)。

这里的 `update_plan` 是当前执行清单，不能据此认为用户日程规划已经贯通。原文、代码和任意工具正文不自动成为个人记忆的边界仍应保留；缺的是把合法的用户决定、任务状态和实际结果接回共同会话的机制。

### 投影不统一还会造成反向混入

新工作入口从 `store.projection().messages` 取最近 12 条，而不是从已经过滤的普通模型上下文取。探针复现：普通聊天已经排除的旧工作讨论，重新进入一个新工作时又出现在 `conversationReference` 中。

因此它既可能漏掉必要背景，也可能重新引入另一路投影已经退出的内容。涉及忽略来源和私有原文时，这一入口仍需专门做生命周期测试；本轮只用合成工作文本证明投影不一致，没有读取或推测真实私有内容。

## 3. 缓存做到了什么、缺少什么

冻结前缀会在后续请求中完整重发，后端供应商才有机会复用计算；它并不意味着应用可以省略人格和背景，或者模型在请求之间自行记住它们。以 DeepSeek 为例，缓存依据匹配的前缀，实际命中可由响应的 usage 字段观察：[官方缓存说明](https://api-docs.deepseek.com/zh-cn/guides/kv_cache/)、[Chat API usage](https://api-docs.deepseek.com/api/create-chat-completion/)。不同供应商的规则与缓存生命周期应分别验证。

当前有三层证据需要区分：

1. **已证明稳定的局部**：同一 flow 的人格 / 系统摘要 prefix 在合成的两次实际 harness 请求中保持一致。
2. **会重写后续前缀的内容**：目标、草稿操作、回退信息都插在工作历史之前；改变目标会使整个请求不再是旧请求的纯追加。普通聊天的召回、跨日引用、世界快照也会重新构造。模式切换还改变工具声明，实际影响须看供应商的请求处理。
3. **缺失的观测**：SSE parser 只保留总输入 / 输出 token，不保留 DeepSeek 的 `prompt_cache_hit_tokens` 或 `prompt_tokens_details.cached_tokens`。合成 SSE 明确带入这两个字段，最终 attempt 记录仍丢失它们。后续（M1，2026-10-19，main）：parser 已把两种字段归一为 `cachedInputTokens` / `uncachedInputTokens` 写入 `model/attempt`，连续性探针改为验证已记录。真实验收（同日，授权调用）：DeepSeek 官方真实 SSE 的命中 / 未命中与记录逐字段一致（相同合成前缀第二次命中 1,280、未命中 244；首次显式 0 保留）；换过分区的文本 GPT 端点单独回报 `prompt_tokens_details.cached_tokens`（命中 4,224 / 未命中 1,445），两种形状均已在真实 payload 中验证；中转 Gemini / Claude 不回报缓存字段，记录保持缺失。该 GPT 端点还会注入一段约 4 千 token 的隐藏前缀并命中其缓存，供应商侧开销要和 LCA 自身上下文分开计量。

因此不能从“prefix 冻结”推出“已经获得较高命中率”，也不能把没有统计解释为完全没有命中。本轮没有真实供应商计费或缓存测量；M1 之后字段可记录，且已用授权真实调用验证了两种缓存形状与真实命中，但仍不构成命中率 / 成本结论。

来源：[工作请求顺序](../../src/main/heart-flow/service.ts#L122)、[普通请求顺序](../../src/main/memory/service.ts#L206)、[wire 序列化](../../src/main/model/client.ts#L82)、[usage 解析](../../src/main/model/stream.ts#L11)、[usage 类型](../../src/main/model/types.ts#L11)。

## 4. 后台任务与主角色的关系

世界泡事实由确定性代码推进，`life.save()` 通过 autonomous 事件通知主 harness；后台阅读 / 写作使用窄 JSON 任务，只接收 kind、step、material、previous。日记另有角色卡和有限 seenFragments。这些调用可以跟随主模型配置，但共享供应商不等于共享请求上下文。

后台机器任务不必为每次提取或文件排版重复整份聊天。连续性的责任应由主会话及其上下文组装层承担：给子任务所需材料，收回带来源的结果，再更新同一条任务与角色经历主线。不能用后台独立任务的状态替代主会话真正看见了相应结果。

来源：[后台窄端口](../../src/main/model/task-ports.ts#L31)、[世界状态与事件](../../src/main/life/service.ts#L17)、[阅读写作输入](../../src/main/life/work/service.ts#L111)、[日记经历入口](../../src/main/diary/service.ts#L26)。

## 5. 按用户要求重整的目标契约

以下是本次要求对应的设计建议，尚未实现。用户已明确希望一个本日 session 连续承载 chat、code、日程和世界泡；具体字段、预算与版本切换实现仍需设计。

### 两段冻结、增量追加

```text
A. 角色与系统约束快照（人格、用户档案、规则及其版本）
B. 本日共同会话检查点（已有摘要 + 最近完整回合 + 当前任务约束）
   ——进入工作时形成一次有来源和版本的稳定快照——
C. 当前工作历史（用户、助手、成对工具调用与结果，按序追加）
D. 新输入与事实增量（用户插话、日程变化、世界事件、当前权限变化）
```

A / B 随每次模型请求重发，同一快照版本内保持稳定；进入 code 改变执行模式和能力，不建立另一个人物或另一本用户会话。B 不一定需要额外调用模型重压本日全部聊天：可以沿用合法压缩检查点，加上未压缩的完整近期回合和明确约束。

增量应在工具结果已经记录的安全边界进入。持续变化的数据不提前插入稳定历史之前；是否主动发言与是否接收事实分别控制。时间需要时用时钟工具查询，不把每秒变化的时间戳放进稳定前缀。

当用户修订指令、来源失效、权限撤回或上下文过长时，应明确切换快照版本。缓存不能成为保留已失效信息的理由。

### 工作结束后回到同一条主线

- 保存带来源的工作语义检查点：目标、用户决定及理由、实际改变、验证结果、未解决问题和下一步；附上执行证据引用。
- 聊天和工作视图可以折叠不同细节，共同会话仍能引用这些决定和结果。
- 区分任务上下文、用户显式决定、个人经历、文件正文和原始工具输出，不通过“全部允许抽取”来补连续性。
- 恢复旧任务时保留旧工作检查点，同时接入当前角色 / 会话增量；旧审批和执行授权不复活。
- 需要跨模式使用的日程、记忆、世界查询与实际工作工具由统一能力层提供，执行仍按当前授权判断。

### 与 DSH 接入的先后关系

先明确 LCA 拥有的共同会话、A / B 快照、增量与来源生命周期契约，再把 DSH 的 run / session 映射到它。仅换成 DSH 内核或桌面 Host，不会自动修复当前的入口筛选、UI 分流、事件门控与退出摘要；这些属于 LCA 的上下文装配职责。

## 6. 真正的连续性验收

后续实现至少用实际请求捕获覆盖以下场景，不能只检查提示词里出现角色名字：

1. 聊天早期明确工程约束，经过长聊天与 `/compact`，进入 code 后仍能拿到约束和未决事项。
2. 同一工作至少跨两次工具采样；A / B 的内容和版本保持一致，工具调用 / 结果配对完整，新增内容可追踪。
3. 工作中用户改主意、番茄进入休息、日程出现变更；下一合适采样点收到增量，同时保留安静策略。
4. 回到 chat 可以解释刚才的决定和实际结果；继续计划、安排生活不要求用户重复背景。
5. 长任务压缩后仍保留目标、理由、当前约束和未解决问题；重启及恢复旧任务接入新的合法事实。
6. 忽略来源、取消文件、切换隐私路由与恢复不会让过期原文进入冻结快照或记忆。
7. 请求捕获证明稳定内容，供应商 usage 单独证明真实缓存命中；合成流程、模型表现和账单分别报告。
