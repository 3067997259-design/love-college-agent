## 本批实现

- [来源清单](../../vendor/airi-memory/manifest.json) 将固定 mods 与已选工作区增量分开。原始字节保存在 `vendor/airi-memory`，原许可证与分发规则均已加入；运行时不读取 `D:/airi`。
- `src/main/memory/airi/` 保留领域、仓储与主要编排；原浏览器存储、Pinia、Vue、auth、provider、journal 接口替换为主进程端口。只剥离 AIRI 自己的计划持久化和浏览器聊天压缩设置；DSH 将拥有模型历史压缩。原 SQL 的兼容表／列保留。
- `src/main/memory/storage/` 通过 Node Neo `@duckdb/node-api@2.0.0-r.1` 开真实文件库，主进程控制 utility process。事务租约覆盖整个 callback，其他写入与 checkpoint 排队；失败没有临时内存库回退。所有业务时间来自 Clock。
- settings／原 outbox 的本地状态采用主进程写入、fsync 后替换的文件；该状态不收凭据。稳定 operationId 将意图、数据库事务回执和 append-only 完成记录相连；重开先对账。镜像 dirty 记录与事实同事务，写入原 outbox 并 fsync 后才按版本确认，关闭数据库到状态文件之间的丢失窗口。
- 镜像仓储保持原三种向量列与算法；LCA 宿主按用户、角色、数据根和恢复 epoch 选择独立 schema，错误不回传连接串。镜像配置和投递仅用假连接测试，未连接真实 Postgres。
- 原 Parquet 快照合同已适配原生执行器：支持五表旧版与六表 v2，LCA v3 另含提交回执和镜像 dirty 记录。新版私人存档使用 v3，向空数据库事务导入并校验完整列、所有者、回执索引和操作日志；导出前检查原生正文中的已知凭据，避免压缩掩盖泄漏。
- 独立 embedding 端口保留三种向量维度、模型指纹、query/document 角色和 usage；API 适配在 main 内持有密钥。无配置明确不可用，不自动下载原浏览器模型或更换向量空间。真实向量与镜像服务没有调用。
- 单个 runtime 的初始化改为共享 promise；更正后向量就绪状态绑定事实 revision，避免新事实未 embedding 时直接复用旧的就绪标记。目录仍可独立于向量使用。
- 工作交班使用已发布检查点；现有工作卡显示当前目标版本的文件改动、命令通过与失败计数，模型自报百分比不进入投影。前台引用最新原始决定、执行进度与已核验交付，保留工作作用域。
- 日回顾不再只截取最后 24 个片段：用成功输入的覆盖计数与摘要指纹续算，并保留前版索引；周、月仍从日回顾取材，分批输入保持预算。原始日志不删除，引用按完整条目进入预算。`list_experiences`／`read_experience` 提供带版本的导航与展开。
- AIRI 更正／忘记回执增加可选的原来源身份，和原事务一起保存；当前摘要按来源策略失效。明确的历史问题可展开已更正原话并标注 superseded；忘记后的同一事实版本链不会经历史展开复活。旧回执缺少可核对来源时，先退役此前自动摘要，再从允许材料重建；不会把旧文换个版本号直接重新发布。日记选材未改。
- 独立向量和镜像配置保存在本机 `connections/memory.json`，不进入快照或存档白名单；界面只收写入参数并显示脱敏状态。每次 embedding（含迁移）都先预留资源；不同端点不能静默沿用旧密钥。暂停／更换连接后的迟到结果不确认新队列。镜像提前删除保存空正文 tombstone，同一来源的远端写入与删除事务串行。真实 Postgres 竞争用例已加入但未运行。
- 向量模型切换沿用原 AIRI 迁移状态与三种维度，失败保留 stale 向量并能继续，事实仍可按 ID 读取。超过 100 条后续操作的忘记历史不再被仓储截断；界面展示最近事实、优先展示待审阅操作。
- 旧事实按稳定 ID 迁入原生库，保留原时间、访问计数、层级、来源和已被替代状态，继续待用户审阅。迁移核对成功输入坐标与原采集指纹，失效／工具来源只保留原归档；经历、摘要和原日志不改写。迁移回执与新事实同事务，之后忘记也不会在下次迁移时复活。
- 自动采集按原始成功输入的 key 提交完整候选及完成回执；模型和 embedding 仍在事务之外。部分来源对账未完成时整批继续待定，完整提交后的状态文件缺口通过回执修复，不重复调用抽取模型。空结果同样有完成回执。原 AIRI 领域与原测试的无宿主事务入口保留。

```powershell
pnpm verify:airi-memory

pnpm test:continuity:conversation
pnpm test:continuity:execution
node scripts/continuity-recovery-gate.mjs
node scripts/accept-continuity.mjs --list
```

存储入口只执行离线记忆相关测试和 utility-process 合同。完整候选入口顺序执行 typecheck、lint、全量单测、存储／执行／恢复关卡、固定 DSH bridge／family／collaboration、一次生产构建及产品 Electron 场景。`scripts/smoke-continuity.mjs` 已实现：它逐项核对本次目录内的实际结果，生成 T1–T16 合同覆盖表和证据哈希，不使用其他运行的旧 PASS。各任务保存独立日志和源码指纹；执行期间源码变化则停止。Electron 场景顺序运行，独立 profile 可通过 `LCA_TEST_DATA_ROOT` 指向另一卷；原生测试用 `LCA_TEST_ARTIFACTS_DIR`，缓存用 `LCA_TEST_CACHE_ROOT`。

候选包另用 `pnpm test:continuity:package`：读取固定构建回执，核对 DuckDB DLL、Node 绑定、SQLite 与许可，再以包内 EXE 运行实际 SQLite、非空完整恢复、记忆界面和待核对工作恢复。此入口不安装，不接真实服务，不代替完整包矩阵、覆盖升级或第二机验收。

阶段 6 已完成的定向修复与证据：

- 构建把记忆宿主拆入 `out/main/chunks/` 后，旧的相对 worker 路径失效。改为应用根目录下的实际 worker；正常产品已开库、配置向量并完成重启。
