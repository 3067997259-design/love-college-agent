# D3 接收、唤醒与 attention：实施清单与进度

2026-10-19，demo 分支 `codex/day-timeline-demo`。D2 已完成（一条时间线 + 安全门禁）。本文是 D3 的施工清单；第一批已落地，第二批（attention 调度与 Q7）待做。

## 1. 目标（来自执行计划）

1. **接收与唤醒分开**：任一回合运行时接收全部待处理事件；专注/安静节拍只决定事件能否**唤起**回合。
2. **专注期间任务续跑**：手上已批准任务在专注中可自主推进；每次专注设 token 预算与回合上限；遇审批、提问或失败即停；任务回合用独立步骤上限。
3. **注意力调度点**：新建一个决定"她此刻拿着哪件事"的地方，替代各模块互相检查；顺序按 D-8：用户说话 > 用户任务正在进行的一步 > 答应的礼物 > 她自己的读书/写作/外出。任务在等待（批准/回答/命令/测试）时不算占用她，她自己的事从书签继续。生活作品可用判定改问这个调度点，左页姿势取自它。
4. **Q7 剧本**：有任务的专注里，任务等批准和命令时她的读写有进展；任务恢复时生活作品夹书签让位；休息时交班同时说两边，礼物照常交付。

## 2. 第一批（已完成 2026-10-19）

- **回合内全量接收**：[loop.ts](../../src/main/harness/loop.ts) 的 `drain()` 不再按 quiet 过滤；运行中的回合在每次采样拿到全部 inbox 事件并写 `inbox/drain`。唤醒仍只看 `eligible()`：用户事件或非安静时段。
- **专注任务续跑**：`createHarness` 新增 `taskRun` 端口（`available` / `focusKey` / `steps` / `tokens` / `turns`）。专注运行且存在已批准手上任务时，worker 在用户回合结束后继续 `autonomous` 回合，直到：
  - 每段专注上限（默认 **4 回合 / 40,000 token / 单回 6 步**，token 按本次专注的 `model/attempt` 成功值累计，重启后从 journal 重算）；
  - 任务在等待用户（`question/requested` 未闭环、或投影 waiting-user）；
  - 上一回合失败（`turn/end.reason !== 'completed'`）。
- **任务上下文**：自主续跑回合在请求末尾注入 `continuingTask` 数据段（任务、计划版本、步骤状态、授权范围、继续指令），不进入记忆、不改聊天历史。
- **测试**：[d3-continuation.test.ts](../../tests/unit/d3-continuation.test.ts) 4 项（安静时不唤醒但运行回合收到事件、专注续跑到上限即停、提问后停止、失败后停止）；原 harness 安静缓冲测试按新语义更新。`pnpm test` 81 文件全过。
- 接线：[index.ts](../../src/main/index.ts) 传入 `taskRun`，`available` 依据番茄 focus + `authorizedActiveTask()`。

## 4. 已知限制与待决定

- 每段专注上限默认值（4 / 40k / 6）是初始值，Q7 后由维护者调整。
- 自主续跑目前只覆盖任务推进；"她自己的事"走 `life/work` 后台模型，可用判定已经改问 `attention.lifeAllowed()`。
- 交班内容与休息时说两边仍是 D4 的范围；D3 只记录停止/回合事实。
- 旧心流 `flow.*` 命令路径仍保留给历史脚本，D3 不再扩展它。

## 5. 验收结果（2026-10-19，Q7 前半）

剧本：`pnpm test:attention-flow`（Electron 开发者 profile + 剧本模型，不联网）。步骤：聊天提议任务（未批准）→ 确认并开始专注 → 她的阅读开始 → 阅读夹检查点 → 批准任务（专注中）→ 任务自主续跑 4 回合到上限 → 阅读在被占用期间不前进 → 续跑结束后阅读从书签继续。证据：`test-results/d3-attention/scenario.json`。

| 项目 | 结果 |
| --- | --- |
| 任务等待期 | 任务 `proposed`（等批准）时，她的阅读已完成 1 个检查点 |
| 注意力/姿势 | 任务自主计算时 `attention.kind = task`，左页姿势 `desk-computer` |
| 专注续跑 | `autonomous` 回合 = 4（达到每段专注回合上限）；token 与单回 6 步上限由 harness 计数 |
| 让位 | 任务计算窗口内新的 `life/work-commit` = 0 |
| 续跑后 | 阅读检查点从 1 增至 2（从书签继续，未重做已完成步骤） |

说明：休息交班、礼物交付与"同时说两边"依赖 D4 交班，未在本剧本内断言。
