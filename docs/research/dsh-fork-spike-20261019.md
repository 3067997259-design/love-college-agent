# DSH fork 接入 spike

2026-10-19。维护者用 0.2.2 做新手试用后，决定 fork DeepSeek Harness（DSH）来替换心流。目标是三件事：聊天和工作在同一个会话里，两边的插件互通，沿用 DSH 的上下文管理。

本记录核对这条路线在 LCA 里能否跑通，以及本机遇到的阻碍。功能放在开关 `LCA_DSH=1` 后面，默认关闭，不替换现有执行。

| 项 | 状态 |
| --- | --- |
| 基线 | LCA `cad44d1`（0.2.2）；DSH fork 与上游同为 `687f282e`（0.2.1-rc.2），没有修改 DSH 源码。 |
| 已完成 | 外部插件 `dsh/lca-bridge` 与 `lca` 组装；主进程宿主与执行端口；书本显示回复、工具活动、停止和审批；Electron 固定为 44.7.0。 |
| 实测 | 无模型启动探针；维护者授权的真实模型三轮探针（11 步，约 13 万输入 token）；书本界面里新手请求、改脚本、工作中插话三段交互。 |
| 未完成 | “项目内信任”预设没有写入；Markdown 渲染；按需记忆与日摘要注入；项目选择界面；自主事件仍走旧循环；DSH 运行时打包与第三方声明。 |

## 1. 起因：旧版的新手试用

同一句“帮我写个小脚本，算一下 1 到 10000 里有多少个质数，存成文件再运行一下给我看结果”，在 0.2.2 里没有得到任何回复，只有“运行预算到了上限”。原因有四个，彼此叠加。

- **日预算把用户工作也算进去，而且无法调整。** 每次调用按请求体的 UTF-8 字节预留，不按 token（[loop.ts:146](../../src/main/harness/loop.ts#L146)）。一次约 3 万单位，实际输入只有 5–8k token。日总额 50 万（[ledger.ts:72](../../src/main/resources/ledger.ts#L72)），大约 14 次工作调用就用完，之后普通聊天也不回。普通安装改不了上限，只有展位模式可以（[index.ts:410](../../src/main/index.ts#L410)）。这个预算原本是为自主行为准备的，套到用户工作上属于意外。
- **普通回合没有运行代码的工具。** coding 插件在普通回合里被整个剔除（[index.ts:641](../../src/main/index.ts#L641)），旧心流启动时被关闭（[index.ts:497](../../src/main/index.ts#L497)）。任务卡批准的范围写死为 `commands: 'each'`（[schema.ts:91](../../src/main/journal/schema.ts#L91)），也就是批准了一个不存在的能力。
- **降级的回合不能再写入。** 同一回合读过资料、邮件或网页后，写入一律拒绝（[desk-tools.ts:19](../../src/main/task/desk-tools.ts#L19)）。
- **错误不透明。** 工具异常只记作 `tool-failed`，原因被丢弃（[loop.ts:183](../../src/main/harness/loop.ts#L183)）；后台 worker 出现意外异常后会永久停机（[loop.ts:230](../../src/main/harness/loop.ts#L230)）。

## 2. 接入方式

- **薄 fork。** DSH 按上游原样构建，fork 目前零改动。LCA 的行为写成 DSH 外部插件：profile 的 `node_modules` 链接到本仓库的 `dsh/lca-bridge`，与 DSH 共用同一个 Cordis 实例。只有插件做不到的改动才进 fork，并尽量提回上游。
- **进程。** LCA 主进程以 Electron Node 模式启动 `dsh --profile lca`，双方经 Node IPC 通信（[host.ts](../../src/main/dsh/host.ts)）。`$DSH_HOME` 放在 LCA 数据目录下，与用户自己的 DSH 安装分开。子进程只拿到显式列出的环境变量。
- **组装。** [cordis.patch.yml](../../dsh/lca-bridge/cordis.patch.yml) 关闭 DSH 身份句、账号登录、遥测、标题生成和热更新；凭据只从启动环境读取。模型路由取自 LCA 的“日常对话”配置：DeepSeek 官方接口走 `dsh-llm-deepseek`，其他接口走 pi-ai 的 OpenAI 兼容路由。
- **桥接插件**（[index.js](../../dsh/lca-bridge/index.js)）：
  - 行为规则、档案和角色卡放进 `deployment:persona-prefix`，说话方式放进 `deployment:persona-suffix`。
  - LCA 工具以 `lca_` 前缀注册，调用时回到主进程执行。
  - 消息分三种送法：`followup` 开新一轮，`steer` 在她工作中途插话，`inject` 只补上下文不唤醒她。
  - 风险命令先询问，涉及 LCA 私有数据的调用直接拒绝；所有审批都发回 LCA。
- **书本。** 执行端口与旧 harness 用同一个接口（[execution.ts](../../src/main/dsh/execution.ts)），在 [index.ts:723](../../src/main/index.ts#L723) 按开关替换。
  - 每天对应一个 DSH 会话。
  - 回复、工具调用和结果写成书本已有的日志记录。助手消息带上 `toolCalls`，工具结果成对写入，所以旧循环拼出的上下文依然合法。
  - DSH 工具的活动有自己的手写小字模板。
  - 审批复用“她向你提问”卡片，“以后都允许”按项目记住。

## 3. 实测

### 3.1 探针

`node scripts/probe-electron.mjs dsh-spike` 不带授权时只做启动：宿主就绪、打开会话、正常退出。Electron 44.7.0 下，DSH 直接跑在 LCA 自带的 Electron 里。

带 `LCA_REAL_MODEL=1` 时跑三轮合成请求，报告只含数字、布尔值和静态枚举：

| 轮次 | 步数 | 结果 |
| --- | --- | --- |
| 新手请求 | 5 | 写好了脚本；运行时被沙箱拦住（见 §4），升级请求按探针规则拒绝，她如实说明并给出答案 |
| 问番茄钟 | 2 | 调用 `lca_get_timer` 回答剩余时间 |
| 改脚本并插话 | 4 | 插话在下一步被接收，README 按插话要求写成中文 |

三轮合计约 13 万输入 token、2.2 千输出 token，用时 108 秒。这次的路由没有报告缓存命中。

### 3.2 书本界面

开发版，全新数据目录，真实的“日常对话”配置：

| 交互 | 审批 | 结果 |
| --- | --- | --- |
| 新手请求 | 1 次，选“这个项目以后都允许” | 脚本真正运行，给出 1229 |
| 改脚本、写 README | 0 | 自行运行出 1 到 100000 共 9592 个 |
| 布置任务后插话 | 0 | 先回应插话，再报告测试通过 |

后来几步观察到约 82% 的缓存命中，还没有系统测量。补上说话方式的后缀之前，她会用 Markdown 回复，也会忽略插话；补上之后两者都明显改善。

## 4. 本机环境发现

1. **Electron 版本指纹。** DSH 的原生模块只接受特定的 Electron 版本（43.0.0、44.0.0、44.7.0、45.0.0-alpha.6），LCA 原先用的 44.7.2 会被拒绝。现在固定为 44.7.0。补丁版本相同，原生模块 ABI（149）不变，sqlite 探针通过。
2. **D 盘缺少“更改权限”。** D 盘根目录只给普通用户“修改”权限，没有 WRITE_DAC。DSH 的 Windows 沙箱要给工作目录追加权限，在 D 盘任何目录都会失败（Win32 5）。此前一次 D 盘目录的权限修复多半也是这个原因。沙箱失败后，模型会去读 DSH 的诊断技能，再请求升级权限。
3. **下载 Electron 要走代理。** 新版本的二进制需要设置 `ELECTRON_GET_USE_PROXY` 和 `GLOBAL_AGENT_HTTPS_PROXY`。`node scripts/run.mjs install-electron` 已经内置了这两项。

## 5. 权限：维护者的决定与现状

维护者批准的方案：用户选定的项目默认“项目内信任”，即不走系统沙箱，危险命令先问，LCA 私有数据拒绝，并记住“以后都允许”。她的书桌，以及由第三方原文触发的工作，仍然受限。

现状：把这个预设写进 DSH 权限配置的改动没有完成。实施时被编码助手的自动权限检查拦下，留待维护者亲自写入。现在项目会话沿用 workspace-write + 询问，在 D 盘上的表现是：

- 每条命令先在沙箱里失败一次，再请求升级。
- 用户在书里选“这个项目以后都允许”之后，升级会被自动批准，不再打扰。
- 代价是每条命令都多走一轮工具调用，费时间也费 token。

## 6. 后续

- **Markdown。** 受过 harness 训练的模型习惯输出 Markdown，与其用提示压制，不如让书本加上简单的解析。解析落地后，去掉后缀里“不用 Markdown”的要求。
- **审批卡。** 改成一次点击就确认。
- **记忆与摘要。** 按需检索的记忆和前几天的摘要进入 DSH 会话（inject 或当天后缀）。
- **项目选择。** 做一个选择界面，替代 `LCA_DSH_PROJECT`。
- **统一状态。** 自主事件和忙碌状态并入同一个会话。
- **子代理与智能体团队。** 保留 DSH 的相关工具，UI 已有设想（一群小桃子一起忙碌）。控制提示成本用按需披露，不删工具。
- **打包。** 固定 DSH 版本；随安装包分发 DSH 运行时时，附带它的 LICENSE 与第三方声明。
- **缓存。** 系统测量缓存命中率，确认两种路由的用量字段都能正确解析。

## 7. 复现

前置条件：
- 本机已检出并构建 fork（`pnpm install && pnpm run build:artifacts`）。
- 用 `DSH_ROOT` 指向 fork 目录。

不调模型的启动探针：

```bash
node scripts/probe-electron.mjs dsh-spike
```

书本界面需要先构建本仓库（`pnpm build`），再用独立的数据目录启动开发版：

```bash
LCA_DATA_DIR=<独立数据目录> LCA_DSH=1 LCA_DSH_PROJECT=<项目目录> node_modules/electron/dist/electron.exe .
```

真实模型探针和界面测试会调用付费模型，需要相应任务的明确授权。
