## 网关调整

此前网关从发起请求起统一等待 45 秒。对账发现，多条 provider 消费记录对应 55–65 秒的服务端耗时，本地等待先被取消。该结果支持调整测试时限，尚不能证明 provider 早晨服务波动的具体原因。

| 限制 | 新值 | 计时规则 |
| --- | --- | --- |
| 首响应 | 120 秒 | 从发起请求到首段非空响应体；仅收到响应头不取消此限制 |
| 数据空闲 | 60 秒 | 首段数据后，每次非空数据重置；空块不重置 |
| 请求总长 | 300 秒 | 始终从发起请求起算，持续收数据也不能无限延长 |
| 场景等待 | 600 秒 | 容纳一个回合的多次模型步骤与产品状态收敛 |
| 工具屏障兜底 | 1,800 秒 | 为前台聊天与补充回合留出时间；实际释放仍由文件事件触发 |

所有请求时限通过统一 Clock 调度。记录响应头、首段数据、最后数据、完成和超时的相对时间，以及 `first-response`／`idle`／`total` 超时阶段；首段数据不是模型首字，统计不混用。收到完整 `[DONE]` 仍立即结束，不等待 HTTP EOF。下游取消、网关关闭和正常结束都会移除计时器。

固定失败词汇继续使用 `TIMEOUT`，细分阶段留在诊断字段。首次失败仍停止批次；没有加入自动重试或失败回退。参数写入运行回执，辅助源码和配置随每次预跑／实测冻结。
