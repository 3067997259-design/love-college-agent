# 候选 10：DSH 初始化、宿主重启与固定包验收

[候选 9](continuity-candidate9-repairs-20261103.md)的新安装回归在生活工作场景失败，未发布。正式 root 的所有权保护正确拒绝了空 ID；问题出在执行层已经建立了会话占位对象，却在 DSH 注册完成前把状态通知发送出去。

## 修复

- 状态更新与取消只对已经获得 ID 的会话发送。初始化期间仍记录当前状态，真正发送回合时重新取得最新状态。root 所有权检查保持，不把 `DSH_ROOT_UNAVAILABLE` 吞掉。
- Windows 子进程启动失败且没有 PID 时，明确完成失败收尾，不等待可能永远不来的 `close`。已启动进程的管道错误仍要求等待实际退出；不把 IPC 断开当作进程已经结束。
- stderr 管道自身的错误转为既有宿主不可用状态，避免未捕获异常窗口阻止应用退出；不打印可能包含供应商信息的 stderr。
- 扩展维护中的“重启”在释放前台使用权后，真正关闭并重建共享 DSH 进程。存在其他使用权时拒绝重启，旧进程未退出时拒绝新建宿主；保留各工作 root 的隔离。此前预跑中扩展已启用但仍为 disabled，实际未完成重启，失败报告保留。
- 安装场景统一采用指定的短测试数据根和动态端口；位于另一卷的执行关卡、合成 Minecraft MCP 夹具明确解析本 checkout 的依赖。升级测试支持独立卷。均为测试接线，不改变服务授权或质量阈值。
