### DSH 能力的使用方式

优先复用固定版本已有的服务和日志，LCA 负责权限、作用域、安全投影与书本交互，不另写一套代理执行循环。

- 插件使用 `pluginManager`；MCP 使用 DSH 的 MCP 配置与连接能力；skill 使用 `skills.list/snapshot/get` 和 filesystem provider。这三者没有一个共同的“install skill/MCP”万能接口，需要各自的适配。
- 旧 LCA 插件和 MCP 与 DSH 扩展都显示来源与实际所有者。现有连接不静默迁移、不双连接；校园助手继续通过 LCA 的 `sourceMails` 链路。
- 当前 DSH skill provider 会查项目 `.dsh/skills`、`.agents/skills`，以及 DSH / agents 用户目录等。计划明确允许的搜索根和安装作用域，避免无提示地把其他应用或其他 profile 的 skills 带进来。
- 管理器默认调用 `pnpm`。LCA 当前没有给它指定安装包自带的 package manager。干净 Windows 上的 Node/pnpm 供应必须做打包探针，不能用维护者 PATH 中的工具证明用户可安装扩展。
- 首选维持当前关闭 HMR 的方式，提供明确的重启生效流程。是否引入 HMR 另行评估，不能为省一个重启按钮扩大运行中替换范围。

## 两个安全缺口

### S1：子代理的信任与审批

**源码事实：**

- `dsh/lca-bridge/index.js` 的 `tools/post-execute` 只有 `top && sandboxDenied(result)` 会进入 `askTrust`。子代理遇到同样的 Windows ACL 错误时不会得到这条处理。
- `trust` / `untrust` 仅切换指定根会话的 preset；LCA 的审批卡只收到 root `sessionId`，缺少实际发起者和其项目身份。
- DSH `captureDelegatedPolicyOverrides` 会捕获创建时的父级 sandbox override，并把子会话审批策略固定成 `never`。这里 `never` 表示自动拒绝需要审批的操作；`user-approval` 在发出 `approval/request` 前就拒绝。因此不能假设现有 bridge 监听器会把子代理的所有审批传到书里。
- 子代理是创建时权限快照。父级之后信任或撤销信任，不能假定已存在的子会话自动同步。
- LCA `execution.approve` 依赖当前主回合；如果主回合已结束而成员仍在工作，当前路径不能直接承担该成员的审批。

**目标与拟议实现：**

1. 记录并校验 `rootSessionId / originSessionId / parentSessionId / projectId / epoch`，在创建、恢复、切换项目和撤销信任时都可解析到实际归属。禁止用“当前打开项目”替代请求所属项目。
2. 在 LCA 管理的子会话中建立明确的审批转交方案。先验证 Cordis scoped setup / service seam 能否在首次模型步骤前完成接入；只调整 LCA 子会话，不全局改变 DSH 默认委派策略。
3. 信任由用户对项目作出；在已信任项目内创建成员沿用已授权范围。子会话新遇到沙箱不可用时，通过主进程展示带成员身份的信任请求，批准后仅作用于该项目；拒绝后不让模型反复修 ACL。
4. 信任撤销作用于该项目的现有成员及后续恢复成员；pending approval 带作用域和有效期。停止、重启、换模型、恢复存档后，旧响应不得授权新动作。
5. 降级回合不新建信任，也不应用常设批准；风险操作按现有规则处理。成员不能借另一个成员或已结束的根回合绕过检查。
6. 首个 spike 若无法通过插件层实现“首次步骤前有效、恢复仍有效、撤销立即生效”，记录最小 DSH fork 补丁的必要性与替代方案，再安排独立补丁。不能仅去掉 `top` 条件便宣布修复。

### S2：长期成员的第三方内容撤回

**源码事实：**

- 子成员读网页等会调用 `degrade(root, source)`，但 `agent/pre-step` 中的撤回仅对 `live.has(sessionId)` 的根会话执行。
- 因而根会话进入下一轮并清除降级时，长期成员自己的旧原文可能仍然留在其模型上下文中。
- [retirementProjection](../../dsh/lca-bridge/policy.js) 读取当前会话的 `tool/call`、`tool/result` 和标记过的 LCA 引用；它没有处理 `source.kind = agent-message` 的成员转述。DSH 的 `send_message` / Team 消息实际可作为这种 `user/message` 送入另一个成员。
- `DELEGATION` 结果的退役依赖当前会话自身的来源记录；子成员单独读过来源，不能只靠根会话的这个投影证明回传结果被追踪。
- 谱系缓存是进程内 Map。多层冷恢复、消息迟到和成员重建需要独立核对，不能把正常创建顺序的单测外推到重启。

**目标与拟议实现：**

1. 来源归属和待撤回状态按实际会话持久化；根会话显示汇总状态。根轮次与成员轮次分别记录，不能把两者的数字当成同一个时钟。
2. 每个成员在下一次模型请求前检查本会话的过期引用。主角色进入下一轮并不直接证明队员已经干净；队员还在同一工作段时保留它的限制。
3. 把成员转述、委派结果、fork 继承内容及被它们引用的摘要纳入来源传播。标识由主进程或 bridge 生成和校验，不接受模型自报“已清理”。
4. 先定义边界：用户新回合与新任务的原文授权如何继承到成员、哪些消息仅续跑旧任务。实现中保留可核对的来源/授权标识，避免把“收到一条队友消息”自动当成原文的新授权。
5. 压缩不能让尚未退出的来源在摘要中丢失标识；退役改变模型可见投影，不删除原始日志。无法证明已经撤回时保持限制，并报告可理解的原因。
6. 覆盖恢复、根闲置而队员运行、跨项目、跨日、取消后迟到的结果和存档回退。无法核对归属的 LCA 后代不能因查不到 root 而直接跳过安全与额度检查。

### 扩展管理必须同时封住的权限通路

这不是增加一个独立产品方向，而是开放扩展后 S1/S2 能成立的前提：

- `plugin_manager` 可以持久修改整个 profile；DSH 的工具要求 full-access 或单次批准。`lca-trusted` 已使用 full-access sandbox，不能把项目信任解释成安装代码或修改 LCA 安全服务的授权。
- 当前 `gatedWhileDegraded` 没有包含 `plugin_manager`。需按管理动作分类：只读查询、安装/移除、启停、配置与构建脚本批准分别处理，模型调用与 UI 调用走同一授权规则。
- 保护 base、LCA bridge、审批、隐私、用量等必需组件及 profile 层级；不能让管理器自己的动作关闭负责约束它的服务。DSH 原生管理器对其自身管理组件的保护不能代替 LCA 的保护清单。
- 代码插件属于获准的宿主代码，不宣称工作区沙箱能隔离恶意插件；安装前给出来源、版本、变更范围和构建脚本要求。密钥继续由主进程管理，普通日志和 renderer 只接收脱敏结果。

### 拟议 UI 实施顺序

1. **状态草图。** 用占位轮廓验证左页 0、1、多个成员以及人数超过可见位置时的构图；右页继续承载当前对话与审批。草图不是采用素材，也不连接真实模型。
2. **场景契约。** 在当前近景外增加独立的团队远景模式；背景、主角色、小桃子与可点击位置分层。不是把含角色和书桌的整张近景图直接缩小。成员位置稳定，不因每条事件重新排队。
3. **事实到表现。** `running` 表现工作，等待批准或同伴表现对应等待；`inactive` 只表示当前没有回合，不能画成“任务完成”。完成、失败与已请求停止必须取不同事实；DSH 的 accepted interrupt 不算已经停下。
4. **素材准备。** 核对旧宽景、人物身份、服饰、光线、透视和房间家具关系，列出新远景及小桃子所缺素材；生成/绘制候选后集中审图，用户采用后才接正式资产。
5. **兼容与节奏。** 新手上色、夜间、熄灯、外出、照片回看、迷你窗及减少动画偏好各有明确回退；自定义角色包缺少团队素材时不混入桃子替代其身份。优先用中性状态表示，场景兼容作为可选包能力。
6. **验收。** 检查左页实际尺寸下的可读性、遮挡、键盘操作、焦点与审批可达性；大量活动只更新必要区域。专注时不因普通队员状态反复弹通知。

视觉切片可以在安全工作期间先做静态草图。真实成员控制与自动团队运行，必须在安全门槛通过后接入。

### 接口首稿应包含什么

- `ExtensionView`：明确所有者、种类、来源、版本、作用域、安装状态、启用意图、实际生效状态、待重启原因和安全错误分类。不要把 `installed`、`enabled`、`ready` 合为一个布尔值。
- `ExtensionOperation`：operationId、目标、阶段、可取消状态、最终结果、重启需求；审批绑定版本/来源/变更，失败或结果未知时先核对现状。
- `AgentView`：root/parent/member ID、项目、模式、名字与任务、activity、独立 outcome、等待原因、可用控制项、用量汇总。子消息与主角色对用户说的话分开。
- `TeamTaskView`：任务 ID、revision、owner、依赖、状态和写入范围提示。DSH 的范围冲突只是提示，不当作文件锁。
- 命令全部由主进程校验身份和 epoch。停止只返回“请求已接受”，收到实际结束后再改变终态；renderer 不自己拼接或重放 DSH 消息。
- 日志只新增本次产品需要的事实、归属和审批，不复制所有子会话工具原文；成员输出不自动成为用户经历或抽取记忆。

### 普通子代理和 Team 的装配决策

上游 Team layer 会替换三个同名控制工具并禁用普通委派入口，不能同时原样装入两套工具。P0 需验证后选定以下实现之一，并留下决策记录：

1. **首选调查：** 在 LCA 适配层保留普通 `subagent/subagent_fork`，用明确的作用域或统一路由分派控制工具到实际成员系统；Team 的名单、普通子目录和消息地址不能混淆。
2. **备选：** 两种协作模式按会话明确选择，分别装配；切换时不打断现有成员，也不复用不兼容历史。只有运行时服务无法可靠共存时才采用，并说明体验代价。

“保留能力”是已确定方向，具体命名与装配方式属于 P0 技术决策；不直接采用禁用普通子代理的上游 profile，也不偷偷注册两个同名工具。

| S4 | 成员 A 读原文，再通过 `send_message` 发给 B/主角色；fork 继承、委派结果、摘要压缩及迟到消息都保持来源，退役后请求中不再出现合成原文标记。 |
| S5 | 读原文后重启、换模型、换项目、跨日、存档回退；谱系/投影损坏或撤回失败时停止解除权限限制，旧批准不重放。 |
| A1 | 成员创建、失败、运行、闲置、继续、结果、单成员中断和整组停止；接受指令和真实终态分开验证。 |
| A2 | root 已闲置而成员仍在运行；全家族额度、用量、审批和关闭正确。后台自主回合不能通过委派绕过步数与预算约束。 |
| A3 | Team 成员消息、任务 claim/revision 冲突、依赖、写入范围重叠、进程恢复；普通子代理与 Team 控制无地址或工具名串用。 |
| V1 | 左页近/远景与人数、状态匹配；夜间/熄灯/外出/新手/照片/迷你窗/缺素材有正确表现；键盘可操作、审批可达、无无关焦点抢占。 |
| R1 | 同一个候选安装包上验证扩展依赖和原生模块；干净机器无 Node/pnpm 时路径明确可用；升级保留现有用户记录与扩展配置。 |
