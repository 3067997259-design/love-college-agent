# 1.2 P0 / P1：隔离探针与接口落地

日期：2026-10-23。对应[开发计划](v1.2-development-plan-20261023.md)的 P0 / P1。DSH 仍为项目内固定的 `0.2.1-rc.2`，未改参考仓库或升级依赖。

## 本次结论

- **P0 完成：** 普通 spawn、fork、Team 三种运行方式均能重复复现 S1 / S2；同样三种方式验证了插件生命周期与模型上下文替换的修复切入点。
- **P1 完成接口及身份基础：** 扩展、成员和团队任务共享类型已独立提交；main 与 bridge 绑定运行代次、项目、根／父／子会话，关键请求校验后才进入额度、工具与审批。新页面和业务操作尚未接入，相关命令返回不可用。
- **两个缺口仍未完成生产修复。** `*-seam` 是测试专用插件：放开子审批用于验证生命周期；用合成标记代替未来的来源账本用于验证退役 API。它不进入正式 profile，不能据此宣布 S1 / S2 关闭。

## P0 的装置与证据

运行 `pnpm test:dsh-family`。入口为 [dsh-family-check.mjs](../../scripts/dsh-family-check.mjs)，测试插件为 [dsh-family-probe.mjs](../../scripts/fixtures/dsh-family-probe.mjs)。每次运行在系统临时目录建立独立项目、HOME、DSH_HOME、AGENTS_HOME 与 profile，使用环境变量白名单和只监听 loopback 的脚本模型。没有读取本机凭据、连接真实模型、安装扩展或操作用户项目。

每个场景先委派任务，再继续子会话，最后退出整个 DSH 进程，启动新进程恢复根与子会话。证据包含实际模型请求、会话事件、工具结果、审批事件和退出码；原始文件保留在运行时打印的临时目录。终端报告与失败退出码便于回归，报告中的 `ok` 表示符合该场景的预期，基线场景预期就是复现缺口。

| 检查 | 实际结果 | 边界 |
| --- | --- | --- |
| spawn / fork / Team 默认子策略 | 首次创建固定 `never`，审批未到 LCA，合成需要审批的工具未执行 | 这是自动拒绝，不是自动批准 |
| 子 ACL 失败 | 合成 `grantWrite` 错误原文进入子模型请求，没有项目信任询问 | 确定性注入错误；没有修改 Windows ACL |
| 子来源读取 | 第三方合成原文在下一次子续聊、重启冷恢复请求中仍可见 | 来自实际请求捕获，不以模型自述为证据 |
| 子消息回传 | `agent-message` 转述和 `subagent-settled` 完结消息在根新回合仍保留来源标记 | 两种来源均需修复 |
| 首次步骤／恢复拦截 | `agent/created` 在委派策略写入之后、首次模型请求之前执行；续聊也可能冷恢复 | 必须覆盖每次恢复，不能只监听首次 spawn |
| 退役 API | 在各会话 pre-step 替换工具结果及来源消息后，后续／冷恢复请求不再包含标记，原始日志仍在 | 测试插件通过已知标记识别来源，不是生产来源传播方案 |
| Team 最小装配 | 不加载 UI bundle；成员消息、续聊、恢复、任务创建及领取成功 | 未覆盖多人任务冲突、全部控制动作与用户界面 |
| 扩展管理入口 | 运行中确认九个 manager 方法存在 | 未执行安装、移除或启停，包管理器及打包路径留待 P3 |

普通子工具和 Team 的运行服务可以共存，但控制语义不能混用。本次仅在临时 profile 中禁用普通 `send_message/list_agents/interrupt_agent` 的两个插件实例，装入 Team 的 scoped 工具，保留 `subagent/subagent_fork`。这证明服务共存和单一名称装配，不证明普通子代理在此 profile 中具备完整控制路由。P5 继续采用计划中的首选路线：在 LCA 适配层按真实身份路由普通成员与队员，禁止模型凭名称自行切换系统；不采用整个上游 Team profile 去删除普通委派能力。

## P1 的实际代码

- [collaboration.ts](../../src/shared/collaboration.ts)、[extensions.ts](../../src/shared/extensions.ts)：活动与结果分开、任务 revision、扩展启用意图与生效状态分开、操作取消与结果未知分开。公开视图没有任意路径、连接配置或原始 transcript。
- [dsh-protocol.ts](../../src/shared/dsh-protocol.ts)：协议版本 2、运行代次和项目绑定。它是 main 与 DSH 的内部协议，不从共享 barrel 导出。`DshSourceLease` 是 P2 将消费的来源契约，当前尚无完整的持久来源账本。
- [identity.ts](../../src/main/dsh/identity.ts)：主进程登记根会话，子成员只能登记在已知父级之下；校验真实路径、运行代次、项目、谱系与显示 revision。根失效使后代一起失效。当前只接受与根相同的工作目录，跨目录委派的项目范围规则另在 P2 完善。
- [host.ts](../../src/main/dsh/host.ts)、[bridge](../../dsh/lca-bridge/index.js)：每次模型准入、LCA 工具请求、审批和问题携带 origin；未知身份拒绝，异步返回再次核对。DSH 不能自行替换 main 预留的根 ID。原有 IPC 关闭／断线保护保留。
- [v12-commands.ts](../../src/main/bridge/v12-commands.ts)：新命令检查 epoch、字段白名单和 book 界面来源；未接入适配器时明确 unavailable，不提供通用 manager RPC。当前不发布空的“ready”成员／扩展快照。

在接线中修正了几个相邻的安全边界：账本异常拒绝步骤；无根回合时的子步骤仍申请额度；拒绝准入在请求发送前返回 DSH 的 `reject`（运行结果为 `blocked`）；主进程将 blocked 记为失败；停止回合后到达的批准不再落为长期信任。

接口提交：`b08b09c`（共享契约）、`c59c6c2`（身份登记先于模式投影）。消费者单独提交。

## P2 的具体修复顺序

1. **S1：每成员权限及审批。** 在已验证的创建／恢复切入点设置子审批；以已登记 origin 选择项目，统一根与子 ACL 反馈。逐成员处理信任授予／撤销，并覆盖并发、停止、超时和迟到回答。主角色闲置时的问题卡生命周期不能再依赖根 `turn` 对象。同步修正 DSH 子角色的“审批总被拒绝”提示。
2. **S2：持久来源账本。** 使用授权 ID 和会话自己的轮次追踪来源。显式标记工具原文、引用、fork 继承、成员转述和完结消息；在每个会话请求前退役，无法核对时保持限制。普通控制消息不能一律退役，否则会误删新任务；压缩摘要也不能丢失来源。
3. **安全回归。** 将基线反例转为正式修复断言，移除对测试标记识别的依赖；增加多层、根闲置、换项目、取消、损坏投影、摘要压缩、信任撤销与恢复。没有这些证据不开放真实成员控制与扩展写动作。
4. **P3 / P5。** 再做 profile 配置保留、扩展操作窄适配和受保护组件；接成员生命周期、消息控制与 Team 路由。左页全房间构图仍是已确认方向，未画的构图及交互不阻挡当前底座工作。
