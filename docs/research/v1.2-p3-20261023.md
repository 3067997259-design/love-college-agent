# 1.2 P3：扩展底座、审批与操作核对

2026-10-23。接续 [开发计划](v1.2-development-plan-20261023.md)与 [P2 安全修复](v1.2-p2-20261023.md)。本切片接通主进程管理接口；扩展页面留在 P4，成员控制和全房间画面留在 P5 / V1。

## 实现

- 主进程与脚本启动共用 `dsh/lca-bridge/profile.js`。保留用户 dependency、bundle 选择、其他 manifest 字段、Cordis patch 和 pnpm 配置；必需的 base / bridge 声明保持存在，bridge 位于 bundle 层末尾。迁移采用原子写入，并保存变更前的完整 manifest；损坏输入拒绝覆盖。此备份用于手动回退，不承诺跨版本扩展自动兼容。
- `src/main/dsh/extensions.ts` 提供安全快照与有限命令，接入 controller 和既有审批卡。安装先经原生目录选择、无链接的本地副本及完整文件指纹，再按提案确认；renderer 不能提交安装路径、registry URL 或任意管理 RPC。启停 / 移除检查显示版本和指纹，并在审批前后核实。未配置模型时也可以启动不打开 agent 会话的管理 host。
- 安装默认停用。启用 / 停用保存意图，关闭 HMR 的运行时仍保留实际旧状态；明确批准重启后才生效。状态同时读取 bundle 声明与插件 fiber，加载失败或尚未激活不会被标为 ready。移除运行中的 bundle 被拒绝，须先停用、重启，再移除。
- 安装、启停、移除、重启逐次批准，项目信任不参与放行。构建脚本先被阻止，再按同一候选指纹及实际待批准包清单另行询问；底层许可绑定 pnpm 报告的精确包选择器。本次操作后恢复原 pnpm 策略，不生成新的常驻脚本批准。移除使用禁用脚本的 pnpm 配置。带 profile 自身安装生命周期脚本的配置拒绝通过本接口安装。
- base、bridge、运行时自带组件和保留命名空间受到保护。受管理的本地 bundle 只允许添加自身名称前缀的插件行，不能修改既有安全行。现有 LCA `manifest.json` 包仍走原来的 registry，不混入 DSH bundle，也不重复装配校园入口。代码插件仍是经用户批准的宿主代码，不是沙箱内的不可信代码。
- 模型直接调用 `plugin_manager` 修改 profile 仍被生产 bridge 拒绝；当前受支持的写入口是主进程窄接口。启用管理工具的合成场景验证了已信任主角色与已读第三方内容的成员都不能借项目权限绕过这条边界。
- `extensions.json` 保存主进程操作投影和请求去重；`extension-events.jsonl` 追加操作事实；profile 下的 `lca-extension-operations.json` 在副作用前记录意图、回复前保存结果。取消请求不等于回滚；超时、断连后查询同一个 operationId，不自动重新安装。冷启动不恢复旧批准；有持久完成回执时可核对为成功，没有完成证据则保持 unknown。仍在写 profile 的旧进程会阻止新启动，临时构建授权在冷恢复前还原。
- 随运行时固定分发 `pnpm 11.24.0`，通过 Electron 的 Node 模式和绝对 CLI 路径调用。没有修改上游 DSH 源码；runtime 仍为 `0.2.1-rc.2`，依赖锁文件和第三方说明生成流程继续保留。

## 验证

`pnpm test:dsh-extensions` 使用临时 HOME、数据目录、profile、候选包及禁用公网 registry 的配置。它运行生产 main 服务、host、bridge、DSH 和 pnpm，以合成审批答案驱动接口；不调用模型。Electron 模式下 PATH 只含 Windows 系统目录，排除系统 Node 和 pnpm。测试构建脚本使用 Windows 系统工具，不代表任意扩展的第三方编译工具已随应用提供。

覆盖安装默认停用与重复请求、启用后实际加载、运行中移除被拒绝、停用冷启、移除冷启与用户配置保留、独立构建批准、构建中取消及文件恢复、丢失 IPC 完成回执后的 main / DSH 冷恢复核对、恶意声明覆盖被拒绝、加载失败不冒充 ready、管理端口的核心组件保护。丢失回执通过测试专用传输拦截后真正断开 IPC，恢复时验证操作总数不增加。

`test:dsh-family` 保留 P2 的 14 个场景，增加 `spawn-manager`：在临时 profile 开启上游管理工具，让已信任的主角色和来源受限的子成员实际尝试关闭 bridge / base；实际工具回执均被 LCA 拒绝，未进入扩展副作用路径。

最终结果：17 个单测文件、161 项通过；扩展生命周期 11 项通过；家族安全 15 场景通过，309 次本机脚本模型请求、30 次子进程退出均为 0。类型检查、改动文件 ESLint、生产构建和 diff 检查通过。接口提交 `d114cc4`，实现提交 `277edd1`，工作分支仍为 `codex/1.2-development-plan`。

## 边界与下一批

本轮只开放原生选取的本地 DSH bundle。registry / git / tarball 安装输入、逐插件行配置编辑与版本豁免没有开放；运行时自带组件暂不允许经新接口修改。复杂依赖的构建可能需要用户另行安装工具链。无法证明完成的操作保持 unknown，不将磁盘上“看起来存在”推断为构建脚本的所有外部效果均已完成或撤销。

本轮没有新扩展页面、真实模型或其他真实服务调用、完整 Electron 窗口交互、NSIS 安装 / 升级、第二台机器、存档 UI 恢复和长期体验验收。Electron 的 Node 模式与移除 PATH 依赖是运行时证据，不是干净机器安装验收。

下一批为 P4：在既有插件书签接入这组接口，并显示真正的 skill catalog 与 MCP 来源 / 状态。P2 已记录的跨根回合成员保守终止规则未改变，持续团队调度仍属于 P5。
