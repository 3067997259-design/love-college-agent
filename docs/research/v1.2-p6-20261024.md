## 本批修复

- 项目选择立即通知执行层，撤销旧协作投影；跨日也按同一边界处理。旧作用域的审批、额度准入、工具回调和迟到事件不再进入当前书页。新作用域的首次刷新不会被自身初始化取消。
- 切回同一运行时内仍驻留的项目，复用其 DSH 根 handle；重新绑定 LCA 授权，不重复 resume/create 相同 sessionId，不自动续跑成员。
- `dsh-sessions.json` 与书本数据在同一恢复事务中备份/退役。以前的“移走失败也继续”被移除；异常索引在替换前拒绝恢复，事务中断则回滚。旧版已提交事务若无法安全退役索引，阻止启动而不是连接旧成员。

完整开发范围见 [1.2 计划](v1.2-development-plan-20261023.md)。本批未修改 DSH npm 包、锁文件或美术资产；尚未发布 1.2。

## 组合恢复证据

`test-results/p6-87b5b2c1-7f5b-4741-b17a-83ca1970ddf0/evidence.json` 记录最终 10 组全链检查。使用真实 Electron、preload、主进程与固定 DSH，模型由本地脚本接口回复，HOME、profile、项目和提供者配置隔离。跨日由可控业务时钟触发，不能称为真实时间的长期日用。

另外验证了主角色闲置但成员仍工作时，项目切换、扩展重启及存档导出均不能越过 busy 边界。扩展命令的 accepted 回执只表示收到了命令，最终操作为 failed，没有获得批准或执行重启。`probe:backup` 的真实 SQLite 检查证明异常会话索引不会导致半恢复、恢复事务中断能带着索引一起回滚。

最终源码对应的结构化证据见 [P6 证据](evidence/v1.2-p6-20261024.json)。安装、第二机和真实服务结果另行追加，不从旧版本或合成模型推断。

历史页首轮在第二次日切超时：测试只观察 completed 与新用户消息，可能误认上一回合已经完成。合成日志证实日切发生时新回合仍在模型步骤中；冻结时钟后没有下一次维护机会。测试改为核对新的 task ID 已完成，完整复跑通过，产品日切条件未放宽。首次失败日志保留在回归目录。
