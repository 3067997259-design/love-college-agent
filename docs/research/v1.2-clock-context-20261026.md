# 聊天回合的当前时间依据

2026-10-26。用户在 10:59 发送“早安。”，模型回复“我这边快晚上十一点了”。本轮只读核对该次已有记录，并运行本地回归，没有追加真实模型请求。

## 定位

- 系统时区为 UTC+8，书页按上海时间显示；该次模型步骤开始于 2026-10-26 10:59:30。
- DSH 请求记录的模型为 `[满血C]gemini-4-argon`、`reasoningEffort: high`。这证明所选档位进入 DSH 请求配置，不能证明供应商内部实际如何执行。
- 该会话仅一个模型步骤；LCA 送出的系统、用户和运行时消息没有当前时间或“23 点”的事实，也没有调用 `get_clock`。现有运行配置未注入 DSH time-context 的时间消息。
- 因此，“快晚上十一点”没有 LCA 程序依据。可确认的问题是开场缺少时间事实、模型仍自行给出钟点；没有证据将其归因为提高思考档位，也无法从本地记录判断供应商是否另行修改提示。

## 修复

- 每个 DSH 新回合的开场引用加入 `currentTime`，由 main 统一 Clock 读取；包含 UTC ISO、本地时间与 `Asia/Shanghai` 时区，不依赖模型主动调用工具。
- 与 `get_clock` 共用 `readClock`，避免两条时间路径分叉；下一轮重新取值，并用程序值覆盖外部引用中同名字段。
- 系统提示明确双方共用程序本地时间，UTC 不能直接当本地钟点；长回合需要更新时调用工具，没有证据时不猜测或另设角色时区。
- 开场时间沿用已有引用的退役边界，不作为用户原话写入聊天或记忆。普通 steer 不重发开场引用，运行中的最新时间仍由工具获取。
