# 真实状态交接、独立委派与建队复测

2026-10-26。用户明确要求使用当前配置，先看主模型切换到工作模型，再验证 DeepSeek 官方工作模型的建队和委派。测试当前开发工作区的源码 Electron，非安装包验收。模型配置、路由和思考强度保持用户选择；配置仅由获授权的 Electron main 读取。

后续用户单独授权的[规则员身份续用](v1.2-real-member-reuse-20261026.md)已通过冷恢复、相同成员实际执行和无新增身份核验。下文保留前三项测试的当时范围与用量。

## 结果与证据

## 探针误判与继续方式

第一段交接的程序执行成功，但探针误将 `ActivityView.taskId` 写成 `turnId`，导致原报告 `MODEL_SELECTION_EXPECTATION_FAILED`。原报告保留。只读审计确认同一回合的 chat / work 请求、main 的模式变更和成功时钟活动后，将其明确归为验收脚本误判，未重新调用主模型。

修正字段后，下一段隔离测试直接从 work 进入，完成独立委派和团队任务；只使用第一段扣除后的剩余额度。`--state-routing` 为三项顺序验收，`--work-only` 用于已经有交接证据时的后续工作阶段；两个报告通过 `precedingRun` 关联，不把它们描述成同一个应用会话。

## 额度与收尾

- 总上限 480,000 预留单位，自主额度 0；交接使用 35,557，委派和团队累计使用 131,892，合计 **167,449 / 480,000**，41 次模型准入。这是 LCA 预留账本，不是供应商收费 token 或费用。
- 第一段交接约 18 秒，第二段约 71 秒。隔离实例均已关闭、家族已停止，临时凭据副本均已移除；正常预览和源配置未改动。
- 没有在内容问题出现后自动重跑，也没有追加真实请求。复杂项目工作、长期稳定性、指定成员后续复用、安装包和第二机仍需各自证据。
