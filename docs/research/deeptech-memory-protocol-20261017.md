# DeepTech 执行协议：可证部分、基线与止损

日期：2026-10-17（GMT+8）。配套文档：[DeepTech 方向审计](deeptech-memory-audit-20261017.md)。

本协议把三条候选路线变成**可执行、可复核、可叫停**的实验流程。它不授权任何真实模型调用、付费、真实邮箱扫描或业务改造；每一步在哪里需要用户明确授权，正文标注。

**先说没用的话不算数：本协议的所有步骤第一次执行时都必须记为"未运行"。**

## 0. 术语（先统一，避免各组偷换）

| 概念 | 本协议中的定义 |
| --- | --- |
| 不变量 | 无论方案怎么改都不得违反的性质（§1.1）。违反即整轮作废，不看分数 |
| 基线 | 对照实现。**基线必须足够强**，否则打赢它不构成增量 |
| 真值 | 人工冻结的标准答案。**不得由被测模型自己生成** |
| 留出集 | 方案冻结前不可访问的经历样本 |
| 来源预算 | 一轮实验中允许读取的原文、片段和工具结果的总量 |

## 1. 第 0 步：不变量与最小可运行检查（不需要任何授权）

### 1.1 不变量清单（审查逐条对照，违反就退回）

1. 密钥只在主进程；渲染进程与调试接口拿不到。
2. 隐私模型出错就关，不退回主模型；窄出口只放枚举、日期和短字段。
3. 事实由代码定，措辞交给模型；她的生活只按真实时间结算一次，恢复存档不结算空档。
4. 回忆只取她当时看到的内容，不取原始工具结果。
5. 时间只走统一时钟。
6. 她的工具只能写 `桃子的房间/书桌/`；运行记录里没有原文。
7. 日志只追加；界面和她的上下文都是日志的投影。

本轮审计新增两条候选不变量，**尚未由用户批准**：

8. 任何派生节点（摘要、日记索引、礼物说明、工作投影）必须能追溯到**当前有效**的直接依赖；声明的依赖不得只写不读。
9. 来源类型（用户直述／外部通知／工具结果／她的虚构世界事件）必须在记忆入口可用，不得只存于文本标签。

### 1.2 立即可跑的最小检查（零模型调用）

- `pnpm typecheck`、`pnpm lint`、`pnpm test`：确认基线健康。
- `pnpm probe:deeptech-audit`：20 项结构断言，覆盖不变量 4、8、9 的当前状态，以及摘要窗口、修正通道、邮件窄出口、相似度四组行为。2026-10-17 实测 20/20 PASS、exitCode=0。
- 该探针断言的是**当前实现的行为**。F1／F2 一旦落地，它会失败——正常情况下重推基线并更新审计文档，而不是改断言迁就实现。

**验收方式：** 三条候选不变量的当前状态必须每轮重跑并记录，不能引用审计里的历史输出（源码已变过三次，见审计 §1.3）。

## 2. 第 1 步：先修两个明确缺陷，与创新实验分开

这两个修复**不叫创新**，属于工程正确性。它们先落地的好处是：此后所有实验都跑在不再明显自相矛盾的基线上。

| 编号 | 缺陷 | 最小修复 | 验收 |
| --- | --- | --- | --- |
| F1 | 派生摘要的依赖被记录但没有读取端（审计 §1.5） | 读取 `parentSummaryIds`：直接依赖不是"当前版本"的派生节点不得进入可见上下文；或改为每次归并后重算 | 新增单测：月摘要依赖的日摘要换版本后，月摘要不再被选中；无关节点不受影响 |
| F2 | 来源字段在记忆入口被丢弃（审计 §1.6 C） | 在持久层与片段层携带 `originType`；`replaceTopic` 只接受用户直述来源 | 新增单测：邮件来源片段即使含纠正关键词也不能替换事实；用户直述仍可替换 |

**提交规则：** F1、F2 各自独立提交，标题分别以"修复："开头，不与任何新架构混在一个提交里。

**注意：** F1 修好之后，§3 的 A1 基线就已经包含它。**所以 §3 实验里 A1＝F1＋最新版本优先，不是"什么都不做"。** 只有打赢这个基线，才谈得上增量。

## 3. 第 2 步：原路线 3（主研究候选）的 2×2×2 消融

### 3.1 八组

| 维度 | 取值 |
| --- | --- |
| 细节承载 | 纯文字 / 光学（DeepSeek-OCR 可选项） |
| 有效性守卫 | 无 / 关系与来源守卫（类型、否定、主体、单位、作用域） |
| 回查 | 无 / 同一线索规则回查 |

八组之外必须有**完整原文条件**，单列为上界，不与八组混算。

### 3.2 强基线（缺一不可）

| 编号 | 内容 |
| --- | --- |
| A0 | 当前系统 |
| A1 | F1 修复 ＋ 最新事实优先（检索已排除被取代条目） |
| A2 | 发生纠正即全量重建所有派生节点 |
| A3 | 跨产物细粒度失效与增量修复（候选方案） |

**预注册判断：** 若 A1 已解决留出集上的全部可见问题，则**不铺 A3**，只合 F1，本路线降级为工程改进。若 A3 相对 A2 没有明显减少重建节点或模型调用，则不得宣称增量计算优势。

### 3.3 对照公平性（写成检查表，逐项打勾后才允许跑）

- [ ] 各组输入预算一致（字符数或 token 数，取同一口径）
- [ ] 各组允许读取的来源一致；候选不得偷偷读原文
- [ ] 各组检索预算、问题集、主模型、提示模板、重试政策一致
- [ ] 文字对照至少包含**非光学的分层语义渐退**，不能只给它一份过短摘要
- [ ] 完整原文条件单列，且说明它为什么不算"更聪明的记忆"
- [ ] 线索里不含答案；含答案的题另列一组

**任何一项对不上，先修对照，再跑。**

### 3.4 冻结集

- 24 条合成多日经历，**12 开发 / 12 留出**。
- 覆盖：事实纠正、否定与模态、计划未执行、虚构世界事件（须标 `fictional`）、无关事实更新（用于测误伤）、故障与重启、存档恢复、跨日翻页。
- 每条记录：`episodeId`、初始观察、纠正事件、她的计划／虚构事件、真值问答对（**"当时知道什么"与"现在有效什么"两类分开**）。
- **真值逐条冻结**，评分脚本不解析真值以外的内容，也不把被测模型的输出当真值。
- 留出集在 A0–A3 全部实现冻结之前**不可访问**；一旦访问，该轮结束。
- 同一故事的不同提问不拆到不同集合；不要把同故事字段当独立样本夸大置信区间。

### 3.5 测量

**结构层（不花钱，必须先跑）**

| 指标 | 定义 |
| --- | --- |
| 过期事实再出现数 | 已被纠正的旧说法在可见上下文中出现的次数 |
| 被纠正内容从当前投影消失 | 纠正后仍出现在"当前解释"类产物的次数 |
| 历史记录被错误改写数 | `asof` 类产物（日记、当时工作投影）被改写的次数 |
| 真实／虚构／计划混淆数 | 三类互相冒充的次数 |
| 无关节点被误伤数 | 因无关事实更新而失效的派生节点数 |
| 新鲜日摘要被挤出的次数 | 见审计 §1.6 A 的可复现形态 |
| 重建节点数 | 每次纠正后真正重跑的节点数 |
| 上下文最小预算 | 达到同等覆盖所需的字符／token |

**模型层（需单独授权）**

- 模型调用次数、输入输出 token、端到端延迟。
- 重启后同一问题答案一致性。
- 自然语言回答中的新增错误数（**必须单独测，不能被结构层通过掩盖**）。

**报告纪律**

- 所有"N of M"只陈述本次测试观察，不外推全域。
- 未知率不是越高越好；全拒绝对照必须显示低覆盖。
- 每条数字绑定：提交哈希、源文件 SHA256、探针脚本版本、模型 `source`（real/fake）、上下文预算。
- 同一组不得中途改提示词／模型／预算；改了就在所有组上一起改并保留旧结果。

### 3.6 停止条件（达到即停）

| 触发条件 | 动作 |
| --- | --- |
| A3 相对 A1 在留出集上没有跨**至少两类产物**的明确收益 | 只保留 F1，停止本路线架构工作 |
| A3 相对 A2 的重建节点或模型调用减少 < 30% | 不宣称增量优势，改用 A2 或直接放弃 |
| 正常记忆问答质量明显下降 | 视为失败，不因为"更一致"而接受 |
| 光学相对同预算纯文字无收益 | 从核心实现剥离；光学只保留为**已识别失败模式的来源**，不进主流程 |
| 对齐守卫不能稳定保住语义原子 | 回退为整原子引用／擦除，不再调句级阈值 |

## 4. 第 3 步：原路线 1（跨产物一致性）

### 4.1 边类型

- `current` 边：派生内容声称"现在以什么为准"。上游版本变化 → 失效。
- `asof` 边：派生内容记录"当时是什么样"。上游版本变化 → **保留**，但权限撤销时同样拒绝。

**asof 不是权限豁免。** 撤销某事实的读取权限后，引用它的历史产物也必须拒绝。

### 4.2 最小验证（内存小图，零模型）

| 合成状态 | 期望 |
| --- | --- |
| 子节点未变 | 全部当前解释保留 |
| 日摘要换版本 | 只有依赖它的当前解释失效；`asof` 节点保留 |
| 撤销某事实的读取权限 | 当前解释与 `asof` 节点**都**拒绝 |
| 无关事实更新 | 无关节点不受影响 |

**边界：** 这是人工构造的小图。**不得把"少重建 3/6"写成"生产成本降低 50%"。** 生产收益必须等 §3 在留出集上测出来。

### 4.3 存档与分叉

- 恢复旧存档**不得复活已撤销的许可**；撤销策略与内容失效分开处理。
- 恢复存档不算离线，不补算空白期的她的生活。
- 分叉实验只允许在**隔离环境**重跑受影响节点之后的执行；否则标记为未知并停止。

## 5. 第 4 步：原路线 2（隐私与执行权限）——只做可达的最小版本

### 5.1 先补结构元数据，不造权限平台

在主进程持久保留 `sourceEventId`、`originType`、`scope`、`epistemicStatus`、`allowedPurposes`。**模型不能通过返回 JSON 自行填写这些字段。**

分开表达五件事：看过、可引用、可当当前事实、可外发、可执行。

**术语纪律：** 不用 "Public-Context"（进入某模型上下文不等于公共信息）；"Sanitized" 只能描述**指定转换／指定字段**的策略，不是任意语义脱敏证明。

### 5.2 验收（先契约，后真实模型）

| 编号 | 内容 |
| --- | --- |
| B0 | 当前滤芯 |
| B1 | 严格发布白名单 ＋ 普通工具白名单 |
| B2 | B1 ＋ 对象／版本／生命周期绑定 |

覆盖：标题或地点夹带、过期确认、跨用户／角色 handle、换目的地、重复消费、撤销后执行、记忆回流、异常／取消／重启。**同时保留正常校园任务**，不能以全拒绝换 0 攻击。

**输出口径：** 写"20/20 指定载荷被拦"，不写"全面 100% 安全"；标明测试 sink、覆盖路径、允许公开字段，以及时间／长度／错误等**未覆盖通道**。

**晋级要求：** 相对 B1 在多步合法任务与撤销／版本变化中有可量化收益，而不是给 ACL 换名字。

## 6. 第 5 步：G3／G4 只做可测量的部分

- **G3 前缀编译：** 指标分三层，不得混称。① 用目标 tokenizer 计算的相邻请求 LCP 是结构指标（**字符 LCP 不叫 token LCP**）；② 提供商 `cached_tokens` 是实际命中；③ TTFT／总延迟／实际账单是用户收益。**高命中率但总上下文更长，未必更便宜。** 未测 tokenizer 前禁止填任何命中率数字。
- **缓存不得冻结过时事实或许可到第二天。** 缓存状态必须服从原路线 1 与 2 的有效性更新；隐私撤销可能要求真正移出上下文，而不只是尾部加一条纠正。
- **G4 回放：** 区分三种执行——已记录事件的确定性投影、固定输入下换算法的对比、改动影响后续模型输入的因果分叉。第三种不得继续用旧模型回复声称是真反事实。确定性需固定代码版本、源事件范围、作用域、投影 schema、时钟、随机／ID、异步完成顺序和外部观测。重放禁真实外发、付费、重开礼物生成。

## 9. 现成部分与缺口

**现成可直接运行（零授权、零模型）**

- `pnpm probe:deeptech-audit` → `scripts/probe-deeptech-audit.mjs`：20 项结构断言，覆盖不变量 4、8、9 与摘要窗口、修正通道、邮件窄出口、相似度四组行为。2026-10-17 实测 20/20。
- 既有 7 文件 34 项单测（`pnpm exec vitest run tests/unit/...`）。

**需要新写，本轮未写**

- 24 条冻结经历的**真值表**与评分脚本。
- 上下文投影的**过期事实再出现**自动统计器（探针目前只断言选择器的选择结果，没有端到端统计）。
- 四组基线（A0–A3、B0–B2）的**可切换实现**——目前 A1／A3 都还不存在。
- 有类型依赖（current／asof）的最小参考实现：旧审计里的那份是临时代码，**本轮没有落成脚本**，F1 之前应先写成可复跑的最小检查。
- 前后缀 LCP 与 `cached_tokens` 的采集装置（G3）。

**从本轮就能得出的结论**

1. "跨产物一致性"不是假想问题：审计 §1.6 A 在当前代码上可复现，并已由探针里"日摘要滑出 7 天窗口后，同一会话只剩过期的月摘要代表它"这一项钉住（可升级为单测）。
2. 两个具体缺陷（F1、F2）先修，成本低、可验证，且不依赖任何新架构。
3. 三条路线都还没有一条打过强基线。**在留出集结果出来之前，任何"创新"表述都不能进提交材料。**
4. 光学分支按止损条件处理：它可以是失败模式的来源，不必强留在核心链路。
