# 主模型工具调用定位：供应商 API 未满足调用契约

2026-10-26。针对[协作复测未触发委派](v1.2-real-collaboration-20261026.md)，用户要求确定问题所在。结果定位到当前聊天模型 API 的 function calling 链路：绕过 LCA / DSH 的最小请求也未返回所要求的标准工具调用。DSH 的本地出站捕获同时确认，协作工具已被序列化到请求中。

这不是对供应商内部实现的结论。该模型渠道是否禁用了工具调用，或中转转译是否丢失 `tools` / `tool_choice`，仍须上游确认；不能只据客户端结果断言是哪一种。

## 真实接口对照

仅 Electron 主进程读取已保存的聊天模型连接。四个请求使用相同的虚构函数 `diagnostic_echo(value: "OK")`、固定测试句和 128 的输出 token 参数；不带私人对话，不执行模型返回的工具。每次超时 45 秒，不自动重试。诊断账本每次预留 2,000 单位，上限 8,000；四次后停止，不重置额度。

| 条件 | 实测结果 | 解释 |
| --- | --- | --- |
| 流式、`tool_choice: "auto"` | 45.016 秒超时。 | 未取得可用工具调用结果。 |
| 流式、明确指定 `diagnostic_echo` | HTTP 200，SSE，16.637 秒；返回 69 字符普通文字，`finish_reason: "stop"`，标准 `tool_calls` 为 0。 | 指定函数的调用要求未被遵守；本请求未经过 LCA / DSH。 |
| 非流式、同一指定函数 | 45.017 秒超时。 | 非流式请求也未取得可用结果。 |
| 流式、`tool_choice: "required"` | 45.010 秒超时。 | 必须调用工具的另一种表达也未取得结果。 |

此前同一连接补齐 `/v1` 后，固定纯文本请求曾正常返回 `OK`。纯文本连通与工具调用兼容是两个独立条件；本次没有把竞技场能聊天作为 function calling 通过的证据。超时表示客户端停止等待，不能据此断言供应商已停止生成或不会计费。

## DSH 出站核对

另以合成服务运行当前 `startDshHost`、LCA bridge 和随附 OpenAI completions 适配器，使用与当前自定义路由同形的配置，并装入此前请求记录中的 15 个 LCA 工具定义。只向本机服务发出一次请求，没有真实模型调用。

本机服务实际收到 `POST /v1/chat/completions`，JSON 中有 47 个标准 `tools`，包含 `subagent`、`subagent_fork`、`spawn_teammate` 和任务板工具。请求为流式，未指定 `tool_choice`，输出参数为 `max_completion_tokens: 32768`。合成响应后回合正常结束。

源码核对：`src/main/dsh/routes.ts` 把自定义连接交给 `openai-completions`；随附 pi-ai 的该适配器将工具转换成 `type: "function"`、`function.name / description / parameters` 并写入 `params.tools`。没有修改上游运行时或锁文件。

这是本地合成出站捕获，不是对原真实请求的原始 HTTP 包回放。但它证明了当前适配路径能够发送协作工具；真实接口的最小失败又独立于 LCA / DSH，因此当前不能将失败归因于 LCA 未装配帮手工具。

## 最小复现请求

把模型占位符替换为当前聊天模型名，向供应商的 OpenAI 兼容 `/v1/chat/completions` 发送下列请求。鉴权由用户在自己的客户端添加；这里不记录密钥或供应商地址。

```json
{
  "model": "<当前聊天模型名>",
  "stream": true,
  "stream_options": { "include_usage": true },
  "max_tokens": 128,
  "messages": [
    { "role": "user", "content": "This is a function-calling compatibility test. Call diagnostic_echo exactly once with value OK. Do not answer in plain text." }
  ],
  "tools": [
    {
      "type": "function",
      "function": {
        "name": "diagnostic_echo",
        "description": "Record the fixed synthetic test value.",
        "parameters": {
          "type": "object",
          "properties": { "value": { "type": "string", "enum": ["OK"] } },
          "required": ["value"],
          "additionalProperties": false
        }
      }
    }
  ],
  "tool_choice": { "type": "function", "function": { "name": "diagnostic_echo" } }
}
```

需要核对实际返回的 `choices[].delta.tool_calls`，而不是普通文字中是否写了函数名或调用意图。

## 影响与证据边界

当前架构由聊天模型开场，第一次写入、命令或委派请求触发工作模型交接。聊天模型没有发出任何工具调用时，独立的编程模型尚未接手；本轮也没有测试工作模型。应先让当前聊天连接稳定返回标准工具调用，再复测完整协作；不自动换供应商、切模型或把普通文字解释为真实工具执行。

结构化记录及各报告哈希见[定位证据](evidence/v1.2-function-calling-diagnostic-20261026.json)，本机明细位于 `.local-data/function-calling-a72e4f3c-560c-4736-bbf6-887ed00f47f7/`。没有输出凭据、供应商地址、内部推理或原始请求头；没有修改用户配置、生产执行逻辑或候选安装包。原协作失败证据保留，真实协作门槛仍未通过。
