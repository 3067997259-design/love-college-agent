# 跨产物一致性实验：依赖新鲜性守卫（F1）与来源权限（F2）

日期：2026-10-17（GMT+8）。这是 [执行协议](deeptech-memory-protocol-20261017.md) 要求的"先修两个明确缺陷、再与强基线对照"的第一次实际执行。审计见 [DeepTech 方向审计](deeptech-memory-audit-20261017.md)。

**一句话结论：** 依赖新鲜性守卫把"用过期上层摘要代表那段经历"的发生数从 **6/16 降到 0/16**，同时**没有丢失任何代表覆盖**（守卫把代表的职责交回被纠正后的日摘要）；来源权限守卫把"不可信外部通知替换已确认事实"从可复现变成被拒绝。两项修复都**不影响控制组**（8 条无纠正条目、0 条选择变化）。

## 2. 两个修复的准确内容

### F1：依赖边不再"只写不读"

审计发现 `parentSummaryIds` 只在归并时写入（`service.ts:126`），全仓没有读取端。现在：

- 新增 `validSummaries(summaries)`：一个派生摘要声明依赖的子摘要，若**存在但已不是该周期（`level:period`）的当前版本**，该派生摘要判为失效。
- **缺失的声明依赖按"未知"处理，不判失效**——记录丢失是另一个问题，不在本次改动范围，保留原行为。
- `prepareContext` 在调用选择器之前先过滤，**在按来源会话去重之前**完成，所以失效的宽摘要不会再把同一会话的当前窄摘要挤掉。
- 未修改 `summaryReferences` 的签名与窗口规则，避免接口扩散。

### F2：来源种类不再等于传输角色

`inbox/event` 会被投影成 `role: 'user'`（`journal/projection.ts:63`），而 `seen.ts` 只保留角色、丢掉来源，于是"含纠正关键词的外部通知"能取得与用户直述相同的事实替换权。

现在：

- `SeenFragment` 增加 `origin: 'user' | 'mail' | 'document' | 'pomodoro' | 'autonomous' | 'model' | 'tool' | 'unknown'`，来自**日志记录本身**（`inbox/event.source`），以及未加 JSON 包裹的普通用户消息。
- 修正通道（`replaceTopic`）要求 `origin === 'user'`。外部通知仍可被记录为经历/候选，只是**不能替换已确认事实**。
- 该字段为可选，缺省时按原有行为（`undefined` 视为 user），以免破坏在模块外构造片段的既有代码。

**做法（不新增测试框架）**

**冻结集**：24 条 = 开发 12 + 留出 12；每条是 `{窗口近/远} × {月/周} × {已重建/未重建/对照}` 的一个格。真值由构造决定（哪句是旧说法、哪句是当前说法），不由被测模型生成。留出集在装置冻结后一次跑完。

**对照的两条规则**

- 旧规则 = 审计记录的当前实现（只看日历年龄窗口）。

纠正类 6 条发生变化的分别是：`dev-f2`、`dev-f4`、`hold-f2`、`hold-f4`、`hold-f5`、`hold-f6`（全部是**远窗口 + 尚未重建**的格子）。变化形态一致：

```

week-v1(提交在下周二)   →  day-2026-08-10-v2(提交改到下周三)
```

### 4.2 修复只在一种情形起作用——这正是它该有的样子

| 情形 | 条目 | 旧规则过期 | 新规则过期 | 说明 |
| --- | ---: | ---: | ---: | --- |
| 近窗口（几天内回看） | 4 | 0 | 0 | 日摘要在 7 天窗口内，本来就优先，守卫不需要介入 |
| 远窗口 + 已重建 | 3 | 0 | 0 | 纠正后归并已产出新版本，旧版本本来就不会被选中 |
| **远窗口 + 尚未重建** | **9** | **6** | **0** | 唯一出问题、也是唯一被修复的格子 |
| 对照（无纠正） | 8 | 0（期望） | 0（期望） | 守卫不误伤 |

**结论：F1 的收益完全集中在"很久以前那段经历，其上层摘要还没按纠正重建"这一格。** 其余 18 条两种规则完全一致——这既说明守卫精确，也说明**不能把它宣传成普遍性改进**。

### 4.3 代价：不是丢记忆，而是换代表

曾经担心"失效了旧摘要会不会让那一段经历没有代表"。实测：**覆盖 24/24，两个规则相同**。原因是失效判定发生在按来源会话去重之前，所以过期月摘要被剔除后，被纠正后的日摘要（`day-...-v2`）接替成为该会话的代表。

也就是说，这次修复**没有用"忘掉"换"一致"**：旧说法不再出现，当前说法反而更多出现（18 → 24）。

## 5. 诚实边界

- **fake 模型。** 全部结果来自确定性 fake 模型与合成摘要状态。它验证的是**选择与守卫逻辑**，不是"真实模型会不会这样回答"。
- **不是端到端产品实验。** 装置直接构造摘要状态并驱动 `prepareContext`，没有跑完整的日翻页、空闲抽取与归并调度链。
- **不是留出集上的模型质量对比。** 协议 §3 要求的 A0–A3 与 2×2×2 消融**仍未执行**。
- **没有测真实攻击。** F2 只证明"标记为外部来源的片段不能替换事实"，没有测真实模型产生该输出的频率，也没有测完整投毒链。
- **窗口参数敏感性。** 结论依赖 7 天（日/周）与 30 天（月）窗口；改窗口会改变"远窗口"格子的数量，不改变机制结论。
- **不含真实用户经历。** 经历全部合成。

## 6. 对协议基线的更新

原协议的 A0–A3 四组基线里，**A1 原本定义为"F1 修复 + 最新事实优先"**，现在 A1 已经落地。因此：

- A0（旧行为）与 A1（本次修复）的差异**已被本次实验测量**：纠正类 6 → 0 条过期，覆盖不降。
- 仍然没有测的是 **A2（全量重建）** 与 **A3（细粒度增量失效）**：那需要真实的日摘要/归并链路与重建计数，本轮没有搭建。
- 按协议 §3.2 的预注册：**A1 已经解决本装置覆盖的全部可见问题**。因此在这一装置覆盖的范围内，"铺 A3 大图"缺少依据；是否继续推进原路线 3 的更高目标，应由**新的、本装置覆盖不到的情形**（例如多跳依赖、跨产物：日记与礼物说明、撤销权限）来决定。
