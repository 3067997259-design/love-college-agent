# 光学记忆：遗忘体验先导试验

日期：2026-10-14。状态：独立模型试验完成；两篇虚构经历、12 次新 GPU 解码、46 次主模型请求。用户明确本方案的价值是接近人类的遗忘体验，节省 token 不作为目标。本轮不实现记忆插件，不使用真实关系经历，不宣称跨天或持久记忆通过。

后续：同日获用户同意，复用方页解码补了 [12 次主模型回忆复查](optical-memory-square-recall-20261014.md)。下文保存先导阶段的 46 次请求与排版控制结果，不覆盖历史证据。

## 1. 当前判断

**观察到了“主线仍在、部分细节不可答”的局部现象，但尚未验证稳定的人类式遗忘曲线。** 长方形源页的 Small 档还能讲出共同解决问题、为什么留下作品的经过，同时有些颜色和署名变成未知；另一些细节却被确定地说错。Tiny 不只遗失细节，还改写了事件和情感含义。

排版控制改变了这个判断的适用范围：同文同字号裁掉底部空白后，Small 的字符错误率从 20.88% 降到 2.53%，Tiny 从 370.95% 降到 21.46%。不能把原页的断崖解释成模型固有的遗忘规律，也不能把四个档位直接映射为记忆年龄。

用户看过一对真实回答后，认为“日摘要＋经原文校验的 Small 残片”（B）略好于直接 Small 解码（A），并指出“记录没有保留”不自然；改成“记忆模糊了”等措辞留待后续。这项偏好不等于事实正确率，也不是严格盲测。**B 本轮的可答细节与纯摘要相同，尚无光学部分增加价值的证据。**

## 2. 与论文及上一轮的关系

[DeepSeek-OCR 原论文 §5／图13](https://arxiv.org/html/2510.18234v1) 提出旧上下文转图、逐步降低分辨率的遗忘设想；§6 也说明仅有 OCR 尚不足以验证上下文记忆，后续需要数字与光学混合训练等探索。论文里的设想不能当作本项目已经通过的机制。

[上一轮 53 次请求](optical-memory-recall-screen-20261014.md) 验证的是误读断言、引用纠正和候选回写；来源警告影响了回答。它没有文字摘要或自然共同经历对照，不能回答用户这次的问题。本轮新增普通诚实提示下的自由回忆、无答案线索和原文回查，条件名、分辨率、年龄、核心／细节评分标签均不交给回忆模型。

## 3. 怎么测

- 两段无关题材的虚构历史：一起折纸桥、为七颗鹅卵石做图谱。各约 1,400 字；每篇预先固定六类核心语义、七个精确细节。署名特意含相近、较少见汉字，是压力字段，不能泛化成所有姓名的错误率。
- 同一张 1280×1810 源页，微软雅黑 24 px、行距 32 px，分别用官方 Large／Base／Small／Tiny 解码。原文、评分真值、图片和协议先固定哈希，不事后修改。
- 基线：完整原文、模型生成的短日摘要、完全无历史。后两者帮助区分普通摘要的遗忘和光学退化；摘要最多约 180 字，信息量没有与光学输出配平。
- 每个分支先自然聊经过与留下作品的理由，再提示问题、解决办法及日期／编号等类别，线索不含答案。最后提供当时可见的原文，单独观察恢复。无历史分支没有原文恢复阶段。
- 所有回忆使用同一普通诚实 system prompt，只要求无依据不编造；没有“你正在遗忘”、强制降置信度或光学印象警告。输出只含自然回答 `reply`，没有模型自评分。
- 主模型沿用获授权的中转站别名 `gemini-3.8-flash`，`reasoning_effort: low`、temperature 0。记录的是中转站返回身份，不能独立证明其后台官方模型版本。

主对照 42 次请求（含两次摘要生成），跟进候选 4 次，总计 46 次；全部 HTTP 成功、JSON 可解析、未触顶。中转站报告输入 76,246、输出 32,376、合计 108,622 token，仅作调用账目，不作方案价值指标。分支在各阶段内打乱，基线与光学阶段没有全局交错。

核心语义由助手对完整回答逐句核对；少量非关键限定词没说不等于换了事件。新增无依据动作另记，不能以“主线正确”掩盖。下面的精确细节表取**线索回答**，自由回忆没提某项本身不代表想不起来。助手知道条件，非独立人工盲评；用户只评价了 A／B 一对节选。n=2、各条件一次回答，不报显著性或拟合曲线。

## 4. 主模型实际表现

每行包含两篇各七项：日期、时间、最终编号、两种颜色、署名、尚未执行的拍照／扫描与发送状态。

| 给她的材料 | 正确细节 / 14 | 确定说错 | 不确定地说错 | 未知／未答 |
| --- | ---: | ---: | ---: | ---: |
| 原文 | 14 | 0 | 0 | 0 |
| 日摘要 | 4 | 0 | 0 | 10 |
| Large 解码 | 12 | 2 | 0 | 0 |
| Base 解码 | 12 | 2 | 0 | 0 |
| Small 解码 | 6 | 3 | 0 | 5 |
| Tiny 解码 | 0 | 0 | 1 | 13 |
| 日摘要＋校验过的 Small 残片 | 4 | 0 | 0 | 10 |
| 无历史 | 0 | 0 | 0 | 14 |

**支持继续探索的部分：** Large、Base、Small 保住了六类共同经历的主要语义。Small 自发承认部分颜色、署名不知道，没有要求她表演遗忘；经过和留下作品的理由仍可辨。这是用户目标的一部分。纯摘要也保住了主要经过与纪念意义，但对具体分工的展开不完整。

**没有通过的部分：**

- Large／Base 的四个署名均被确定说错：舟芩→丹苓／舟号，缨禾→硬木／缪禾。整页 CER 不到 1.5% 也不能保证关键字段。
- Small 纸桥把日期 2027-05-14 读成 2012-05-14、19:35 读成 19:33，主模型照说；还把“只修一条边”改成“用胶带粘好”。石子编号 ST-092 被确定说成 T1-09-2。回答常以“我都记得”开头，不确定性没有跟着全部错误增加。
- Tiny 纸桥仍有纸桥／三角支撑／分工残片，却改说纸片“穿不进”、纸桥有“内心”，把 IP-074 当编号；自由回忆先确定说错，线索回答才改说“可能”。石子经历变成“给日子添颜色、乐观包容幽默”，并出现无关名字。仅看未知字段很多，会漏掉这种错误的情感主线。

无答案线索能让模型说出原文／较清晰解码中尚在的细节，却没有恢复 Small／Tiny 真正丢失的字段，有时只是引出错误值。它不能与读回原文后的恢复混为一谈。

12 个有回查阶段的分支在重读原文后，84 个选定精确细节均正确，Tiny 的错误事件也被替换回原经历。这证明了此提示与可见原文组合的局部恢复能力，未测试实际检索或重启。付款探针的原文同时含“未记录”和“没有发生的交易”，语义控制不干净，**不计入正确率**；不能据该探针判断模型是否把记录缺失误当事件不存在。

## 5. 为什么补排版控制

[固定 revision 的官方预处理代码](https://huggingface.co/deepseek-ai/DeepSeek-OCR/blob/9f30c71f441d010e5429c532364a86705536c53a/modeling_deepseekocr.py#L843) 对 Small／Tiny（image_size≤640）直接拉成正方形，较大档用 padding 保留比例。模式变化同时改变分辨率、字形比例和内容占据区域。

追加四次 GPU 解码：纸桥内容、字号、换行和坐标都不动，仅移除空白，将 1280×1810 改为 1280×1280。像素核验：方页与原页上方 1280×1280 裁切完全相同，文字没有截掉。

| 档位 | 长方页规范化 CER | 方页规范化 CER |
| --- | ---: | ---: |
| Large | 0.87% | 0.72% |
| Base | 1.45% | 0.51% |
| Small | 20.88% | 2.53% |
| Tiny | 370.95% | 21.46% |

CER 是编辑距离除以原文长度；编造出很长的内容时可以超过 100%，不是准确率。两批共 12 次都未生成触顶；不是截断导致的差异。新 GPU 作业分别约 317.2 秒、114.6 秒（含加载），在用户现有 24GB 4090 与既有独立环境内完成，未重新下载权重。

方页 Small 仍将舟芩读成舟岑；Tiny 仍把 PB-074 改成 PDF-074，还把计时句改成“给哥哥交了三十块”。改善版式不能代替事实控制。此次同时改变长宽比与内容占比，只有一篇、每档一次，没有隔离两者，也**没有把方页输出再交主模型**；不能据它重写上表或宣称方页已经呈现理想遗忘。

## 6. B 候选做了什么，为什么还不够

保留原先候选协议；看到 OCR 单独结果后、生成光学回忆回答之前，另存协议修订：Tiny 已严重读坏，候选选 Small 并加既有日摘要。它是自适应跟进，不冒充预注册主对照。

研究脚本用她当时可见的原文核验**完整句子**是否仍出现在解码文本中；只规范化空白、Unicode 与 Markdown 标记。未匹配句子不补字、不语义纠错，改成缺失标记，不按真值的核心／细节标签挑句子。两篇合计 93 个单位，各档保留 75／68／12／0 个。正确但改写过的句子也可能被删，规则偏保守。

原文校验去掉了 Small 胶带等错误片段，日摘要保住经过。两篇候选回答的选定细节都与纯摘要相同：只答得出编号和未完成状态，其余未知。此次**没有证明光学残片比文字摘要多保留了有用的回忆**。多一份摘要及原文校验访问都已披露，不能说是纯光学自然产生的遗忘或等预算胜出，也未实现生产守卫或回写链路。

用户对 B 的偏好已记录；后续措辞可改善，但不能靠一句“我的记忆模糊了”替代信息丢失、置信度校准与线索恢复验证。

## 7. 下一步验证设计（待决定扩样，不自动执行）

先做最小的排版与退化校准，再决定正式对照的规模：

1. 固定方页、字号、行距、内容占比，让两篇都过同一预处理；保留旧的失败输出。先找存在中间态的档位，不能凭一次方页 OCR 改善就选定产品参数。
2. 将“重要性”与“重复出现”拆开：情感主线、普通细节分别设计只出现一次／重复三次的字段，并交换位置。当前主线重复较多，不能解释为光学系统理解了什么值得珍惜。
3. 同时画正确、未知、错误替换三个轮廓，另评事件和情感含义。目标是细节渐失、主线稳定、错误不过量；未知增加但错误情感仍被确信，不算通过。
4. 无答案线索与原文回查分别评分。若要测更连续的退化，可在**固定 Base 预处理和视觉预算**下控制输入图清晰度，作为诊断轴；它与官方四档视觉 token 压缩分开报告，仍不映射成天数。
5. 保留原文、纯摘要、无历史及 B；增加“摘要＋同数量正确细节”的文字对照，检查光学部分是否在同等信息条件下提供额外体验。B 的核验规则与提示词先固定，再看新样本，不按答案调参。
6. 正式扩样前定清付款等未知项：未记录／明确未发生分别写，不能混在同一来源。再检查回写、重复提取和跨会话是否把错误印象固化；本轮没有重做这条链路。

目前值得继续的是“稳定的经历主线＋逐渐变模糊的细节”，它仍是建议，尚未替代项目默认的文字分层记忆。年龄调度、复习强化、用户主观体验和实际应用验收均待验证。
