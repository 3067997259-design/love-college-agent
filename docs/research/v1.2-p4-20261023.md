# 1.2 P4：扩展管理页、技能目录与 MCP 状态

2026-10-23。接续 [P3](v1.2-p3-20261023.md)和 [1.2 计划](v1.2-development-plan-20261023.md)。本批沿用插件书签、纸张布局和既有审批卡；用户明确要求艺术资产在其在场时共同调整，本批没有生成、替换或采用美术，也没有接入全房间镜头或成员画面。

## 页面与管理行为

- `PluginCenter` 区分 LCA 本地包、DSH bundle 和由 LCA 管理的 MCP。插件工具仍在各插件详情中列出；技能页改为真正的 Markdown / 扩展技能目录。
- DSH 安装使用原生目录选择与候选指纹；安装、启停、重启、移除和独立构建批准均在当前管理页完成。受保护组件默认收起，没有修改按钮；用户扩展区同时显示保存意图、实际加载状态和待重启。必须停用并重启后才可移除运行中的代码。
- 操作记录显示准备、审批、执行、取消、失败和未知状态。结果未知时禁止再发新的变更，只允许刷新 / 核对原 operationId；查询已有完成回执不会新增安装操作。取消等待不等于撤回已经发生的效果。
- 技能与扩展管理互斥，项目不能在审批中切换。页签刷新与既有 MCP 导入协调，避免刷新期间提交导入后只得到 busy。页内审批独立于列表滚动，键盘可操作的原生按钮 / details 不要求切回聊天页。

## 技能目录与文件边界

`dsh/lca-bridge/skills.js` 在 DSH skills registry 注册 provider，复用随附 `@deepseek-ai/dsh-skill-filesystem` 的 parser / get。没有复制或修改上游源码，也没有新增代理循环。原有隐式 filesystem provider 在 LCA patch 中关闭，读取范围限定为当前项目自己的 `.dsh/skills`、`.agents/skills` 和此存档的 `DSH_HOME/skills`，不向上找父仓库、不读其他应用的用户 skills。

本地 provider 不缓存可变文件目录；每次目录与正文读取重新发现并校验。每根最多 512 项，每份 Markdown 最多 1 MiB；解析和读取使用只读端口，拒绝文件、目录及祖先中的 symlink / junction。显示有效项、同名被覆盖项、解析失败与缺文件；扩展注册的运行时技能仍由 DSH 合并决定实际胜出项。第三方 provider 自身的动态行为不在本批本地文件验收范围内。

`src/main/dsh/skills.ts` 提供本地目录导入与已导入目录移除。原生选取后复制到私人候选区，按整个目录指纹审批；导入到所选项目或此存档，不覆盖同名目录，不执行资源脚本。复制到目标盘的 staging 后校验，再原子改名。`skills-imports.json` 记录归属，`skill-events.jsonl` 追加操作观察；冷启动只观察已有文件，不重放批准。

移除只开放给页面导入且内容指纹未变的目录，实际改名至对应根的同级 `lca-skill-removed` 目录，保留文件。原有或已改动文件继续由用户在本地维护。取消、关闭、项目切换及来源变化使旧批准失效。公共视图只有元数据与不透明 ID；候选路径、目录归属文件和技能正文不传 renderer。

`skill` 工具结果按 `plugin` 来源进入已有 P2 传播 / 退役路径。因此她读取技能后，写入与外部动作仍受逐次审批约束；下一轮不会把上次的技能正文继续作为当前文件。页面没有新增 `/skill` 等直接正文注入入口，本批模型验收针对 DSH `skill` 工具。

## MCP 与兼容

MCP 页内显示配置来源、连接所有者、连接中 / 已连接 / 断开 / 错误和白名单工具。沿用 LCA 原有连接、原生启动目标确认、指纹和隐私窄出口，再向 DSH 提供工具；没有迁移或双连接。重启不自动重连。校园一体插件继续屏蔽旧 Student Hub MCP 与候选导入工具。

P4 接入的管理能力仍限本地 bundle、已配置的 LCA MCP 和本地技能目录。没有开放 registry / git / tarball 安装、任意 Cordis RPC、扩展行配置编辑或新的 MCP 凭据入口。

存档级技能的正文可经 provider 读取，附带资源仍受 `dsh-home` 私有根保护；需要通用文件工具或脚本的技能应导入项目，再走原有项目权限。导入副本不新增执行授权。
